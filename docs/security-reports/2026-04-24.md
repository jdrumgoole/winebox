# Security Review — 2026-04-24

## 🟠 WARNING (Address within 1 week)

### 1. Price History Endpoint Leaks Other Users' PII

**Location:** `winebox/routers/price_tracker.py:327-376` — `GET /api/prices/{wine_price_id}/history`

**Issue:** The `get_wine_price_history` endpoint returns `town_city`, `state_county`, and `notes` fields from **all users'** archived price history entries without ownership filtering. The main `get_wine_price` endpoint correctly uses `_entry_to_out()` (lines 67-108) to redact PII for non-owners, but the history endpoint bypasses this and returns raw `WinePriceHistory` documents.

**Impact:** An authenticated user can read the town/city, state/county, and free-text notes that other users attached to their price observations. While no GPS coordinates or photos are leaked (those fields are not in `WinePriceHistoryEntryOut`), the location granularity and notes may constitute PII.

**Recommendation:** Apply the same owner-gating logic used by `_entry_to_out()`: only emit `town_city`, `state_county`, and `notes` when the history entry's `owner_id` matches the requesting user. For non-owners, return `null` for those fields.

## 🟡 INFO (Best practice recommendations)

### 1. Reference Data Endpoints Are Unauthenticated (By Design)

**Location:** `winebox/routers/reference.py`, `winebox/routers/xwines.py`

All `/api/reference/*` and `/api/xwines/*` endpoints are intentionally public (no `RequireAuth`). These serve shared wine reference data (grape varieties, regions, classifications, X-Wines dataset) that is not user-owned. The X-Wines search endpoint is rate-limited at 120/minute and capped with `MAX_REFERENCE_RESULTSET`. This is acceptable but should be documented as a deliberate design decision.

### 2. `RequireAdmin` Defined but Never Used in Routers

**Location:** `winebox/services/auth.py:229-238`

The `RequireAdmin` dependency is defined and exported but no router endpoint uses it. Admin access is currently IP-restricted at the nginx layer (`deploy/nginx-winebox.conf:206-220`) rather than at the application layer. If admin endpoints are added in the future, they should use `RequireAdmin` for defense-in-depth.

### 3. Consider OCSP Stapling in Nginx

**Location:** `deploy/nginx-winebox.conf`

The nginx SSL configuration is strong (TLS 1.2+, modern cipher suites, HSTS) but does not include OCSP stapling (`ssl_stapling on; ssl_stapling_verify on;`). Adding this would improve TLS handshake performance and privacy.

### 3. Authentication & Authorization — PASS

- **Password hashing:** Argon2id via `pwdlib` (industry best practice)
- **Timing attack prevention:** Dummy hash verification for non-existent users prevents username enumeration (`services/auth.py:105-114`)
- **JWT security:** HS256 with jti (per-token revocation), iat (bulk invalidation), 2-hour expiry
- **Token revocation:** JTI blacklist in MongoDB with automatic cleanup every hour via background task (`main.py:96-127`)
- **Password change:** Invalidates all existing tokens via `tokens_invalidated_after` cutoff (`services/auth.py:285-303`)
- **Account lockout:** 5 failed attempts triggers 15-minute lockout (`models/login_attempt.py`)
- **Rate limiting:** All auth endpoints rate-limited (login: 30/min, register: 10/min, forgot-password: 5/min, password change: 5/min)

### 4. Data Isolation (owner_id Filtering) — PASS

- The shared `get_wine_or_404()` helper (`routers/wines/_common.py:58-76`) enforces owner scoping for all wine endpoints
