# Security Review — 2026-07-19

## Summary

This is an automated daily security review of the WineBox project covering dependency vulnerabilities, hardcoded secrets, authentication/authorization, NoSQL injection, input validation, rate limiting, token security, security headers, data exposure, git history, and infrastructure configuration.

**Result: 3 CRITICAL, 9 WARNING, 12 INFO findings.**

---

## CRITICAL (Immediate action required)

### 1. CVE-2026-48710 — Starlette Host-Header Authentication Bypass

- **Package:** starlette 0.50.0 (pinned via FastAPI 0.128.1)
- **Latest safe version:** starlette >= 1.0.1
- **Description:** A single malformed character in the Host header bypasses all middleware security checks. All versions before 1.0.1 are vulnerable.
- **Remediation:** Upgrade FastAPI to >= 0.135 (which pulls starlette >= 1.0.1). Test all middleware-based security (CORS, HTTPS enforcement, CSP).

### 2. CVE-2026-48526 & CVE-2026-48525 — PyJWT Algorithm Confusion & DoS

- **Package:** PyJWT 2.12.1
- **Latest safe version:** PyJWT >= 2.13.0
- **CVE-2026-48526:** Algorithm confusion allows forged HS256 tokens when mixed algorithm families are allowed.
- **CVE-2026-48525:** DoS via CPU/memory amplification in detached payload decode.
- **Remediation:** Update `pyproject.toml` constraint to `pyjwt>=2.13.0` and run `uv lock`.

### 3. CVE-2026-58203 — pydantic-settings Symlink Traversal

- **Package:** pydantic-settings 2.12.0
- **Latest safe version:** pydantic-settings >= 2.14.2
- **Description:** Symlink attack allows local file read outside `secrets_dir` when `secrets_nested_subdir=True`. Affects 2.12.0 to 2.14.1.
- **Remediation:** Update `pyproject.toml` constraint to `pydantic-settings>=2.14.2` and run `uv lock`.

- **Description:** While 46.0.7 covers known 2026 CVEs, being 3 major versions behind means missing security hardening in 47.x/48.x/49.x.

### 7. FastAPI Bundles Vulnerable Starlette

- **Package:** FastAPI 0.128.1
- **Description:** Pulls starlette < 1.0.1 which has CVE-2026-48710 (BadHost). Upgrading FastAPI resolves both this and finding #1.
- **Remediation:** Upgrade to `fastapi>=0.135`.

### 8. Import Processing Endpoints Lack Explicit Rate Limits

- **File:** `winebox/routers/import_router.py`
- **Affected endpoints:**
  - `POST /upload-parsed` (line 263) — triggers AI mapping via Anthropic API
  - `POST /{batch_id}/rows` (line 317) — unlimited chunk uploads
  - `POST /{batch_id}/process` (line 409) — CPU-intensive batch processing
  - `POST /{batch_id}/process-stream` (line 450) — CPU-intensive streaming
  - `POST /{batch_id}/remap` (line 627) — bulk update
- **Description:** These expensive operations rely only on the global 60/min default. They should have explicit per-endpoint limits (e.g., 5-10/minute for AI calls, 30/minute for uploads).
- **Remediation:** Add `@limiter.limit("5/minute")` decorators to AI/processing endpoints.

### 9. Admin Panel Has No Default Rate Limits

- **File:** `winebox/admin/main.py`, line 58
- **Description:** Unlike the main app (which has `default_limits=["60/minute"]`), the admin panel `Limiter` has no default limits. Only the login endpoint has an explicit `5/minute`. All other admin endpoints are unthrottled.
- **Remediation:** Add `default_limits=["30/minute"]` to the admin panel's Limiter initialization.

### 10. Unbounded `.to_list()` on Event Histories

- **Files:**
  - `winebox/routers/bottles.py`, lines 188-190
  - `winebox/services/cellar_event_view.py`, lines 236-242
- **Description:** Both load ALL events for a wine/item with no `.limit()`. A wine with many events would load all into memory.
- **Remediation:** Add `.limit(500)` or paginate event history queries.

### 11. No `max_time_ms` on Expensive Aggregation Pipelines

- **Files:**
  - `winebox/routers/cellar.py`, line 128 — `$facet` aggregation
  - `winebox/routers/xwines.py`, lines 397-399 — regex search (3 separate queries)
  - `winebox/services/search_service.py`, lines 77-91 — 10-field `$or` regex fallback
- **Description:** No query sets `max_time_ms`. Long-running queries can tie up a worker for the full 30s socket timeout.
- **Remediation:** Add `max_time_ms=5000` to aggregation pipelines and expensive regex queries.

### 12. Admin `delete_user` Does Not Clean Up All User Data

- **File:** `winebox/admin/routers/admin.py`, lines 303-330
- **Description:** Deleting a user does not remove `CellarItem` documents (`cellars` collection), `CellarEvent` documents (`cellar_events` collection), or correctly target `RawUploadRow` documents (which use `batch_id`, not `owner_id`). Personal data is orphaned in the database.
- **Remediation:** Add deletion of cellar items, cellar events, and raw upload rows (via batch IDs) to the `delete_user` endpoint.

## INFO (Best practice recommendations)

### 13. Hardcoded Test Passwords in Utility Scripts

- **Files:**
  - `scripts/check_url_hashes.py`, line 39
  - `scripts/screenshot_import_tab_order.py`, line 53
  - `scripts/screenshot_checkin_enrichment.py`, line 32
- **Description:** Hardcoded `"TestPassword123!"` for ephemeral test users against OAT/local environments. Violates project policy in CLAUDE.md but poses minimal real risk.
- **Remediation:** Read test passwords from environment variables.

### 14. Unmasked URL Logging in Migration Script

- **File:** `scripts/migrations/migrate_sqlite_to_mongo.py`, line 218
- **Description:** Prints the full MongoDB URL to stdout without masking. If run with a production URL containing credentials, those appear in terminal output.
- **Remediation:** Mask the URL to show only first/last 4 characters (matching `deploy/common.py` behavior).

### 15. Missing HTTP Timeouts in DNS Setup Script

- **File:** `scripts/setup_digitalocean_fastmail_dns.py`, lines 64, 77, 92, 102
- **Description:** `requests.get/post/delete` calls without `timeout` parameter. A hung connection could block indefinitely.
- **Remediation:** Add `timeout=30` to all requests calls.

### 16. DMARC Policy Set to `p=none`

- **File:** `scripts/setup_digitalocean_fastmail_dns.py`, line 47
- **Description:** DMARC is monitoring-only. If DKIM/SPF are validated, tighten to `p=quarantine` or `p=reject` to prevent email spoofing.
- **Remediation:** Update DMARC record to `p=reject` after confirming email delivery is stable.

### 17. Public Endpoints Without Authentication (Intentional)

- **Files:** `winebox/routers/xwines.py`, `winebox/routers/reference.py`
- **Description:** X-Wines and reference endpoints serve public dataset information without auth. Intentional — needed for autocomplete on unauthenticated forms. Rate-limited.
- **Status:** By design, no action needed.

### 18. 50K-Element `$in` Array in X-Wines Price Filter

- **File:** `winebox/routers/xwines.py`, lines 132-134
- **Description:** Loads up to 50,000 IDs into a `$in` filter. Not an injection but degrades query performance.
- **Remediation:** Consider a `$lookup` pipeline or paginated intersection.

### 19. Missing `max_length` on Some Pydantic Fields

- **Files:**
  - `winebox/schemas/wine.py`, lines 26-33 — `wine_type`, `price_tier`, `producer_type`, `custom_fields`
  - `winebox/schemas/import_schemas.py`, lines 33-39 — `mapping` dict
  - `winebox/admin/routers/admin.py`, line 193 — admin `password` field
- **Description:** Missing length constraints could allow oversized documents or Argon2 CPU exhaustion on very long passwords.
- **Remediation:** Add `max_length` constraints; cap admin password at 256 chars.

### 20. Unbounded `to_list(length=None)` in Cellar Inventory

- **File:** `winebox/services/cellar_inventory.py`, line 88
- **Description:** Fetches all cellar items for a set of wine_ids without limit. Bounded by page size in practice.
- **Remediation:** Add explicit length parameter.

### 21. JWT TTL 120 Minutes with No Refresh Token

- **File:** `winebox/auth/regstack_setup.py`, line 67
- **Description:** Tokens expire after 2 hours with no refresh mechanism. Users must re-authenticate. Not a vulnerability — a UX/security tradeoff.
- **Status:** Informational only.

### 22. `enforce_https` Defaults to False in Code

- **File:** `winebox/config/schema.py`, line 19
- **Description:** Code default is `False`; production config template sets it `True`. Relies on deployment pipeline correctness.
- **Status:** Informational — production startup validation would warn but not block.

### 23. PostHog API Key Exposed Without Auth

- **File:** `winebox/main.py`, lines 312-325
- **Description:** `/api/config/analytics` returns PostHog project API key without auth. PostHog project keys are write-only by design.
- **Status:** By design, no action needed.

### 24. `str(e)` in Import Error Responses

- **File:** `winebox/routers/import_router.py`, line 180
- **Description:** `ValueError` from spreadsheet parsing passed as HTTP error detail. Could theoretically include library-internal technical messages.
- **Remediation:** Wrap with a generic message: "Invalid file format. Please check your spreadsheet."

## CLEAN (Passed review)

- **Hardcoded secrets:** No real API keys, credentials, or connection strings in source code
- **Git history:** No secrets ever committed; .gitignore covers all sensitive file types
- **Authentication:** All user-data endpoints require `RequireAuth`; all admin endpoints require `RequireAdmin`
- **Data isolation:** Every user-data query scopes by `owner_id` or `cellar_id`
- **Password security:** Argon2id with constant-time verification; password change invalidates all tokens
- **Token security:** JTI-based revocation; bulk invalidation on password change; no token leakage in logs
- **Security headers:** Full set (CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Permissions-Policy)
- **CORS:** Same-origin by default; no wildcard origins
- **CSP compliance:** No inline scripts; external JS files only
- **HTTPS enforcement:** nginx redirects HTTP to HTTPS; HSTS with preload
- **NoSQL injection:** All user input is escaped for regex; ObjectId parsing wrapped in try/except; no unsafe operators
- **File uploads:** Validated by extension, magic bytes, and size; UUID filenames prevent path traversal
- **XSS prevention:** Jinja2 autoescape; html.escape() for user content in exports
- **Systemd hardening:** Runs as dedicated user; NoNewPrivileges; ProtectSystem=strict
- **nginx:** server_tokens off; TLS 1.2/1.3; strong ciphers; IP-restricted admin
- **API key handling:** All loaded from environment; Anthropic clients have timeouts
- **Debug mode:** Blocked in production by startup validation
- **Sensitive data logging:** None found
