### WARNING

**WARNING-1: Price tracker photo upload does not validate file extension or magic bytes**

- **File:** `winebox/routers/price_tracker.py` (lines 192–209)
- **Detail:** The price tracker photo upload endpoint checks `content_type` against a whitelist and enforces a 10 MB size limit, but unlike `ImageStorageService.save_image()` (which validates magic bytes and overrides the user-declared extension), the price tracker takes the file extension directly from the user-supplied filename without validating it against an allowlist or checking magic bytes. A file named `photo.svg` with `content_type: image/jpeg` would be saved as `{uuid}.svg`. This is inconsistent with the main image upload flow which has defence-in-depth (extension validation + magic byte detection + detected extension override).
- **Recommendation:** Validate the extension against an allowlist (e.g., `{"jpg", "jpeg", "png", "webp", "heic"}`) and add magic byte detection to match the `ImageStorageService` pattern. Alternatively, reuse `ImageStorageService.save_image()` for price tracker photos.

**WARNING-2: `cryptography` package is 2 major versions behind (46.0.7 vs 48.0.0)**

- **File:** `pyproject.toml`, `uv.lock`
- **Detail:** The pinned version 46.0.7 has all known CVEs patched (CVE-2026-39892, CVE-2026-34073), but version 48.0.0 was released 2026-05-04 with OpenSSL 3.5.2 and additional security hardening. Being 2 major versions behind means missing ongoing security improvements.
- **Recommendation:** Upgrade `cryptography` from `>=46.0.7` to `>=48.0.0` and test for compatibility.

### INFO (Best practice recommendations)

**INFO-1: E2E test secret key hardcoded in tasks.py (carried over from previous review)**

- **File:** `tasks.py` (lines 283, 2017)
- **Values:** `"e2e-test-secret-key-not-for-production-use-1234567890"` and `"oat-e2e-test-secret-key-1234567890"`
- **Detail:** Clearly labelled test-only values used for isolated E2E test environments. Not used in production. Low risk.
- **Recommendation:** Consider loading from an environment variable for consistency with project conventions.

**INFO-2: `skip` parameter has no upper bound on most paginated endpoints**

- **Files:** `winebox/routers/search.py`, `winebox/routers/cellar.py`, `winebox/routers/met.py`, `winebox/routers/transactions.py`
- **Detail:** All `skip` parameters use `ge=0` but no upper bound. A very large `skip` value (e.g., `skip=999999999`) forces MongoDB to scan and discard that many documents, which is a minor DoS vector. The X-Wines search endpoint caps skip at `le=10000`, but other endpoints do not.
- **Recommendation:** Add a `le=MAX_USER_RESULTSET` (or similar) cap to `skip` parameters across all paginated endpoints.

**INFO-3: FastAPI and uvicorn are several minor versions behind**

- **Files:** `pyproject.toml`, `uv.lock`
- **Detail:** FastAPI is at 0.128.1 (latest: 0.136.1, 8 minor versions behind) and uvicorn is at 0.40.0 (latest: 0.46.0, 6 minor versions behind). No CVEs found, but bug fixes and performance improvements are accumulating.
- **Recommendation:** Plan an upgrade to pick up recent bug fixes. Test thoroughly, as FastAPI 0.136+ requires Python 3.10+.

**INFO-4: User input reflected in some error messages**

- **Files:** `winebox/routers/transactions.py` (line 71), `winebox/routers/wines/scores.py` (lines 129, 176), `winebox/routers/import_router.py` (line 689)
- **Detail:** User-supplied IDs are included verbatim in 404 error response detail messages (e.g., `f"Transaction with ID {transaction_id} not found"`). FastAPI serializes these as JSON so there is no direct XSS risk, but reflecting user input in error messages is a minor info-leak pattern.
- **Recommendation:** Use generic error messages without echoing the user-supplied value, e.g., `"Transaction not found"`.

**INFO-5: `slowapi` has had no releases in 12+ months**

- **Detail:** slowapi 0.1.9 is the latest version, with no new releases in over a year. No CVEs found, but the project may be approaching dormancy.
- **Recommendation:** Monitor for signs of abandonment. If it becomes unmaintained, evaluate alternatives like `limits` with a custom FastAPI integration.

#### 2. Hardcoded Secrets Scan

- `config/secrets.env.example` contains only placeholder values.
- `.gitignore` properly covers: `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`.

#### 3. Authentication & Authorization Audit

- **All 60+ endpoints** handling user data require `RequireAuth` or `RequireAdmin`.
- **All database queries** for user-owned data filter by `owner_id` or `cellar_id`.
- Public endpoints (`/api/reference/*`, `/api/xwines/*`, `/health`, `/api/config/analytics`) serve only static reference data — no user information exposed.
- Admin endpoints use `RequireAdmin` (not just `RequireAuth`).
- Password changes invalidate all existing tokens via dual mechanism:
  - Per-token blacklist (JTI-based)
  - Bulk `tokens_invalidated_after` cutoff on user document
- Password reset (`on_after_reset_password`) also calls `revoke_all_user_tokens()`.
- User registration validates email format (Pydantic `EmailStr`) and password length (8+ chars).
- Constant-time password comparison via Argon2 `verify()` with dummy hash for non-existent users.
- Admin self-modification guards: admins cannot deactivate, remove-admin, or delete their own account.
- Price tracker correctly gates sensitive PII (GPS, town, notes, photos) behind ownership checks.

#### 4. NoSQL Injection & Query Safety

- All regex searches use `re.escape()` before compilation (134 uses of `escapeHtml()` in JS).
- No unsafe MongoDB operators (`$where`, `$expr`, `$accumulator`, `$function`) found.
- All `ObjectId` parsing wrapped in `try/except` with proper 400/404 responses.
- All API inputs validated via Pydantic models — no raw `dict` or untyped JSON bodies accepted by endpoints.
- No raw pymongo collection access bypassing model safety for user-supplied queries.
- Search query length capped at 200 characters.
- `$in` queries bounded by `MAX_USER_RESULTSET` or derived from prior bounded queries.
- `ast.literal_eval()` used (not `eval()`) for parsing Python list representations — safe.

#### 5. Input Validation & Injection Prevention

- File uploads validated: magic byte detection, extension whitelist, size limits (main image flow).
- Path traversal prevented: `_safe_resolve()` rejects `..` components and verifies resolved path.
- Generated filenames use UUIDs, not user input.
- Jinja2 templates use `autoescape=True` — no `|safe` or `{% autoescape false %}` usage.
- `escapeHtml()` function in `app.js` covers all 5 dangerous characters (`&`, `<`, `>`, `"`, `'`).
- No `eval()`, `exec()`, `__import__()`, or `compile()` in application code.
- All paginated endpoints enforce maximum limits via `Query(ge=1, le=MAX_PAGE_SIZE)`.

#### 6. Rate Limiting & DoS Prevention

- **Global:** 60 requests/minute per IP.
- **Login:** 30/minute, 200/hour + account lockout after 5 failed attempts (15-minute window).
- **Registration:** 10/minute, 50/hour.
- **Password reset/change:** 5/minute, 20/hour.
- **Search:** 120/minute, 2000/hour with 200-char query limit.
- **Export:** 10/minute, 30/hour.
- **Scan/enrichment:** 20/minute, 100–200/hour.
- **Admin endpoints:** 30/minute (including 5/minute for admin login).
- All paginated queries bounded by `MAX_PAGE_SIZE` (200) and `MAX_USER_RESULTSET` (10,000).
- File upload sizes bounded at both application layer and nginx layer (`client_max_body_size 10M`).
- Database query timeouts configured: 5s server selection, 10s connect, 30s socket.

#### 7. Session & Token Security

- JWT tokens use HS256 with minimum 32-character secret key (enforced at startup).
- Tokens include `jti` (UUID), `iat`, `exp`, and `sub` claims.
- Dual-layer revocation: per-token blacklist + bulk user invalidation cutoff.
- Revoked token cleanup via MongoDB TTL indexes (automatic) + hourly background sweep.
- Purpose-specific secret derivation (SHA-256) for reset/verification tokens prevents type confusion.
- Access tokens expire after 2 hours; verification tokens after 72 hours; reset tokens after 24 hours.
- No token values logged anywhere in the codebase (only jti UUIDs logged).
- HSTS enabled in production: `max-age=31536000; includeSubDomains; preload`.

#### 8. Security Headers

- `X-Content-Type-Options: nosniff` (both FastAPI middleware and nginx)
- `X-Frame-Options: DENY` (both FastAPI middleware and nginx)
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Permitted-Cross-Domain-Policies: none`
- `Permissions-Policy` restricting camera, geolocation, microphone, etc.
- `Content-Security-Policy`: `script-src 'self'` (no unsafe-inline for scripts), PostHog domains whitelisted, `frame-ancestors 'none'`, `object-src 'none'`.
- CORS: empty origin list by default (same-origin only), explicit whitelist when configured. Methods and headers explicitly listed — not `*`.
- No inline scripts in any HTML file (verified across all static and admin templates).
- Nginx: `server_tokens off`, TLS 1.2/1.3 only, strong ciphers (ECDHE+AESGCM), session tickets disabled.

#### 9. Data Exposure

- `UserRead` schema excludes `hashed_password` and internal fields.
- Error messages are generic ("Incorrect email or password") — no user enumeration.
- API docs (`/docs`, `/redoc`, `/openapi.json`) disabled in production (`debug=False`).
- No stack traces, database names, or file paths in error responses.
- PostHog public API key properly separated from server-side key.
- No sensitive data (passwords, tokens, API keys) in log output.
