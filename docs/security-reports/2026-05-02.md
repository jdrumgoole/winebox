# Security Review — 2026-05-02

## 🟠 WARNING (Address within 1 week)

### WARN-1: No per-query `maxTimeMS` on MongoDB operations
- **Location:** `winebox/database.py:41-48`
- **Description:** The socket-level timeout (`socketTimeoutMS=30000`) is a connection-level backstop, not a per-query limit. A single complex aggregation or regex search could run for up to 30 seconds before timing out. Adding `maxTimeMS` to expensive operations (search, aggregation pipelines, export queries) would provide tighter control and protect against slow-query DoS.
- **Mitigation in place:** Socket timeout of 30s prevents indefinite hangs. All queries are scoped by `owner_id` which limits dataset size.

### WARN-2: Unbounded `.to_list()` on event history queries
- **Locations:** `winebox/services/cellar_event_view.py:242`, `winebox/routers/bottles.py:190`
- **Description:** These calls fetch ALL cellar events for a single wine or bottle without a `length` parameter. A wine with thousands of events (e.g., from repeated batch import/removal cycles) could produce an expensive query and large memory allocation.
- **Recommendation:** Add `length=` limits or paginate event history.

### WARN-3: Hardcoded test passwords in utility scripts
- **Locations:** `scripts/screenshot_import_tab_order.py:53`, `scripts/check_url_hashes.py:39`
- **Description:** Both scripts contain `password = "TestPassword123!"`. While these are development-only scripts with minimal risk, they violate the project's explicit CLAUDE.md policy: "NEVER hardcode credentials... including one-off scripts."
- **Recommendation:** Read from environment variable (e.g., `WINEBOX_TEST_PASSWORD`) and fail with a clear error if unset.

### WARN-4: Price photo extension not validated against allowlist
- **Location:** `winebox/routers/price_tracker.py:206`
- **Description:** The file extension is taken directly from the user-supplied filename (`photo.filename`) and used in the saved filename. While content-type is validated and the filename is UUID-based (no path traversal), a user could send `Content-Type: image/jpeg` with a filename of `foo.html`, resulting in a file saved as `{uuid}.html`. If these files were ever served statically (via nginx or CDN), the `.html` extension could enable stored XSS.
- **Mitigation in place:** Files are served through auth-gated endpoints with ownership checks, not statically.
- **Recommendation:** Restrict extension to an allowlist (`jpg`, `jpeg`, `png`, `webp`, `heic`) or use magic-bytes detection as the main image storage service does.

### WARN-5: `custom_fields` dict unbounded via JSON body path
- **Location:** `winebox/schemas/wine.py:70` (`WineUpdate` model)
- **Description:** The Form-based record endpoints cap total JSON at 5000 chars via `Form(max_length=5000)`. However, the `WineUpdate` Pydantic model accepts `dict[str, str]` with no size cap on the JSON PUT path. An attacker could submit a wine update with thousands of keys or very long values.
- **Recommendation:** Add a Pydantic validator on `WineUpdate.custom_fields` to limit the number of keys (e.g., 50) and individual key/value lengths.

## 🟡 INFO (Best practice recommendations)

### INFO-1: Admin panel PATCH/DELETE endpoints have no explicit rate limit
- **Location:** `winebox/admin/routers/admin.py:256-331`, `winebox/admin/main.py:51`
- **Description:** The admin app's `Limiter` has no `default_limits`, so the user management endpoints (activate, deactivate, make-admin, remove-admin, verify, delete) inherit no rate limit. Mitigated by nginx IP allowlist restricting admin access to a single IP.

### INFO-2: Admin logout uses `RequireAuth` instead of `RequireAdmin`
- **Location:** `winebox/admin/routers/auth.py:48-49`
- **Description:** Functionally harmless (only revokes the caller's own token), but for consistency in the admin panel, should use `RequireAdmin`.

### INFO-3: Admin login does not pass IP address for audit logging
- **Location:** `winebox/admin/routers/auth.py:31`
- **Description:** `authenticate_user()` is called without `ip_address`, so failed admin login attempts will have `ip_address=None` in security logs. The main app login correctly passes `ip_address`.

### INFO-4: User deactivation/deletion does not explicitly revoke tokens
- **Location:** `winebox/admin/routers/admin.py:265-272` (deactivation), `winebox/admin/routers/admin.py:303-330` (deletion)
- **Description:** Deactivation sets `is_active=False` but doesn't call `revoke_all_user_tokens()`. Functionally safe because `get_current_user()` checks `is_active` on every request. Explicit revocation would provide immediate invalidation.

### INFO-5: No OCSP stapling in nginx configs
- **Locations:** `deploy/nginx-winebox.conf`, `deploy/nginx-winebox-oat.conf`
- **Description:** Adding `ssl_stapling` and `ssl_stapling_verify` would improve TLS handshake performance and provide certificate revocation status to clients.

### INFO-6: `skip` query parameters have no upper bound on most endpoints
- **Locations:** `winebox/routers/cellar.py:25`, `winebox/routers/search.py:46`, `winebox/routers/met.py:17`, `winebox/routers/transactions.py:32`, `winebox/routers/wines/crud.py:23`, `winebox/routers/price_tracker.py:259,332`
- **Description:** A very large `skip` value forces MongoDB to scan and discard documents. Impact is limited by `owner_id` scoping and `MAX_USER_RESULTSET` bounds. Only the X-Wines search endpoint bounds `skip` to 10,000.

### INFO-7: Missing `max_length` on some WineBase/WineUpdate string fields
- **Location:** `winebox/schemas/wine.py:26,29,32,63,66,69`
- **Description:** `wine_type`, `price_tier`, and `producer_type` fields have no `max_length` constraint. Arbitrarily long strings waste storage and could cause display issues.

### INFO-8: Admin `CreateUserRequest.password` has no `max_length`
- **Location:** `winebox/admin/routers/admin.py:193`
- **Description:** An extremely long password would be expensive to hash (Argon2). Low risk since the endpoint requires `RequireAdmin`. Recommend adding `max_length=128`.

### INFO-9: FastAPI minimum pin is 27 minor versions behind latest
- **Location:** `pyproject.toml` — `fastapi>=0.109.0` vs latest 0.136.1
- **Description:** No direct CVE, but staying far behind increases risk of missing transitive security fixes. Consider bumping the floor.

### INFO-10: Verify PyYAML uses safe loaders
- **Description:** CVE-2026-24009 affects apps using `yaml.load()` without `SafeLoader`. Confirm all YAML parsing uses `yaml.safe_load()` or `yaml.SafeLoader`.

### INFO-11: `enforce_https` defaults to `False`
- **Location:** `winebox/config/schema.py:19`
- **Description:** Mitigated by nginx handling HTTPS enforcement at the reverse proxy layer. Startup validator warns but does not block.

## 🟢 CLEAN (Passed review)

### Hardcoded Secrets
No real API keys, connection strings, passwords, private keys, or JWTs found in the codebase. All secrets loaded from environment variables or `secrets.env` (gitignored). `.gitignore` properly covers `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`.

### Dependency CVEs
All known CVE-2026 vulnerabilities are addressed by current pins:
- Pillow >=12.2.0 (CVE-2026-25990, CVE-2026-40192)
- PyJWT >=2.12.0 (CVE-2026-32597)
- cryptography >=46.0.7 (CVE-2026-39892, CVE-2026-34073)
- aiohttp >=3.13.4 (CVE-2026-34520)
- requests >=2.33.1 (CVE-2026-25645)
- python-multipart >=0.0.26 (CVE-2026-40347, CVE-2026-24486)
- cairosvg >=2.9.0 (CVE-2026-31899)
- anthropic >=0.96.0 (CVE-2026-34450, CVE-2026-34452)
- certifi >=2026.4.22 (fresh CA bundle)

### Authentication & Authorization
- All user-data endpoints require `RequireAuth` and filter by `owner_id`/`cellar_id`
- All admin endpoints require `RequireAdmin`
- Password hashing uses Argon2id via pwdlib
- Constant-time comparison prevents timing-based user enumeration (dummy hash on missing users)
- Account lockout: 5 failed attempts in 15 minutes triggers 15-minute lockout
- Password changes and resets invalidate all existing tokens (dual-layer: per-token jti blacklist + per-user `iat` cutoff)
- Admin panel has defence-in-depth: nginx IP allowlist + RequireAdmin + separate subdomain

### JWT Token Security
- Algorithm: HS256 (locked, no algorithm confusion)
- Expiry: 2 hours
- Includes `jti` for per-token revocation
- Bulk per-user invalidation via `tokens_invalidated_after`
- Background cleanup prunes expired tokens hourly
- Secret key validated at startup (minimum 32 chars, blocked in production if weak)
- Derived HMAC secrets for different token types (reset, verify) prevent cross-purpose reuse

### NoSQL Injection
- All queries use dictionary-based construction, never string interpolation
- No dangerous operators (`$expr`, `$accumulator`, `$where`, `$function`) found
- All user input comes through FastAPI typed parameters (Pydantic validation)

### Regex Injection
- `re.escape()` consistently used on all user-supplied regex patterns across search, reference, and X-Wines endpoints

### ObjectId Parsing
- All `ObjectId()` conversions from URL parameters wrapped in try/except with proper 400/404 responses

### Path Traversal
- `_safe_resolve()` rejects empty filenames, `.`, `..`, and path separators; resolves and validates within storage directory
- Price photo endpoint checks for `/`, `\`, and `..`

### HTML/XSS Injection
- No `|safe` or `{% autoescape false %}` in any Jinja template
- Frontend `innerHTML` usage consistently passes user data through `escapeHtml()`

### Security Headers
- X-Content-Type-Options: `nosniff`
- X-Frame-Options: `DENY`
- X-XSS-Protection: `1; mode=block`
- Referrer-Policy: `strict-origin-when-cross-origin`
- Content-Security-Policy: comprehensive, no `unsafe-inline` for scripts
- Strict-Transport-Security: `max-age=31536000; includeSubDomains; preload` (nginx + app)
- Permissions-Policy: restricts camera, geolocation, etc.
- `frame-ancestors 'none'`; `object-src 'none'`; `base-uri 'self'`

### CORS
- Default: same-origin only (`cors_origins: []`)
- When active: explicit origin list, not `"*"`; restricted methods and headers

### Data Exposure
- `hashed_password` never in response schemas
- `owner_id` stripped from exports and redacted for non-owners in price data
- Error handlers return controlled exceptions, no raw stack traces
- OpenAPI docs disabled outside debug mode (both main and admin apps)

### HTTPS & TLS
- nginx redirects HTTP to HTTPS (301) on all server blocks
- TLS 1.2 and 1.3 only; strong cipher suite (ECDHE + AES-GCM)
- Session tickets disabled; HSTS with 2-year max-age
- `server_tokens off` hides nginx version

### File Upload Validation

- Content-type and size checks on price photos and import spreadsheets

### Third-Party Integrations
