### :orange_circle: WARNING

**WARNING-1: aiohttp 3.13.3 vulnerable to CVE-2026-34520 (HTTP response splitting)**

- **Package:** aiohttp (transitive dependency via aioboto3 → aiobotocore)
- **Pinned version:** 3.13.3
- **CVE:** CVE-2026-34520 — The C parser (llhttp) accepts null bytes and control characters in response header values, enabling HTTP response splitting / header injection.
- **Fix:** Upgrade to aiohttp 3.13.4+.
- **Mitigating factors:** aiohttp is used as an HTTP client for AWS S3 communication (via aioboto3), not for parsing responses from untrusted servers. The actual risk is low in this context, but the vulnerability is real and the fix is a simple lock file update.
- **Recommended action:** Run `uv lock --upgrade-package aiohttp` and verify aioboto3 compatibility.

**WARNING-2: Wine lookups in transaction export/view not filtered by owner_id**

- **Files:** `winebox/routers/export.py` (line 250), `winebox/services/cellar_event_view.py` (lines 179, 219)
- **Detail:** Wine documents are looked up by `_id` (from owner-scoped events) without adding an `owner_id` filter. Since the wine_ids come from the user's own events, this is not directly exploitable — an attacker cannot inject arbitrary wine_ids into their own transaction history. However, it violates defense-in-depth: if a bug elsewhere allowed event data to reference another user's wine, the lookup would succeed.
- **Recommended action:** Add `"owner_id": current_user.id` to these wine queries.

**WARNING-3: Admin user deletion leaves orphaned CellarItem and CellarEvent documents**

- **File:** `winebox/admin/routers/admin.py` (lines 287–296)
- **Detail:** The `delete_user` endpoint deletes wines, transactions, and import batches, but does not delete `CellarItem` or `CellarEvent` documents. Compare with `winebox/routers/wines/crud.py:delete_all_wines` which does clean these up. Orphaned documents waste storage and create an inconsistent database state.
- **Recommended action:** Add `CellarItem` and `CellarEvent` deletion to the admin `delete_user` endpoint, matching the cleanup in `delete_all_wines`.

### :yellow_circle: INFO (Best practice recommendations)

**INFO-1: Admin panel mutation endpoints lack rate limiting**

- **File:** `winebox/admin/routers/admin.py`
- **Detail:** The `create_user`, `activate`, `deactivate`, `make-admin`, `remove-admin`, `verify`, and `delete` endpoints have no `@limiter.limit()` decorators. Only the read endpoints (`/api/info`, `/api/users`, `/api/stats`) have 30/minute rate limits. The admin panel is IP-restricted at the nginx layer, which limits the blast radius, but defense-in-depth recommends rate limiting mutation endpoints too.
- **Recommendation:** Add `@limiter.limit("10/minute")` to all admin mutation endpoints.

**INFO-2: Admin panel exposes OpenAPI docs in all environments**

- **File:** `winebox/admin/main.py` (line 52)
- **Detail:** The admin `FastAPI()` instance does not disable `/docs`, `/redoc`, or `/openapi.json`. The main app disables these in non-debug mode. Since the admin panel is IP-restricted, this is low risk, but it should be consistent.
- **Recommendation:** Disable API docs in the admin panel when not in debug mode, matching the main app's behavior.

**INFO-3: SECURITY.md describes "Single-Tenant Design" but codebase is multi-tenant**

- **File:** `SECURITY.md` (lines 7–19)
- **Detail:** The document states "There is no user-level data isolation by design" and describes a single-tenant architecture, but the actual codebase has full multi-tenant support with owner_id filtering on all user data. This is misleading and could cause confusion for contributors.
- **Recommendation:** Update SECURITY.md to accurately describe the multi-tenant architecture.

**INFO-4: E2E test secret key hardcoded in tasks.py (carried forward)**

- **File:** `tasks.py` (line 282)
- **Value:** `"e2e-test-secret-key-not-for-production-use-1234567890"`
- **Detail:** Previous review recommended loading from `WINEBOX_E2E_SECRET_KEY` env var. Commit d9693ca partially addressed this — the OAT E2E path (line 1771) now uses `env_values.get("WINEBOX_SECRET_KEY", "oat-e2e-test-secret-key-1234567890")`, but the main E2E test path still has the hardcoded value on line 282.
- **Recommendation:** Use `os.environ.get("WINEBOX_E2E_SECRET_KEY", "e2e-test-secret-key-not-for-production-use-1234567890")` for consistency.

**INFO-5: Price tracker photo file extension not validated against allowlist**

- **File:** `winebox/routers/price_tracker.py` (line 206)
- **Detail:** The file extension is derived from the user-supplied filename (`photo.filename.rsplit(".", 1)[-1].lower()`) and used directly in the stored filename. While content-type is validated against an image MIME whitelist (line 192) and the filename uses a UUID prefix, the extension itself could be anything (e.g., `.php`). The `ImageStorageService._validate_extension` pattern is not used here.
- **Recommendation:** Validate the extension against `{".jpg", ".jpeg", ".png", ".webp", ".heic"}` or derive the extension from the validated content-type.

**INFO-6: certifi CA bundle 3 months behind**

- **Pinned version:** 2026.1.4
- **Latest version:** 2026.4.22
- **Detail:** The CA bundle is 3 months old. While no CVEs were found, regular CA bundle updates ensure revoked CAs are removed promptly.
- **Recommendation:** Run `uv lock --upgrade-package certifi`.

**INFO-7: X-Wines price filter uses large `$in` queries (up to 50,000 IDs)**

- **File:** `winebox/routers/xwines.py` (line 133)
- **Detail:** `_get_price_filtered_ids` loads up to 50,000 IDs from `xwines_prices`, then passes them as `{"$in": list(allowed_ids)}`. This is bounded and functional but creates heavy queries.
- **Recommendation:** Consider a server-side join via `$lookup` or a pipeline rewrite for better performance at scale.

#### 2. Hardcoded Secrets Scan

#### 3. Authentication & Authorization Audit

- **All 60+ endpoints** handling user data require `RequireAuth` or `RequireAdmin`.
- **All database queries** for user-owned data filter by `owner_id` or `cellar_id` (with the exception of WARNING-2 above).
- Public endpoints (`/api/reference/*`, `/api/xwines/*`, `/health`, `/api/config/analytics`) serve only static reference data — no user information exposed.
- Admin endpoints use `RequireAdmin` (not just `RequireAuth`).
- Admin self-protection prevents admins from deactivating/deleting their own accounts.
- Password changes invalidate all existing tokens via dual mechanism:
  - Per-token blacklist (JTI-based)
  - Bulk `tokens_invalidated_after` cutoff on user document
- User registration validates email format (Pydantic `EmailStr`) and password strength (8+ chars with feedback).
- Constant-time password comparison via Argon2 `verify()` with dummy hash for non-existent users.

#### 4. NoSQL Injection & Query Safety

- All regex searches use `re.escape()` before compilation.
- No unsafe MongoDB operators (`$where`, `$expr`, `$accumulator`) found.
- All `ObjectId` parsing wrapped in `try/except` with proper 400/404 responses.
- All API inputs validated via Pydantic models — no raw `dict` or untyped JSON bodies.
- No raw pymongo collection access bypassing model safety.
- Search query length capped at 200 characters.

#### 5. Input Validation & Injection Prevention

- File uploads validated: magic byte detection, extension whitelist, size limits (import capped at 25 MB, images at 10 MB).
- Path traversal prevented in image serving (`_safe_resolve()` rejects `..` components).
- Generated filenames use UUIDs, not user input.
- Jinja2 templates use `autoescape=True` — no `|safe` or `{% autoescape false %}` usage.
- No `eval()`, `exec()`, `__import__()`, or `compile()` in application code. Only `ast.literal_eval()` used for safe string parsing.
- All paginated endpoints enforce maximum limits via `Query(ge=1, le=MAX)`.
- No unsafe YAML loading (`yaml.load`), no pickle/marshal deserialization.

#### 6. Rate Limiting & DoS Prevention

- **Global:** 60 requests/minute per IP.
- **Login:** 30/minute, 200/hour + account lockout after 5 failed attempts (15-minute window).
- **Registration:** 10/minute, 50/hour.
- **Password reset/change:** 5/minute, 20/hour.
- **Search:** 120/minute, 2000/hour with 200-char query limit.
- **Export:** 10/minute, 30/hour.
- **Scan/enrichment:** 20/minute, 100–200/hour.
- **Admin login:** 5/minute.
- **Admin reads:** 30/minute.
- All paginated queries bounded by `MAX_USER_RESULTSET`.

#### 7. Session & Token Security

- JWT tokens use HS256 with minimum 32-character secret key (enforced at startup).
- Tokens include `jti` (UUID), `iat`, `exp`, and `sub` claims.
- Dual-layer revocation: per-token blacklist + bulk user invalidation cutoff.
- Revoked token cleanup via MongoDB TTL indexes (automatic).
- Purpose-specific secret derivation (SHA256) for reset/verification tokens prevents type confusion.
- No token values logged anywhere in the codebase.
- HSTS enabled in production: `max-age=63072000; includeSubDomains`.

#### 8. Security Headers

- `X-Content-Type-Options: nosniff` (FastAPI middleware + nginx static files)
- `X-Frame-Options: DENY` (FastAPI middleware + nginx static files)
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Permitted-Cross-Domain-Policies: none`
- `Permissions-Policy` restricting camera, geolocation, microphone, etc.
- `Content-Security-Policy`: `script-src 'self'` (no unsafe-inline for scripts), PostHog domains whitelisted.
- CORS: empty origin list by default (same-origin only), explicit whitelist when configured.
- Admin panel reuses main app's `SecurityHeadersMiddleware`.
- Nginx adds `X-Content-Type-Options`, `X-Frame-Options`, and HSTS on all static file locations.

#### 9. Data Exposure

- Error messages are generic ("Incorrect email or password") — no user enumeration.
- API docs (`/docs`, `/redoc`, `/openapi.json`) disabled in production (main app).
- No stack traces, database names, or file paths in error responses.
- Admin panel does not expose MongoDB connection URL (intentionally omitted).
- PostHog public API key properly separated from server-side key.
- Export strips `owner_id` from exported data.
- Price tracker properly gates sensitive fields (GPS, notes) by ownership.
