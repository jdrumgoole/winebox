### 🟡 INFO (Best practice recommendations)

**INFO-1: SECURITY.md describes single-tenant architecture but codebase is multi-tenant**

- **File:** `SECURITY.md` (lines 5-18)
- **Detail:** SECURITY.md states "One instance serves one user (or household)" and "There is no user-level data isolation by design." This contradicts the actual codebase which implements full multi-tenant isolation with `owner_id` filtering on all 60+ endpoints, per-user token revocation, and per-user data scoping. The documentation is stale — the application has evolved to a multi-user SaaS model.
- **Recommendation:** Update SECURITY.md to accurately describe the multi-tenant architecture, including `owner_id` isolation, per-user authentication, and admin separation.

**INFO-2: Price tracker photo upload lacks magic byte validation**

- **File:** `winebox/routers/price_tracker.py` (lines 192-209)
- **Detail:** The price tracker photo upload validates the `content_type` header and file size but does not perform magic byte detection. The main image upload (`winebox/services/image_storage.py`) has robust magic byte validation and ignores the declared extension in favour of the detected type. The price tracker upload trusts the client-declared `content_type` and uses the client-declared file extension. An attacker with a valid session could upload a non-image file with a spoofed content-type.
- **Mitigating factors:** Files are stored in a non-web-accessible directory, serving requires ownership verification via authenticated endpoint, and the upload requires authentication. Risk is low.
- **Recommendation:** Reuse `detect_image_type()` from `image_storage.py` to validate content and use the detected extension instead of the declared one, consistent with the main upload flow.

**INFO-3: Password strength validation is length-only (8 characters minimum)**

- **File:** `winebox/auth/schemas.py` (lines 34-41)
- **Detail:** Registration and password change enforce a minimum of 8 characters but do not require complexity. The UI provides client-side strength feedback (commit a8665af), but server-side validation remains length-only. This is acceptable per NIST SP 800-63B guidance which discourages complexity rules. Carried over from previous review (2026-04-26 INFO-3).
- **Recommendation:** Consider adding a blocklist of common passwords (e.g. top 10,000) on the server side.

**INFO-4: E2E test secret key still hardcoded in tasks.py**

- **File:** `tasks.py` (line 283, line 2017)
- **Values:** `"e2e-test-secret-key-not-for-production-use-1234567890"`, `"oat-e2e-test-secret-key-1234567890"`
- **Detail:** Clearly labelled test-only values used exclusively for isolated E2E test environments and OAT deployments. Not used in production. Low risk. Carried over from previous review (2026-04-26 INFO-5).
- **Recommendation:** Consider loading from an environment variable for consistency with project conventions.

#### 3. Authentication & Authorization Audit

- **All 60+ endpoints** handling user data require `RequireAuth` or `RequireAdmin`.
- **All database queries** for user-owned data filter by `owner_id` or `cellar_id`.
- Public endpoints (`/api/reference/*`, `/api/xwines/*`, `/health`, `/api/config/analytics`) serve only static reference data — no user information exposed.
- Admin endpoints use `RequireAdmin` (not just `RequireAuth`), verified in both main and admin panel routers.
- Admin panel (`winebox/admin/`) requires `RequireAdmin` on all management endpoints.
- Admin login (`/api/auth/login` on admin panel) rejects non-admin users with 403.
- Password changes invalidate all existing tokens via dual mechanism:
  - Per-token blacklist (JTI-based)
  - Bulk `tokens_invalidated_after` cutoff on user document
- Password reset via fastapi-users also invalidates all tokens (`on_after_reset_password`).
- User registration validates email format (Pydantic `EmailStr`) and password length (8+ chars).
- Constant-time password comparison via Argon2 `verify()` with dummy hash for non-existent users.
- Account lockout after 5 failed attempts within 15-minute window (15-minute lockout duration).
- Image serving (`/api/images/{filename}`) verifies ownership before serving — no open static file access.

#### 4. NoSQL Injection & Query Safety

- All regex searches use `re.escape()` before compilation (`search_service.py`, `reference.py`, `xwines.py`).
- No unsafe MongoDB operators (`$where`, `$expr`, `$accumulator`, `$function`) found anywhere.
- All `ObjectId` parsing wrapped in `try/except InvalidId` with proper 400/404 responses.
- All API inputs validated via Pydantic models — no raw `dict` or untyped JSON bodies accepted.
- No raw pymongo collection access bypassing model safety in user-facing code.
- Search query length capped at 200 characters.

#### 5. Input Validation & Injection Prevention

- File uploads validated: magic byte detection, extension whitelist (JPEG/PNG/GIF/WebP), size limits (configurable, default 10 MB).
- Path traversal prevented in image serving (`_safe_resolve()` rejects `..`, `/`, `\` components and validates resolved path stays within storage directory).
- Generated filenames use UUIDs, not user input.
- No `eval()`, `exec()`, `__import__()`, or `compile()` in application code.
- All paginated endpoints enforce maximum limits via `Query(ge=1, le=MAX_PAGE_SIZE)`.
- Admin pagination properly bounded with `MAX_PAGE_SIZE` cap.
- Shell commands in invoke tasks use `shlex.quote()` for all user-provided parameters.

#### 6. Rate Limiting & DoS Prevention

- **Global:** 60 requests/minute per IP.
- **Login:** 30/minute, 200/hour + account lockout after 5 failed attempts.
- **Admin login:** 5/minute (stricter).
- **Registration:** 10/minute, 50/hour.
- **Password reset/change:** 5/minute, 20/hour.
- **Search:** 120/minute, 2000/hour with 200-char query limit.
- **Export:** 10/minute, 30/hour.
- **Import (file upload):** 10/minute, 30/hour.
- **Demo install:** 5/minute, 10/hour.
- **X-Wines search:** 120/minute, 2000/hour.
- **X-Wines export:** 10/minute, 30/hour.
- All paginated queries bounded by `MAX_PAGE_SIZE` (200), `MAX_USER_RESULTSET` (10,000), or `MAX_REFERENCE_RESULTSET` (5,000).
- MongoDB connection: `serverSelectionTimeoutMS=5000`, `connectTimeoutMS=10000`, `socketTimeoutMS=30000`.
- Anthropic API calls: explicit timeouts (60-120 seconds).

#### 7. Session & Token Security

- JWT tokens use HS256 with minimum 32-character secret key (enforced at startup — production blocked if too short).
- Tokens include `jti` (UUID), `iat`, `exp`, and `sub` claims.
- Dual-layer revocation: per-token blacklist (JTI) + bulk user invalidation cutoff (`tokens_invalidated_after`).
- Expired revoked tokens cleaned up hourly by background task.
- Purpose-specific secret derivation (SHA256) for reset and verification tokens prevents type confusion.
- No token values logged anywhere in the codebase.
- HSTS enabled in production: `max-age=63072000` (2 years) with `includeSubDomains; preload`.
- HTTP → HTTPS redirect configured for all domains in nginx.
- No deprecated `datetime.utcnow()` usage — all timestamps use `datetime.now(timezone.utc)`.

#### 8. Security Headers

- `X-Content-Type-Options: nosniff` — set in both FastAPI middleware and nginx static locations.
- `X-Frame-Options: DENY` — set in both FastAPI middleware and nginx static locations.
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Permitted-Cross-Domain-Policies: none`
- `Permissions-Policy` restricting accelerometer, gyroscope, magnetometer, microphone, payment, USB; allowing camera and geolocation on self only.
- `Content-Security-Policy`: `script-src 'self'` (no `unsafe-inline` for scripts), `style-src 'self' 'unsafe-inline'` (for basic inline styles only), PostHog domains whitelisted, `frame-ancestors 'none'`, `form-action 'self'`, `object-src 'none'`.
- CORS: empty origin list by default (same-origin only), explicit whitelist when configured. Methods limited to GET/POST/PUT/DELETE/PATCH. Headers limited to Authorization and Content-Type.
- Nginx: `server_tokens off` hides version information.
- No inline scripts found in any HTML files.

#### 9. Data Exposure

- `UserResponse` model excludes `hashed_password` and internal fields.
- Admin user listing excludes `hashed_password` — returns only id, email, full_name, status flags, timestamps, cellar_size.
- Error messages are generic ("Incorrect email or password") — no user enumeration via login.
- API docs (`/docs`, `/redoc`, `/openapi.json`) disabled in production on both main app and admin panel.
- No stack traces, database names, or file paths in error responses.
- PostHog public API key properly separated from server-side key.
- Admin `/api/info` endpoint intentionally does not expose MongoDB hostname.
- Price tracker redacts sensitive fields (town, county, notes, photo) for non-owner entries.
