### :orange_circle: WARNING

**WARNING-1: `SlowAPIMiddleware` is never installed — global `default_limits` is dead code**

- **File:** `winebox/main.py:30-34,207-209`
- **Detail:** The main app creates `limiter = Limiter(key_func=get_remote_address, default_limits=["60/minute"], ...)` and registers it as `app.state.limiter` with a `RateLimitExceeded` exception handler, but **never calls `app.add_middleware(SlowAPIMiddleware)`**. Confirmed via `grep -rn "SlowAPIMiddleware" winebox/` — no matches anywhere in the codebase.
- **How slowapi works:** The `default_limits` are only enforced by the middleware's `dispatch()` method. Without the middleware, endpoints that have explicit `@limiter.limit()` decorators still work (the decorator calls `_check_request_limit` directly), but endpoints without decorators have **zero rate limiting** — the declared "60/minute" default is never evaluated.
- **Impact:** Of ~80 total endpoints across the main app and wines sub-router, only 11 have explicit `@limiter.limit()` decorators. The remaining ~70 endpoints — including all wine CRUD, cellar, bottles, cases, met, transactions, most import processing, reference data, some X-Wines endpoints (unauthenticated), and the destructive `DELETE /api/wines/all` — have no rate limiting at all.
- **Mitigations that reduce severity:**
  - Most affected endpoints require `RequireAuth` (an attacker needs a valid account).
  - Auth endpoints (login, register, password reset) have their own working limits via regstack's separate rate limit mechanism, unaffected by this issue.
  - Explicitly rate-limited endpoints (search, scan, enrichment, export, import upload, demo, prices POST, X-Wines search/export, admin GETs, admin login) are unaffected — their decorators work independently of the middleware.
  - MongoDB socket timeout (30s) and connection timeouts provide a backstop against query-based DoS.
  - nginx `client_max_body_size 10M` limits upload-based abuse.
- **Endpoints of particular concern:**
  - `DELETE /api/wines/all` (destructive bulk delete, auth-only, no throttle)
  - Import `upload_parsed`, `process_batch`, `process_batch_stream` (trigger Anthropic API calls, auth-only, no throttle)
  - `GET /api/xwines/wines/{id}`, `/stats`, `/types`, `/countries` (unauthenticated, no throttle)
  - Admin mutation endpoints (create/activate/deactivate/make_admin/remove_admin/verify/delete user — mitigated by IP allowlist)
- **Recommendation:** Add `from slowapi.middleware import SlowAPIMiddleware` and `app.add_middleware(SlowAPIMiddleware)` in `winebox/main.py` immediately after `app.state.limiter = limiter`. Also add it to `winebox/admin/main.py`. Additionally, add explicit per-route limits to high-value endpoints (destructive ops, AI-calling endpoints, unauthenticated endpoints) rather than relying solely on the global default.
- **Status:** New finding — 2026-08-20.

**INFO-8: Starlette 0.50.0 is affected by CVE-2026-48710 (BadHost) — no practical impact on WineBox**

- **File:** `uv.lock` — starlette pinned at 0.50.0; patch is in starlette 1.0.1
- **CVE:** CVE-2026-48710 — Starlette reconstructs `request.url` from the HTTP Host header without validation. A malformed Host header can cause `request.url.path` to differ from the path the ASGI server actually routed, allowing middleware that makes security decisions based on `request.url.path` to be bypassed.
- **Impact on WineBox: None.** WineBox does not use path-based auth middleware. Authentication is enforced via FastAPI dependency injection (`RequireAuth`, `RequireAdmin`) on individual route handlers, which operate on the ASGI scope path (the correctly-routed path), not `request.url.path`. Additionally, nginx normalises Host headers in production.
- **Upgrade path:** FastAPI 0.128.1 constrains starlette to `<0.51.0,>=0.40.0`. Upgrading to starlette >=1.0.1 requires upgrading FastAPI to >=0.136.0. See also INFO-35 for additional Starlette CVEs.
- **Recommendation:** Plan a coordinated FastAPI + Starlette upgrade in a future maintenance cycle.
- **Status:** Carried forward from 2026-05-27 review.

**INFO-12: Vision-calling write endpoints rely on global rate limit only**

- **Files:** `winebox/routers/wines/record.py`, `winebox/routers/wines/met.py`

**INFO-13: Admin deactivation does not bump `tokens_invalidated_after`**

- **File:** `winebox/admin/routers/admin.py:265-272`
- **Detail:** When an admin deactivates a user, the endpoint sets `is_active = False` but does not bump `tokens_invalidated_after`. This is not a bypass — regstack's auth dependency checks `user.is_active` on every authenticated request (via `_fetch_winebox_user` at `winebox/services/auth.py:72`) and regstack also checks `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` at `regstack/auth/dependencies.py:180`, so the deactivated user is effectively blocked immediately on their next request. However, bumping `tokens_invalidated_after` would add belt-and-suspenders redundancy.
- **Impact:** None in current architecture — `is_active` check provides immediate blocking.
- **Recommendation:** Consider setting `tokens_invalidated_after = now` alongside `is_active = False` for defence-in-depth.
- **Status:** Carried forward from 2026-05-29 review.

**INFO-14: Deprecated `X-XSS-Protection` header set to `1; mode=block`**

- **File:** `winebox/main.py:46`
- **Detail:** The `X-XSS-Protection` header is deprecated and has been removed from modern browsers. Setting it to `1; mode=block` could theoretically introduce XSS vulnerabilities in older browsers by enabling the browser's buggy XSS auditor. - **Impact:** Negligible — the strong CSP is the primary XSS defence.
- **Recommendation:** Change to `X-XSS-Protection: 0` or remove the header.
- **Status:** Carried forward from 2026-05-29 review.
