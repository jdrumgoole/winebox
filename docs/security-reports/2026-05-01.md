### 🟡 INFO (Best practice recommendations)

**INFO-1: Price tracker photo upload lacks magic-byte validation and extension allowlist**

- **File:** `winebox/routers/price_tracker.py` (lines 192–210)
- **Detail:** The price tracker photo upload checks `content_type` against an allowlist (JPEG, PNG, WebP, HEIC) but does not validate magic bytes to confirm the file is actually an image. It also uses the user-supplied file extension directly (`photo.filename.rsplit(".", 1)[-1]`) without validating against an extension allowlist. A file with a spoofed `Content-Type: image/jpeg` but a `.html` or `.svg` extension would be saved and later served via `FileResponse` with the inferred content type, potentially enabling self-XSS. The main `ImageStorageService.save_image()` properly validates magic bytes and uses the detected extension — this endpoint should match that pattern.
- **Risk:** Low. Photos are only accessible to their owner (owner_id-scoped query), so exploitation requires the attacker to already be authenticated as the victim. The `X-Content-Type-Options: nosniff` header prevents MIME sniffing but not execution of a properly-named `.html` file.
- **Recommendation:** Reuse `ImageStorageService.save_image()` or add magic-byte validation and extension allowlist to the price tracker upload.

**INFO-2: Admin panel mutation endpoints lack rate limits**

- **File:** `winebox/admin/main.py` (line 51), `winebox/admin/routers/admin.py` (lines 197, 256, 265, 275, 284, 294, 303)
- **Detail:** The admin panel's limiter is created with `Limiter(key_func=get_remote_address)` — no `default_limits`, unlike the main app's `Limiter(default_limits=["60/minute"])`. Seven mutation endpoints (create user, activate, deactivate, make-admin, remove-admin, verify, delete user) have no rate limit at all. The read endpoints (`/api/info`, `/api/users`, `/api/stats`) and login have explicit limits.
- **Risk:** Low. All admin endpoints are behind nginx IP-allowlist + `RequireAdmin` authentication, so the attack surface is very limited. However, CLAUDE.md guidelines state "Admin endpoints should have stricter rate limits."
- **Recommendation:** Add `default_limits=["30/minute"]` to the admin limiter for baseline protection.

**INFO-3: Admin user deletion does not clean up CellarItem and CellarEvent records**

- **File:** `winebox/admin/routers/admin.py` (lines 303–330)
- **Detail:** The `delete_user` endpoint deletes wines, transactions, import batches, and raw upload rows, but does not delete `CellarItem` (keyed by `cellar_id`) or `CellarEvent` (keyed by `cellar_id`/`owner_id`) records. This leaves orphaned data in the database after user deletion. Not a security vulnerability (orphaned data belongs to a deleted user and is not accessible via any endpoint), but a data hygiene gap.
- **Recommendation:** Add `CellarItem` and `CellarEvent` deletion to the user delete endpoint.

**INFO-4: Admin panel static assets lack cache-busting version parameters**

- **File:** `winebox/admin/static/admin.html` (lines 147–148)
- **Detail:** Admin static files are referenced as `/static/css/admin.css` and `/static/js/admin.js` without version query parameters. The main app uses `?v=0.7.80` for cache busting. After deploys, admins may see stale JavaScript/CSS until they hard-refresh.
- **Risk:** Very low. The admin panel is IP-restricted and accessed by a small number of users.
- **Recommendation:** Add `?v={{ version }}` parameters to admin static file references, consistent with the main app pattern.

**INFO-5: FastAPI 0.128.1 is 8 minor versions behind latest (0.136.1)**

- **Detail:** No CVE directly targets FastAPI at this version, but FastAPI ships security-relevant improvements in minor releases. All other key dependencies (cryptography, PyJWT, Pillow, python-multipart, aiohttp, requests, CairoSVG) are fully patched against known CVEs.
- **Recommendation:** Schedule an upgrade to FastAPI 0.136.1 in a future sprint.

**INFO-6: Fastapi-users `/api/auth/login` endpoint is mounted but produces unusable tokens**

- **File:** `winebox/routers/auth.py` (lines 61–63)
- **Detail:** The fastapi-users auth router is mounted and exposes `POST /api/auth/login`. Tokens issued by this endpoint include an `aud: "fastapi-users:auth"` claim that causes `jwt.decode()` in `get_current_user()` to raise `InvalidAudienceError`, so these tokens cannot authenticate to any protected endpoint. The frontend exclusively uses the custom `POST /api/auth/token` endpoint. The dead endpoint slightly increases attack surface — an attacker could use it to probe valid credentials (it returns 200 vs 400) without the response being useful.
- **Risk:** Very low. The endpoint is rate-limited (30/minute, 200/hour), and the account lockout mechanism still triggers on failed attempts. The information disclosed (valid vs invalid credentials) is not worse than the custom login endpoint.
- **Recommendation:** Consider removing the fastapi-users auth router mount if it is not used, or override `JWTStrategy` to include `jti`/`iat` for consistency.

**INFO-7: Admin login response distinguishes invalid credentials from non-admin accounts**

- **File:** `winebox/admin/routers/auth.py` (lines 33–41)
- **Detail:** The admin login endpoint returns 401 for invalid credentials but 403 for valid credentials on a non-admin account. This allows an attacker to distinguish between "wrong password" and "right password, not admin," confirming account existence and password validity.
- **Risk:** Very low. The admin login endpoint is behind nginx IP-allowlist, so only trusted IPs can reach it. Rate-limited to 5/minute.
- **Recommendation:** Return the same error code (401) for both cases, or merge both into a single generic message.

#### 2. Hardcoded Secrets Scan

- No API keys, connection strings, passwords, private keys, or JWTs found in source code.
- `config/secrets.env.example` contains only placeholder values.
- `.gitignore` properly covers: `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`.
- `git ls-files` confirms no sensitive files tracked (only `config/secrets.env.example`).
- Test fixtures use obvious dummy values (`sk-test`, `phc_test_api_key`, `AKIAIOSFODNN7EXAMPLE`).
- GitHub Actions workflows use `${{ secrets.NAME }}` pattern throughout.
- E2E test secret key now reads from `WINEBOX_E2E_SECRET_KEY` env var with test-only fallback (improved since last review).

#### 3. Authentication & Authorization Audit

- **All 60+ endpoints** handling user data require `RequireAuth` or `RequireAdmin`.
- **All database queries** for user-owned data filter by `owner_id` or `cellar_id`.
- Public endpoints (`/api/reference/*`, `/api/xwines/*`, `/health`, `/api/config/analytics`) serve only static reference data — no user information exposed.
- Admin endpoints use `RequireAdmin` (not just `RequireAuth`).
- Admin panel is IP-restricted at nginx layer + `RequireAdmin` on every endpoint.
- Password changes invalidate all existing tokens via dual mechanism:
  - Per-token blacklist (JTI-based)
  - Bulk `tokens_invalidated_after` cutoff on user document
- User registration validates email format (Pydantic `EmailStr`) and password length (8+ chars).
- Constant-time password comparison via Argon2 `verify()` with dummy hash for non-existent users.
- Admin self-protection: cannot deactivate, remove-admin, or delete own account.

#### 4. NoSQL Injection & Query Safety

- All regex searches use `re.escape()` before compilation.
- No unsafe MongoDB operators (`$where`, `$expr`, `$accumulator`, `$function`) found.
- All `ObjectId` parsing wrapped in `try/except` with proper 400/404 responses.
- All API inputs validated via Pydantic models — no raw `dict` or untyped JSON bodies.
- No raw pymongo collection access bypassing model safety.
- Search query length capped at 200 characters.
- All `$in` queries use server-derived arrays, not raw user input.

#### 5. Input Validation & Injection Prevention

- File uploads validated: magic byte detection, extension whitelist, size limits (main image service).
- Path traversal prevented in image serving (`_safe_resolve()` rejects `..` components).
- Generated filenames use UUIDs, not user input.
- Jinja2 templates use `autoescape=True` — no `|safe` or `{% autoescape false %}` usage.
- Static site export escapes user data with `html.escape()`.
- No `eval()`, `exec()`, `__import__()`, or `compile()` in application code.
- All paginated endpoints enforce maximum limits via `Query(ge=1, le=MAX_PAGE_SIZE)`.

#### 6. Rate Limiting & DoS Prevention

- **Global:** 60 requests/minute per IP (main app).
- **Login:** 30/minute, 200/hour + account lockout after 5 failed attempts (15-minute window).
- **Registration:** 10/minute, 50/hour.
- **Password reset/change:** 5/minute, 20/hour.
- **Search:** 120/minute, 2000/hour with 200-char query limit.
- **Export:** 10/minute, 30/hour.
- **Scan/enrichment:** 20/minute, 100–200/hour.
- **Admin login:** 5/minute.
- **Admin read endpoints:** 30/minute.
- All paginated queries bounded by `MAX_PAGE_SIZE` (200) or `MAX_USER_RESULTSET`.
- Reference data queries bounded by `MAX_REFERENCE_RESULTSET` (5,000).
- File upload sizes bounded: 10 MB images, 25 MB imports.
- Database connection timeouts: serverSelection 5s, connect 10s, socket 30s.

#### 7. Session & Token Security

- JWT tokens use HS256 with minimum 32-character secret key (enforced at startup).
- Tokens include `jti` (UUID), `iat`, `exp` (2-hour), and `sub` claims.
- Dual-layer revocation: per-token blacklist + bulk user invalidation cutoff.
- Revoked token cleanup via background task (hourly).
- Purpose-specific secret derivation (SHA256) for reset/verification tokens prevents type confusion.
- No token values logged anywhere in the codebase.
- HSTS enabled in production: `max-age=63072000` (2 years, via nginx).
- Account lockout after repeated failed logins.

#### 8. Security Headers

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Permitted-Cross-Domain-Policies: none`
- `Permissions-Policy` restricting camera, geolocation, microphone, etc.
- `Content-Security-Policy`: `script-src 'self'` (no unsafe-inline for scripts), PostHog domains whitelisted.
- CORS: empty origin list by default (same-origin only), explicit whitelist when configured.
- Nginx adds `X-Content-Type-Options` and `X-Frame-Options` to static file responses.
- `server_tokens off` hides nginx version.

#### 9. Data Exposure

- `UserResponse` model excludes `hashed_password` and internal fields.
- Admin user listing explicitly constructs safe response dicts.
- Error messages are generic ("Invalid email or password") — no user enumeration.
- API docs (`/docs`, `/redoc`, `/openapi.json`) disabled in production (both main and admin apps).
- No stack traces, database names, or file paths in error responses.
- PostHog public API key properly separated from server-side key.

- Recent security fix (commit `9d7a297`): addressed CVEs (aiohttp, requests, certifi), bounded all queries, disabled API docs in admin panel, paginated admin endpoints, escaped HTML in exports.

#### 11. Infrastructure & Configuration

- Production safety checks at startup: weak secret key blocked, localhost MongoDB warned, HTTPS enforcement checked.
- Database safety check prevents dev environments from connecting to production MongoDB.
- Admin panel defaults to OAT database to prevent accidental production access.
- Nginx: `server_tokens off`, TLS 1.2/1.3 only, strong ciphers (ECDHE+AES-GCM), session tickets disabled, HSTS 2-year max-age.
- Admin panel IP-restricted in nginx; empty allowlist rejected by deploy pipeline.
- Systemd: services run as dedicated `winebox` user with `NoNewPrivileges=true`, `ProtectSystem=strict`, `ProtectHome=true`, `PrivateTmp=true`, bound to `127.0.0.1`.
- All Anthropic API calls have explicit timeouts (60–120 seconds).
- All DigitalOcean API calls have 30-second timeouts.
- No deprecated `datetime.utcnow()` usage anywhere in the codebase.

#### 12. Third-Party Integration Security

- PostHog server-side key in secrets config; client-side key fetched dynamically via API and scoped by CSP.
