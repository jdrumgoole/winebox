### INFO (Best practice recommendations)

**INFO-1: E2E test secret key hardcoded in tasks.py**

- **File:** `tasks.py` (line 283)
- **Value:** `"e2e-test-secret-key-not-for-production-use-1234567890"`
- **Detail:** Clearly labelled test-only value used for isolated E2E test environments. Not used in production. Low risk.
- **Recommendation:** Consider loading from an environment variable for consistency with project conventions.
- **Carried forward from:** 2026-04-26 review (INFO-5).

**INFO-2: Password strength validation is length-only (8 characters minimum)**

- **File:** `winebox/auth/schemas.py` (lines 34–41)
- **Detail:** Registration and password change enforce a minimum of 8 characters but do not require complexity (uppercase, lowercase, digits, symbols). This is acceptable per NIST SP 800-63B guidance (which discourages complexity rules). A client-side password strength meter now provides visual feedback (added in commit `a8665af`).
- **Recommendation:** No action required — current implementation aligns with NIST guidance and UX best practices.
- **Carried forward from:** 2026-04-26 review (INFO-3).

**INFO-3: `datetime.utcnow()` used in legacy migration script**

- **File:** `scripts/migrations/migrate_sqlite_to_mongo.py` (lines 264–466)
- **Detail:** The deprecated `datetime.utcnow()` (timezone-naive) is used in eight places in a one-time SQLite-to-MongoDB migration script. This script has already been executed and is not part of the running application. No production code uses `datetime.utcnow()`.
- **Recommendation:** Low priority. If the migration script is ever updated, switch to `datetime.now(timezone.utc)`.

#### 2. Hardcoded Secrets Scan

- No API keys, connection strings, passwords, private keys, or JWTs found in source code.
- `config/secrets.env.example` contains only placeholder values.
- `.gitignore` properly covers: `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`.
- `git ls-files` confirms no sensitive files tracked (only `config/secrets.env.example`).
- Test fixtures use obvious dummy values (`sk-ant-api-key`, `phc_test_api_key`, `AKIAIOSFODNN7EXAMPLE`).
- GitHub Actions workflows use `${{ secrets.NAME }}` pattern throughout.

#### 3. Authentication & Authorization Audit

- **All 60+ endpoints** handling user data require `RequireAuth` or `RequireAdmin`.
- **All database queries** for user-owned data filter by `owner_id` or `cellar_id`.
- Public endpoints (`/api/reference/*`, `/api/xwines/*`, `/health`, `/api/config/analytics`) serve only static reference data — no user information exposed.
- Admin endpoints use `RequireAdmin` (not just `RequireAuth`).
- Admin self-modification prevented: `_check_not_self()` blocks deactivate, remove-admin, and delete on own account.
- Password changes invalidate all existing tokens via dual mechanism:
  - Per-token blacklist (JTI-based)
  - Bulk `tokens_invalidated_after` cutoff on user document
- Password reset also triggers full token revocation via `on_after_reset_password` callback.
- User registration validates email format (Pydantic `EmailStr`) and password length (8+ chars).
- Constant-time password comparison via Argon2 `verify()` with dummy hash for non-existent users.
- User enumeration prevented: forgot-password returns 202 for both existing and non-existing users.

#### 4. NoSQL Injection & Query Safety

- All regex searches use `re.escape()` before compilation.
- No unsafe MongoDB operators (`$where`, `$expr`, `$accumulator`, `$function`) found.
- All `ObjectId` parsing wrapped in `try/except InvalidId` with proper 400/404 responses.
- All API inputs validated via Pydantic models — no raw `dict` or untyped JSON bodies.
- No raw pymongo collection access bypassing model safety.
- Search query length capped at 200 characters.
- `ast.literal_eval()` used safely (not `eval()`) for grape/vintage list parsing.
- No `eval()`, `exec()`, `__import__()`, `pickle`, or unsafe `yaml.load` in application code.

#### 5. Input Validation & Injection Prevention

- File uploads validated: magic byte detection, extension whitelist (CSV/XLSX for import, image types for labels), size limits (import capped at 25 MB).
- Path traversal prevented in image serving (`_safe_resolve()` rejects `..` and validates canonical path).
- Generated filenames use UUIDs, not user input.
- Jinja2 templates use `autoescape=True` — no `|safe` or `{% autoescape false %}` usage.
- HTML export uses `html.escape()` for user-controlled filter values.
- All paginated endpoints enforce maximum limits via `Query(ge=1, le=MAX_PAGE_SIZE)`.
- Custom field names validated before use in MongoDB update paths.

#### 6. Rate Limiting & DoS Prevention

- **Global:** 60 requests/minute per IP.
- **Login:** 30/minute, 200/hour + account lockout after 5 failed attempts (15-minute window).
- **Registration:** 10/minute, 50/hour.
- **Password reset/change:** 5/minute, 20/hour.
- **Forgot password:** 5/minute, 20/hour.
- **Search:** 120/minute, 2000/hour with 200-char query limit.
- **Export:** 10/minute, 30/hour.
- **Import upload:** 10/minute, 30/hour with 25 MB file limit.
- **Scan/enrichment:** 20/minute, 100–200/hour.
- **Admin login:** 5/minute (stricter than main login).
- **Admin endpoints:** 30/minute.
- All paginated queries bounded by `MAX_USER_RESULTSET` (10,000) and `MAX_REFERENCE_RESULTSET` (5,000).
- MongoDB connection: `serverSelectionTimeoutMS=5000`, `connectTimeoutMS=10000`, `socketTimeoutMS=30000`.
- All Anthropic API calls have explicit timeouts (60–120 seconds).
- nginx `client_max_body_size 10M` for upload protection.

#### 7. Session & Token Security

- JWT tokens use HS256 with minimum 32-character secret key (enforced at startup).
- Tokens include `jti` (UUID), `iat`, `exp`, and `sub` claims.
- 2-hour token expiry (`ACCESS_TOKEN_EXPIRE_MINUTES = 120`).
- Dual-layer revocation: per-token blacklist + bulk user invalidation cutoff.
- Revoked token cleanup via background task (hourly) and MongoDB TTL indexes.
- Purpose-specific secret derivation (SHA256) for reset/verification tokens prevents type confusion.
- No token values logged anywhere in the codebase.
- HSTS enabled in production: `max-age=63072000` (2 years).
- HTTPS enforced via nginx redirect (HTTP → HTTPS for all domains).

#### 8. Security Headers

All security headers present via `SecurityHeadersMiddleware`:

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Permitted-Cross-Domain-Policies: none`
- `Permissions-Policy` restricting camera, geolocation, microphone, etc.
- `Content-Security-Policy`: `script-src 'self'` (no unsafe-inline for scripts), PostHog and Google Fonts whitelisted, `frame-ancestors 'none'`, `form-action 'self'`, `object-src 'none'`.
- CORS: empty origin list by default (same-origin only), explicit whitelist when configured.

Nginx adds `X-Content-Type-Options` and `X-Frame-Options` to all static file locations (fixed since 2026-04-26 review). `server_tokens off` hides nginx version.

#### 9. Data Exposure

- `UserResponse` model excludes `hashed_password` and internal fields.
- Error messages are generic ("Incorrect email or password") — no user enumeration.
- API docs (`/docs`, `/redoc`, `/openapi.json`) disabled in production for both main app and admin panel.
- No stack traces, database names, or file paths in error responses.
- Admin `/api/info` intentionally does NOT expose MongoDB hostname.
- PostHog public API key properly separated from server-side key; public key exposure is by design and safe.
- Login attempt logs record IP and email only — no passwords or tokens.

#### 11. Infrastructure & Configuration

- Production safety checks at startup: weak secret key blocked, localhost MongoDB warned, HTTPS enforcement checked, debug mode validation.
- Database safety check prevents dev environments from connecting to production MongoDB.
- Admin panel defaults to `winebox_oat` database to prevent accidental production access during development.
- Nginx: `server_tokens off`, TLS 1.2/1.3 only, strong ciphers (ECDHE-ECDSA/RSA with AES-GCM), session tickets disabled, HSTS 2-year max-age.
- Admin panel IP-restricted at nginx layer for both OAT and production (allowlist in `deploy/winebox-admin.toml`).
- Admin allowlist non-empty check: deploy renderer refuses to ship an open admin panel.
- `shlex.quote()` applied consistently to all invoke task shell parameters (fixed since prior review).

#### 12. Third-Party Integration Security

- Anthropic API key loaded from environment variable (`WINEBOX_ANTHROPIC_API_KEY`), never hardcoded.
- PostHog API key loaded from environment variable (`WINEBOX_POSTHOG_API_KEY`); public key safely exposed to client-side (standard PostHog pattern).
- All Anthropic API calls have explicit timeouts (60–120s).
- No webhook endpoints found — no signature validation needed.
- No external API calls without timeout configuration.

#### 13. Admin Panel Security (New)

- All admin API endpoints require `RequireAdmin` dependency.
- Admin login endpoint rate-limited at 5/minute (stricter than main app).
- Admin login rejects non-superuser accounts with 403.
- Self-modification guards: admins cannot deactivate, remove admin from, or delete their own account.
- Admin panel runs as separate process on port 8001, behind nginx IP allowlist.
- Security headers middleware shared with main app.
- API docs disabled in production.
- Separate access/error logs for admin traffic.
- User deletion cascades properly: wines, transactions, import batches, and raw upload rows all cleaned up with `owner_id` filtering.
