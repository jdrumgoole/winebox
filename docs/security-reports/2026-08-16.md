### :orange_circle: WARNING

**WARN-1 (NEW): python-multipart 0.0.28 — CVE-2026-53539 (DoS), CVE-2026-53537, CVE-2026-53538 (parameter smuggling)**

- **File:** `uv.lock` — python-multipart pinned at 0.0.28; fixes are in 0.0.30
- **CVEs:**
  - **CVE-2026-53539** (High) — Quadratic-time DoS via semicolon-separated querystring parsing in `QuerystringParser`
  - **CVE-2026-53537 / CVE-2026-53538** (Low, CVSS 3.7) — Content-Disposition and querystring parameter smuggling
- **Impact:** Form endpoints require `RequireAuth` and nginx caps payloads at 10 MB, limiting exploitation. However, the DoS CVE is rated High and affects a direct dependency of FastAPI.
- **Recommendation:** Bump `python-multipart>=0.0.30` in `pyproject.toml` and re-lock.
- **Previous status:** Was INFO-26 in 2026-08-06 report. Upgraded to WARNING given accumulation of three CVEs against the same version and High severity of CVE-2026-53539.

**WARN-2 (NEW): aiohttp 3.13.5 — CVE-2026-69243 (HTTP request smuggling)**

- **File:** `uv.lock` — aiohttp pinned at 3.13.5; fix is in 3.14.2
- **CVE:** CVE-2026-69243 (Medium, CVSS 6.3) — HTTP request smuggling via WebSocket upgrade in the parser.
- **Impact:** WineBox uses aiohttp only transitively (via `aioboto3` as an S3 client), not as an HTTP/WebSocket server. Server-side exploitability is likely low in this deployment, but the dependency is unpatched against a Medium-severity request-smuggling CVE.
- **Recommendation:** Bump `aiohttp>=3.14.2` in `pyproject.toml` and re-lock.
- **Previous status:** New finding not in prior reports. The prior aiohttp CVEs (INFO-19, INFO-21, INFO-36) were all against 3.13.5 but for different vulnerabilities.

**WARN-3 (UPGRADED): Starlette 0.50.0 — CVE-2026-48710 (BadHost authentication bypass)**

- **File:** `uv.lock` — starlette pinned at 0.50.0; fix is in starlette 1.0.1+
- **CVE:** CVE-2026-48710 — Starlette reconstructs `request.url` from the HTTP Host header without validation. A malformed Host header containing `/`, `?`, or `#` can desync `request.url.path` from the ASGI-routed path, bypassing path-based security checks.
- **Impact assessment change:** While WineBox uses dependency-injection auth (not path-based middleware), making direct exploitation unlikely, this CVE is well-documented and actively discussed in the FastAPI community. The project has no `TrustedHostMiddleware` or Host-header validation. Starlette 0.50.0 is now over a year behind the latest (1.6.0). The combination of an auth-bypass CVE, no compensating Host-header control, and growing version gap warrants WARNING rather than INFO.
- **Upgrade path:** FastAPI 0.128.1 constrains starlette to `<0.51.0`. Upgrading requires FastAPI >=0.136.0 + Starlette >=1.0.1 together. This is the largest upgrade in the backlog.
- **Recommendation:** Plan a coordinated FastAPI + Starlette upgrade. In the interim, add `TrustedHostMiddleware` with an explicit host allowlist as defence-in-depth.
- **Previous status:** Was INFO-8 in 2026-08-06 report. Upgraded to WARNING.

**INFO-57 (NEW): CSV/XLSX export — no formula-injection sanitisation**

- **Files:** `winebox/services/export_service/wines.py`, `winebox/services/export_service/transactions.py`, `winebox/services/export_service/xwines.py`
- **Detail:** User-controlled free text (wine name, winery, provenance, custom fields) is written directly into CSV/XLSX cells with no leading-character neutralisation (`=`, `+`, `-`, `@`). A wine name like `=cmd|'/c calc'!A1` would round-trip into an exported spreadsheet and could execute if opened in Excel/Sheets with legacy settings.
- **Impact:** Low — requires a user to (1) have a maliciously-named wine in their cellar, (2) export to CSV/XLSX, (3) open in a spreadsheet app with legacy DDE/formula execution enabled.
- **Recommendation:** Prefix cell values starting with `=`, `+`, `-`, `@` with a single quote (`'`) or a leading tab in the CSV/XLSX writers.
- **Status:** New finding.

### :green_circle: CLEAN (Passed review)

- **Hardcoded secrets:** No real API keys, connection strings, private keys, or JWTs found in tracked code. `.gitignore` correctly covers `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`. No sensitive files in git history.
- **Authentication & authorization:** Every endpoint handling user data requires `RequireAuth` or `RequireAdmin`. All database queries for user-owned data filter by `owner_id`. Admin endpoints consistently use `RequireAdmin`. Password change/reset invalidates all existing tokens via `tokens_invalidated_after`. Registration validates email format via `EmailStr`. Constant-time password comparison via Argon2id throughout.
- **NoSQL injection:** No dangerous operators (`$where`, `$expr`, `$accumulator`, `$function`) anywhere. All user-supplied regex wrapped in `re.escape()`. All `ObjectId()` parsing wrapped in `try/except`. No unbounded `$in` from user arrays. No raw pymongo access bypassing model safety.
- **Input validation:** All API inputs use Pydantic models. No raw `dict` or untyped JSON bodies. File uploads validate type, size, and content (magic-byte sniffing). Jinja2 templates use `autoescape=True`. Filenames sanitised against path traversal (`_safe_resolve()`). Import column mapping gated against a hardcoded field whitelist.
- **Token security:** HS256 with purpose-derived HMAC keys, `jti` for per-token revocation, bulk revocation via `tokens_invalidated_after`, no token leakage in logs or error messages, HTTPS enforced in production.
- **Security headers:** `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, and a real CSP with no `unsafe-inline`. HSTS in production. `server_tokens off` in nginx. TLS 1.2/1.3 only with modern cipher suite.
- **CORS:** Defaults to empty allow-list (same-origin only). No wildcard `*`.
- **Data exposure:** `hashed_password` never serialised to responses. Error messages don't leak internal details. Debug mode disabled by default with startup validation. No sensitive data logged.
- **Git history:** No security-related code changes in last 30 commits. No accidentally committed secrets.
- **Infrastructure:** Secure defaults (`debug=False`, `enforce_https=True` in production). Production database safety guard prevents accidental production DB access. Hardened systemd unit. Admin panel IP-restricted at nginx. MongoDB connection with bounded timeouts.
- **Third-party integrations:** Anthropic API key loaded from environment with explicit timeouts on all calls. PostHog public project key correctly exposed (write-only, not a secret). No webhook endpoints. No external API calls without timeouts.
