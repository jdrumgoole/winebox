### :orange_circle: WARNING

**WARNING-1: python-multipart CVE-2026-53539 — Quadratic complexity DoS in QuerystringParser**

- **File:** `uv.lock` — python-multipart pinned at 0.0.28; patch is in python-multipart 0.0.30
- **CVE:** CVE-2026-53539 — The `QuerystringParser` in python-multipart uses an O(B²) algorithm for field separator location. A single crafted 1 MB POST body can block a worker for seconds. This directly affects FastAPI/Starlette `request.form()` processing.
- **Impact on WineBox:** Moderate. WineBox has publicly accessible form-accepting endpoints via regstack (login at 30/min rate limit, register at 10/min, password reset at 5/min). An unauthenticated attacker could craft bodies that stall workers, degrading service availability. Nginx's `client_max_body_size 10M` constrains payload size, and rate limits reduce the attack surface, but do not fully prevent exploitation.
- **Upgrade path:** Bump python-multipart to `>=0.0.30` in `pyproject.toml`. No breaking changes expected.
- **Recommendation:** Upgrade python-multipart before the next deployment. This is a remotely exploitable DoS on publicly accessible endpoints.
- **Status:** NEW — not present in any previous review.

**INFO-8: Starlette 0.50.0 is affected by CVE-2026-48710 (BadHost) — no practical impact on WineBox**

- **File:** `uv.lock` — starlette pinned at 0.50.0; patch is in starlette 1.0.1
- **CVE:** CVE-2026-48710 — Starlette reconstructs `request.url` from the HTTP Host header without validation. A malformed Host header can cause `request.url.path` to differ from the path the ASGI server actually routed, allowing middleware that makes security decisions based on `request.url.path` to be bypassed.
- **Impact on WineBox: None.** WineBox does not use path-based auth middleware. Authentication is enforced via FastAPI dependency injection (`RequireAuth`, `RequireAdmin`) on individual route handlers, which operate on the ASGI scope path (the correctly-routed path), not `request.url.path`. The only `request.url` usage is `request.url.query` in two redirect handlers (`main.py:265,270`), which poses no auth bypass risk. Additionally, nginx normalises Host headers in production, providing a second layer of protection.
- **Upgrade path:** FastAPI 0.128.1 constrains starlette to `<0.51.0,>=0.40.0`. Upgrading to starlette 1.0.1 requires upgrading FastAPI to >=0.136.0 (latest 0.137.0).
- **Recommendation:** Plan a coordinated FastAPI + Starlette upgrade in a future maintenance cycle. The vulnerability is not exploitable in WineBox's current architecture, but upgrading removes the theoretical risk and keeps the stack current.
- **Status:** Carried forward from 2026-05-27 review.

**INFO-13: Admin deactivation does not bump `tokens_invalidated_after`**

**INFO-14: Deprecated `X-XSS-Protection` header set to `1; mode=block`**

- **File:** `winebox/main.py:46`
- **Detail:** The `X-XSS-Protection` header is deprecated and has been removed from modern browsers. Setting it to `1; mode=block` could theoretically introduce XSS vulnerabilities in older browsers by enabling the browser's buggy XSS auditor. Modern security guidance recommends setting it to `0` or removing it entirely. The strong Content-Security-Policy already provides comprehensive XSS protection.
- **Impact:** Negligible — the strong CSP is the primary XSS defence.
- **Recommendation:** Change to `X-XSS-Protection: 0` or remove the header.
- **Status:** Carried forward from 2026-05-29 review.

**INFO-15: Admin logout uses `RequireAuth` instead of `RequireAdmin`**

#### 2. Hardcoded Secrets Scan

- **No real API keys, production credentials, or private keys committed to the repository.**
- All secrets loaded from environment variables or `secrets.env`.
- `.gitignore` properly covers `.env`, `.env.local`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`.
- Three scripts hardcode `"TestPassword123!"` for ephemeral local test users — low risk (see INFO-3).
- Connection string logging is properly masked in deploy tooling (`deploy/common.py`).

#### 3. Authentication & Authorization Audit

**115 endpoints audited** (89 main app + 15 admin panel + ~11 regstack-managed auth routes):

- **All user-data endpoints** require `RequireAuth` — no exceptions found.
- **All admin endpoints** require `RequireAdmin` — no exceptions found.
- **Public endpoints** are limited to static files, health checks, reference data, X-Wines dataset, and auth flows — all correct.
- **Password hashing:** Argon2id via regstack/pwdlib with constant-time verification.
- **Password change/reset:** Atomically bumps `tokens_invalidated_after`, invalidating all existing tokens.
- **Account lockout:** 5 failures in 15 minutes triggers lockout via regstack.
- **Anti-enumeration:** Login returns generic messages; forgot-password always returns 202.

#### 4. NoSQL Injection & Query Safety

- **No injection vulnerabilities found** across all MongoDB queries in the codebase.
- All `re.compile()` calls with user input use `re.escape()` — verified across all routers and services.
- All `ObjectId()` parsing from user input is wrapped in `try/except` — verified across 13+ files.
- No `$where`, `$function`, or `$accumulator` operators used anywhere in production code.
- All aggregation pipelines built from server-side data only — no user input in pipeline stages.
- Pydantic type enforcement prevents MongoDB operator injection via query parameters.

#### 5. Input Validation

- All API inputs use Pydantic models or typed `Query()`/`Form()` parameters with constraints.
- No raw `request.json()`, `request.body()`, or `request.form()` calls bypass validation.
- Search queries limited to 200 characters. File uploads validated by magic bytes. Pagination capped at `MAX_PAGE_SIZE=200`.

#### 6. Rate Limiting

Comprehensive per-endpoint rate limits are in place:
- Auth: login 30/min, register 10/min, password reset 5/min
- Admin login: 5/min
- Search: 120/min, 2000/hour
- Scan (OCR): 20/min, 200/hour
- Export: 10/min, 30/hour
- Import: 10/min, 30/hour
- Price capture: 30/min, 200/hour
- Global default: 60/min

#### 7. Session & Token Security

- **Algorithm:** HS256 with per-purpose key derivation (session, password_reset, email_change, etc.).
- **TTL:** 2-hour session tokens.
- **JTI:** Every token includes a `jti` claim; per-token revocation via MongoDB blacklist with TTL cleanup.
- **Bulk revocation:** Password change, password reset, and email change all atomically bump `tokens_invalidated_after`.
- **Error messages:** Generic "Invalid or expired token." — no internal detail leakage.
- **Secret key:** Production startup blocks if missing or < 32 characters.

#### 8. Security Headers & CORS

- `X-Content-Type-Options: nosniff` — set on all responses.
- `X-Frame-Options: DENY` — set on all responses.
- `Content-Security-Policy` — tight policy, no `unsafe-inline` for scripts.
- `Strict-Transport-Security` — set in production (1 year, includeSubDomains, preload).
