### WARNING (Address within 1 week)

**WARN-1: Hardcoded passwords in utility scripts**

- **Files:** `scripts/screenshot_import_tab_order.py:53`, `scripts/check_url_hashes.py:39`
- **Detail:** Both scripts hardcode `password = "TestPassword123!"` for creating ephemeral test users. The project's CLAUDE.md explicitly states: "NEVER hardcode credentials, connection strings, passwords, API keys, or tokens in source code — not in scripts, tests, config files, or anywhere that gets committed to git."
- **Recommendation:** Read the password from an environment variable or generate a random one at runtime. Fail with a clear error if the variable is not set.

**WARN-2: `fastapi-users` minimum pin allows vulnerable versions (CVE-2025-68481)**

- **File:** `pyproject.toml` (line: `"fastapi-users>=14.0.0"`)
- **Detail:** CVE-2025-68481 (CVSS 5.9) is a 1-click account takeover via OAuth CSRF, fixed in fastapi-users 15.0.2. The locked version (15.0.4) is already patched, but the floor constraint `>=14.0.0` would allow `uv lock` to resolve a vulnerable version in a fresh environment. WineBox does not currently use OAuth login (password-only), so exploitability is low — but the pin should still be raised defensively.
- **Recommendation:** Bump the minimum to `fastapi-users>=15.0.2` in `pyproject.toml`.

**WARN-3: Unauthenticated reference/X-Wines endpoints lack per-route rate limits**

- **Files:** `winebox/routers/reference.py` (all endpoints), `winebox/routers/xwines.py` (lines 576, 613, 632, 640)
- **Detail:** Approximately 15 unauthenticated endpoints serving reference data (wine types, grape varieties, regions, classifications, X-Wines detail/stats/types/countries) rely solely on the global `60/minute` rate limit. An attacker can issue 60 requests/min to *each* of these endpoints from a single IP, multiplying effective throughput.
- **Recommendation:** Add per-route rate limits (e.g., `120/minute` collective) or group them under a shared rate-limit key.

**WARN-4: X-Wines regex fallback loads up to 15,000 documents into memory**

- **File:** `winebox/routers/xwines.py:397-399`
- **Detail:** When Atlas Search is unavailable, three separate regex queries each load up to `MAX_REFERENCE_RESULTSET` (5,000) documents, then deduplicate in Python. In the worst case this is 15,000 full Wine documents in memory before the `skip+limit` slice at line 413. Combined with the global-only rate limit (WARN-3), this is a potential memory exhaustion vector.
- **Recommendation:** Add a tighter per-route rate limit on the search endpoint and/or reduce the regex fallback result cap.

### INFO (Best practice recommendations)

**INFO-1: No `maxTimeMS` query timeouts on individual MongoDB operations**

- **File:** `winebox/db/document.py`
- **Detail:** Connection-level timeouts are configured (server selection 5s, connect 10s, socket 30s), but individual query operations do not pass `max_time_ms` to the driver. A single slow query could hold a worker for up to 30 seconds.
- **Recommendation:** Consider adding `max_time_ms` to heavy aggregation pipelines as defence-in-depth.

**INFO-2: `skip` parameters lack upper bounds in most endpoints**

- **Files:** `winebox/routers/cellar.py:25`, `search.py:46`, `met.py:17`, `wines/crud.py:23`, `transactions.py:32`, `price_tracker.py:259,332`
- **Detail:** Only the X-Wines search endpoint caps `skip` at `le=10000`. All other endpoints allow arbitrarily large `skip` values, causing MongoDB to scan and discard documents. Mitigated by owner_id scoping (small per-user data sets).
- **Recommendation:** Add `le=10000` to `skip` parameters across all endpoints.

**INFO-3: Unbounded `to_list()` on bottle event history**

- **File:** `winebox/routers/bottles.py:188-190`
- **Detail:** `CellarEvent.find(...).sort(...).to_list()` has no `length` parameter. A bottle with many events could return an arbitrarily large result set.
- **Recommendation:** Add `length=MAX_PAGE_SIZE` or paginate event history.

**INFO-4: Price capture photo uses user-declared extension without allowlist**

- **File:** `winebox/routers/price_tracker.py:206-209`
- **Detail:** The stored filename uses the user-declared file extension without validating against an allowlist (unlike the image_storage service which uses magic bytes). Mitigated by the MIME type check at line 192 restricting to image content types.
- **Recommendation:** Validate the extension against `{jpg, jpeg, png, webp, heic}` for consistency with image_storage.

**INFO-5: Exception details from JSONDecodeError forwarded to clients**

- **Files:** `winebox/routers/wines/record.py:149-152`, `winebox/routers/wines/met.py:154-158`
- **Detail:** `json.JSONDecodeError` message is included verbatim in the HTTP error response via `f"Invalid custom_fields JSON: {e}"`. This could reveal parser internals.
- **Recommendation:** Use a static message like `"Invalid custom_fields JSON format"`.

**INFO-6: Admin logout uses `RequireAuth` instead of `RequireAdmin`**

- **File:** `winebox/admin/routers/auth.py:48`
- **Detail:** The admin panel logout endpoint accepts any authenticated user, not just admins. Risk is negligible since the admin panel is IP-restricted and the endpoint only revokes the caller's own token.
- **Recommendation:** Change to `RequireAdmin` for consistency.

**INFO-7: Missing OCSP stapling in nginx configs**

- **Files:** `deploy/nginx-winebox.conf`, `deploy/nginx-winebox-oat.conf`
- **Detail:** Neither config includes `ssl_stapling on;` or `ssl_stapling_resolver`. OCSP stapling improves TLS handshake performance and prevents some downgrade scenarios.
- **Recommendation:** Add `ssl_stapling on; ssl_stapling_verify on; ssl_stapling_resolver 1.1.1.1 8.8.8.8;` to the nginx configs.

**INFO-8: Anthropic SDK could be upgraded to 0.97.0**

- **File:** `pyproject.toml` (pinned `>=0.96.0`, locked `0.96.0`)
- **Detail:** The latest Anthropic SDK is 0.97.0. The locked version 0.96.0 includes fixes for CVE-2026-34450 and CVE-2026-34452 (both fixed in 0.87.0+), but staying current is good practice.
- **Recommendation:** Run `uv lock --upgrade-package anthropic` to pick up 0.97.0.

**INFO-9: SSE streams hold HTTP connections for up to 5 minutes**

- **Files:** `winebox/routers/wines/enrichment.py:36-37` (600 polls x 0.5s), `winebox/routers/demo.py:91` (300 polls x 0.5s)
- **Detail:** Server-Sent Event streams have finite but long timeouts. Could be used for connection exhaustion if many are opened simultaneously.
- **Recommendation:** These are already authenticated and bounded. Consider a lower poll count if connection limits become a concern.

**INFO-10: Price filter loads up to 50,000 document IDs into memory**

- **File:** `winebox/routers/xwines.py:133`
- **Detail:** `cursor.to_list(length=50000)` loads up to 50,000 IDs into a Python set for price-filtered X-Wines searches.
- **Recommendation:** Consider using a MongoDB `$lookup` or `$in` with a smaller batch size if memory becomes a concern.

### CLEAN (Passed review)

- **JWT/Token Security:** HS256 algorithm with algorithm list enforcement, 2-hour expiry, jti claim for per-token revocation, bulk invalidation via `tokens_invalidated_after` timestamp. Token blacklist with TTL cleanup and MongoDB TTL index. Secret key loaded from environment, auto-generated with warning in dev, startup blocked if missing/weak in production.
- **Password Security:** Argon2 hashing via pwdlib. Constant-time comparison with dummy verification for non-existent users. Password change invalidates all tokens via `revoke_all_user_tokens()`. Account lockout after 5 failed attempts in 15 minutes.
- **Authentication & Authorization:** Every endpoint handling user data requires `RequireAuth` or `RequireAdmin`. All database queries for user data filter by `owner_id`. Admin endpoints use `RequireAdmin` with self-mutation protection. fastapi-users `get_users_router()` (which would allow `is_superuser` self-elevation) is not mounted.
- **Input Validation:** All API inputs use Pydantic models. All search inputs have `max_length` constraints. All regex uses `re.escape()`. All ObjectId parsing wrapped in try/except. File uploads validate type, size, and content via magic bytes.
- **NoSQL Injection:** No dangerous operators (`$where`, `$expr`, `$accumulator`). No user input interpolated into query filters. All `$in` queries use bounded arrays.
- **Secrets Management:** No hardcoded production secrets in source code. `.gitignore` covers `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`. `secrets.env` deployed with chmod 600.
- **Security Headers:** X-Content-Type-Options, X-Frame-Options (DENY), X-XSS-Protection, Referrer-Policy, Permissions-Policy, CSP (no `unsafe-inline` for scripts). HSTS with preload in production.
- **CORS:** Defaults to empty origins list (same-origin only). Admin panel has no CORS middleware at all.
- **HTTPS:** HTTP-to-HTTPS 301 redirects in nginx. TLS 1.2/1.3 only, ECDHE+GCM ciphers, session tickets off.
- **Data Exposure:** No hashed passwords in API responses. owner_id stripped from exports. Error messages are generic. No sensitive data in logs.
- **Debug Mode:** Defaults to false, blocked in production. API docs disabled in non-debug mode.
- **Infrastructure:** Production database safety check prevents non-production hosts from connecting to production. Systemd services run as dedicated user with `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`. Nginx IP-restricted admin panel with non-empty allowlist enforcement.
- **Dependencies:** All known CVEs patched (Pillow, PyJWT, cryptography, aiohttp, requests, python-multipart). No yanked or compromised packages.
- **Datetime Handling:** No deprecated `datetime.utcnow()` usage found.
- **Git History:** No secrets committed in recent history. Last 30 commits include a security fix adoption (commit 9d7a297).
