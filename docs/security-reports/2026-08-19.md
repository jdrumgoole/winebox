6. Rate limiting & DoS prevention

### :orange_circle: WARNING

**WARNING-1: Global default rate limit is dead configuration — `SlowAPIMiddleware` never registered**

- **Files:**
  - `winebox/main.py:30-34,208-209` — `Limiter(default_limits=["60/minute"])` created, `app.state.limiter` set, exception handler added, but `SlowAPIMiddleware` never added via `app.add_middleware()`
  - `winebox/admin/main.py:58,74-75` — Same pattern: `Limiter` created, state set, no middleware
- **Detail:** In slowapi, `default_limits` are only enforced when `SlowAPIMiddleware.dispatch()` calls `_check_request_limit(..., in_middleware=True)`. Without the middleware, the `default_limits=["60/minute"]` parameter is inert — it is configured but never checked. Only endpoints with explicit `@limiter.limit(...)` decorators are rate-limited.
- **Affected endpoints (non-exhaustive):** All wine CRUD (`wines/crud.py`), cellar operations (`cellar.py`), case/bottle management (`cases.py`, `bottles.py`), transaction listing (`transactions.py`), reference data (`reference.py` — 13 public/unauthenticated endpoints), image serving (`images.py`), and most import processing endpoints (`import_router.py` — `/process`, `/process-stream`, `/rows`). Admin mutation endpoints (`admin.py:197-330` — `create_user`, `activate_user`, `deactivate_user`, `make_admin`, `remove_admin`, `verify_user`, `delete_user`) also have no rate limits, though the admin panel is IP-restricted at nginx.
- **What still works:** Per-route `@limiter.limit(...)` decorators on auth endpoints (login: 30/min, register: 10/min, password reset: 5/min), search (120/min), scan/enrichment (20/min), import upload, export, and demo install are all independently enforced and unaffected.
- **Impact:** An authenticated user could hammer unrated endpoints (CRUD, import processing, case/bottle writes) without throttling. Import processing endpoints can trigger paid Anthropic API calls per row, potentially running up costs. Reference data endpoints are public and unauthenticated, making them the easiest DoS vector. The admin panel is mitigated by IP restriction at nginx.
- **Recommendation:** Add `from slowapi.middleware import SlowAPIMiddleware` and `app.add_middleware(SlowAPIMiddleware)` to both `winebox/main.py` and `winebox/admin/main.py`. Verify the default limit engages on an undecorated route. Additionally, add explicit `@limiter.limit(...)` decorators to admin mutation endpoints for defence in depth (CLAUDE.md requires "Admin endpoints should have stricter rate limits").
- **Status:** New finding — 2026-08-19. Missed in all previous reviews (incorrectly reported as CLEAN since 2026-04-03).

**INFO-8: Starlette 0.50.0 is affected by CVE-2026-48710 (BadHost) — no practical impact on WineBox**

- **File:** `uv.lock` — starlette pinned at 0.50.0; patch is in starlette 1.0.1
- **CVE:** CVE-2026-48710 — Starlette reconstructs `request.url` from the HTTP Host header without validation. A malformed Host header can cause `request.url.path` to differ from the path the ASGI server actually routed, allowing middleware that makes security decisions based on `request.url.path` to be bypassed.
- **Impact on WineBox: None.** WineBox does not use path-based auth middleware. Authentication is enforced via FastAPI dependency injection (`RequireAuth`, `RequireAdmin`) on individual route handlers, which operate on the ASGI scope path (the correctly-routed path), not `request.url.path`. Additionally, nginx normalises Host headers in production.
- **Upgrade path:** FastAPI 0.128.1 constrains starlette to `<0.51.0,>=0.40.0`. Upgrading to starlette >=1.0.1 requires upgrading FastAPI to >=0.136.0. See also INFO-35 for additional Starlette CVEs.
- **Recommendation:** Plan a coordinated FastAPI + Starlette upgrade in a future maintenance cycle.
- **Status:** Carried forward from 2026-05-27 review.

**INFO-13: Admin deactivation does not bump `tokens_invalidated_after`**

- **File:** `winebox/admin/routers/admin.py:265-272`
- **Detail:** When an admin deactivates a user, the endpoint sets `is_active = False` but does not bump `tokens_invalidated_after`. This is not a bypass — regstack's auth dependency checks `user.is_active` on every authenticated request (via `_fetch_winebox_user` at `winebox/services/auth.py:72`) and regstack also checks `is_payload_bulk_revoked(payload, user.tokens_invalidated_after)` at `regstack/auth/dependencies.py:180`, so the deactivated user is effectively blocked immediately on their next request. - **Impact:** None in current architecture — `is_active` check provides immediate blocking.
- **Recommendation:** Consider setting `tokens_invalidated_after = now` alongside `is_active = False` for defence-in-depth.
- **Status:** Carried forward from 2026-05-29 review.
