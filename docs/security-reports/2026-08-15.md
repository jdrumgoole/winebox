### :orange_circle: WARNING

**WAR-1: `SlowAPIMiddleware` not added — `default_limits` silently unenforced on undecorated routes**

- **File:** `winebox/main.py:30-34`
- **Detail:** The `Limiter` is constructed with `default_limits=["60/minute"]` (line 32) and wired to `app.state.limiter` (line 228) with the `RateLimitExceeded` exception handler registered (line 229). However, `SlowAPIMiddleware` is never added via `app.add_middleware()`. In slowapi, `default_limits` are only applied to undecorated routes via the middleware's `dispatch()` method, which calls `_check_request_limit(request, handler, in_middleware=True)`. Without the middleware, routes that use the `@limiter.limit()` decorator work correctly (the decorator calls `_check_request_limit` directly), but routes without explicit decorators receive **zero rate limiting** — not the documented 60/minute.
- **Affected endpoints (no rate limiting at all):**
  - `winebox/routers/reference.py` — all 13 endpoints (public, no auth)
  - `winebox/routers/xwines.py` — `/wines/{id}`, `/stats`, `/types`, `/countries` (public, no auth)
  - `winebox/routers/cellar.py` — all endpoints (authenticated)
  - `winebox/routers/bottles.py` — all endpoints (authenticated)
  - `winebox/routers/cases.py` — all endpoints (authenticated)
  - `winebox/routers/transactions.py` — all endpoints (authenticated)
  - `winebox/routers/met.py` — all endpoints (authenticated)
  - `winebox/routers/wines/crud.py` — all endpoints (authenticated)
  - `winebox/routers/wines/checkout.py` — all endpoints (authenticated)
  - `winebox/routers/wines/add_to_cellar.py` — all endpoints (authenticated)
  - `winebox/routers/wines/grapes.py` — all endpoints (authenticated)
  - `winebox/routers/wines/scores.py` — all endpoints (authenticated)
  - `winebox/routers/wines/record.py` — all endpoints (authenticated)
  - `winebox/routers/wines/met.py` — all endpoints (authenticated)
  - `winebox/routers/import_router.py` — `/upload-parsed`, `/{batch_id}/rows`, `/{batch_id}/mapping`, `/{batch_id}/process`, `/{batch_id}/process-stream`, `/{batch_id}/remap`
  - `winebox/routers/images.py` — all endpoints (authenticated)
- **Endpoints correctly protected (explicit `@limiter.limit()` decorator):** login, register, password reset/change, search, X-Wines search, export, scan, enrichment, price capture, demo, admin routes.
- **Impact:** Public endpoints (`reference.py`, some `xwines.py`) can be hammered without throttling. Authenticated endpoints without per-route limits have no rate limiting beyond what nginx provides. The `default_limits=["60/minute"]` in the code creates a false sense of security. Previous INFO findings (INFO-42, INFO-12) that cited "the global 60/minute rate limit provides baseline protection" were incorrect — that protection never applies to undecorated routes.
- **Same gap exists in admin app:** `winebox/admin/main.py:58` creates a `Limiter` with no `default_limits` and no middleware. All admin routes have explicit decorators so the practical impact there is nil, but the middleware should be added for defence-in-depth.
- **Fix:** Add `from slowapi.middleware import SlowAPIMiddleware` and `app.add_middleware(SlowAPIMiddleware)` in both `winebox/main.py` and `winebox/admin/main.py`, after `app.state.limiter` is set.
- **Status:** New finding — 2026-08-15.

**WAR-2: Three regstack account endpoints have no rate limit configured — password brute-force via stolen token**

- **File:** `winebox/auth/regstack_setup.py:45-53`
- **Detail:** The `_RATE_LIMITS` dict configures per-route rate limits for 7 regstack routes (login, register, forgot-password, reset-password, verify, resend-verification, change-password) but omits three account management endpoints:
  - `change_email_rate_limit` — `POST /api/auth/change-email` (re-verifies current password)
  - `confirm_email_change_rate_limit` — `POST /api/auth/confirm-email-change`
  - `delete_account_rate_limit` — `DELETE /api/auth/account` (re-verifies current password)
  Since these config fields default to `None`, regstack's `collect_route_limits()` skips them — no `@limiter.limit()` decorator is applied. Combined with WAR-1 (missing `SlowAPIMiddleware`), these endpoints have **zero rate limiting**.
- **Impact:** The `change-email` and `delete-account` endpoints both re-verify the user's current password inline (`regstack/routers/account.py:114-129,208-223`). Unlike `/login`, which is protected by both rate limiting (30/minute) and `LockoutService` (lockout after 5 failures), these endpoints have neither. An attacker holding a stolen bearer token could brute-force the account password through either endpoint with no throttling and no lockout.
- **Fix:** Add `change_email_rate_limit`, `confirm_email_change_rate_limit`, and `delete_account_rate_limit` entries to `_RATE_LIMITS` in `winebox/auth/regstack_setup.py`, matching the `change_password_rate_limit` values (`"5/minute;20/hour"`).
- **Status:** New finding — 2026-08-15.

**INFO-8: Starlette 0.50.0 is affected by CVE-2026-48710 (BadHost) — no practical impact on WineBox**

- **File:** `uv.lock` — starlette pinned at 0.50.0; patch is in starlette 1.0.1
- **CVE:** CVE-2026-48710 — Starlette reconstructs `request.url` from the HTTP Host header without validation. A malformed Host header can cause `request.url.path` to differ from the path the ASGI server actually routed, allowing middleware that makes security decisions based on `request.url.path` to be bypassed.
- **Impact on WineBox: None.** WineBox does not use path-based auth middleware. Authentication is enforced via FastAPI dependency injection (`RequireAuth`, `RequireAdmin`) on individual route handlers, which operate on the ASGI scope path (the correctly-routed path), not `request.url.path`. Additionally, nginx normalises Host headers in production.
- **Upgrade path:** FastAPI 0.128.1 constrains starlette to `<0.51.0,>=0.40.0`. Upgrading to starlette >=1.0.1 requires upgrading FastAPI to >=0.136.0. See also INFO-35 for additional Starlette CVEs.
- **Recommendation:** Plan a coordinated FastAPI + Starlette upgrade in a future maintenance cycle.
- **Status:** Carried forward from 2026-05-27 review.
