# WineBox Security Review — 2026-04-14

## :red_circle: CRITICAL (Immediate action required)

### 1. `python-jose` is abandoned (supply chain risk)
- **Package:** `python-jose` 3.5.0 (confirmed in `uv.lock`)
- **Issue:** No releases since 2021. FastAPI documentation recommends PyJWT. An
  abandoned cryptographic library will not receive patches for future
  vulnerabilities. `pyjwt` 2.11.0 is already resolved in the lock file as a
  transitive dependency — a straight swap is feasible.
- **Recommendation:** Replace `python-jose[cryptography]` with `PyJWT[crypto]`.
- **Status:** Unchanged since 2026-04-06. Now 8 days open.

### 2. `anthropic` SDK has 2 unpatched CVEs (below 0.87.0)
- **Package:** `anthropic` 0.77.1 (confirmed in `uv.lock`)
- **CVE-2026-34450:** Insecure default file permissions (0o666) in local
  filesystem memory tool.
- **CVE-2026-34452:** TOCTOU race in memory tool path validation allowing
  symlink-based sandbox escape.
- **Recommendation:** Bump `anthropic>=0.87.0` in `pyproject.toml` and refresh
  `uv.lock`.
- **Status:** Unchanged since 2026-04-06. Now 8 days open.

## :orange_circle: WARNING (Address within 1 week)

### 3. Price tracker leaks other users' PII (new finding)
- **Location:** `winebox/routers/price_tracker.py:54-84` (`_entry_to_out`),
  used by `get_wine_price` at `winebox/routers/price_tracker.py:241-250`.
- **Issue:** `WinePrice` is a global crowdsourced document: a user who contributed
  a price entry for a given wine can read the full document via
  `GET /api/prices/{wine_price_id}`, which includes **every** contributor's
  entries. `_entry_to_out` emits for each entry:
  - `owner_id` (raw `PyObjectId` serialised to string — line 73) — allows
    enumeration of other users' MongoDB IDs.
  - `coordinates` (latitude/longitude + accuracy_metres — lines 60-66) — GPS
    location where the photograph was taken. If a user captured a price from
    their own cellar at home, their home coordinates are exposed to anyone
    else who contributes a price for that same wine.
  - `shop_name`, `town_city`, `state_county`, `country`, `notes` — shop
    location text and free-form notes, potentially PII.
- **Risk:** Cross-user privacy disclosure. A malicious user can contribute a
  single cheap price observation and then pull the full global history of any
  popular wine, harvesting owner_ids and precise GPS points.
- **Recommendation:** In `_entry_to_out`, only include `owner_id`, `coordinates`,
  `notes`, and `photo_url` when `entry.owner_id == current_user.id`. For other
  users' entries, return only aggregate fields (`price`, `currency`, `timestamp`,
  `shop_name`, `country`). Alternatively, fuzz coordinates to ~1 km accuracy
  before exposing.
- **Status:** New finding (introduced in 0.7.x price tracker rewrite).

## :yellow_circle: INFO (Best practice recommendations)

### 13. Emacs auto-save and lock files tracked in git (new finding)
- **Location:**
  - `docs/#schema-diagram.md#` — Emacs autosave copy of `schema-diagram.md`
  - `docs/.#schema-diagram.md` — Emacs lock **symlink** pointing to
    `jdrumgoole@macmini.lan.33221`
- **Issue:** The lock symlink target leaks the developer's username, local
  hostname, and Emacs PID. The autosave file duplicates document content and
  will drift from the tracked `schema-diagram.md`.
- **Recommendation:** Add `.#*` and `#*#` patterns to `.gitignore`, then
  `git rm --cached docs/.#schema-diagram.md docs/\#schema-diagram.md\#` and
  commit.
- **Status:** New finding.

### 14. ObjectId parsed without try/except in price_tracker (known, still present after rewrite)
- **Location:** `winebox/routers/price_tracker.py:247` (`get_wine_price`),
  `:267` (`delete_price_entry`), `:304` (`get_wine_price_history`).
- **Issue:** `ObjectId(wine_price_id)` raises `bson.errors.InvalidId` on a
  malformed ID, surfacing as a 500 instead of a clean 404. The rest of the
  codebase (e.g. `bottles.py:103-106`, `cases.py:210-213`) has the correct
  pattern.
- **Status:** Previously flagged 2026-04-07 item #25. File was substantially
  rewritten since but the defect persists — re-report.

### 15. Form fields in price_tracker lack `max_length` (known, still present after rewrite)
- **Location:** `winebox/routers/price_tracker.py:118-132`.
  `capture_type`, `wine_name`, `wine_type`, `currency`, `notes`, `shop_name`,
  `town_city`, `state_county`, `country` all use bare `Form(...)` with no
  length bound. Only a manual check on `wine_name` (line 149) and `notes`
  (line 151) limits length.
- **Recommendation:** Push the bounds into `Form(..., max_length=N)` so
  FastAPI rejects oversized inputs before the handler runs. Compare with
  `wines/checkin.py` which constrains every Form field.
- **Status:** Previously flagged 2026-04-07 item #26. Unfixed.

### 16. `POST /api/prices` photo upload size limit is enforced after read (new finding)
- **Location:** `winebox/routers/price_tracker.py:168-170`
- **Issue:** `content = await photo.read()` loads the full upload into memory
  before the 10 MB length check. A client can send a very large body and
  exhaust the worker before the check fires. Contrast with
  `winebox/services/image_storage.py` which uses a streaming size validator.
- **Recommendation:** Use the shared `validate_upload_size()` helper or a
  streaming read with an early abort at 10 MB.
- **Status:** New finding.

### 17. Unbounded `.to_list(length=None)` in new cellar and search code paths (new finding)
- **Location:**
  - `winebox/routers/cellar.py:125` (`$facet` aggregation result)
  - `winebox/routers/cellar.py:172` (`/grouped` endpoint)
  - `winebox/routers/search.py:132` (provenance filter)
  - `winebox/routers/search.py:157, 176` (transaction date filters)
- **Issue:** All four paths are scoped by `cellar_id`/`owner_id`, so blast
  radius is bounded by one user's own data — not a cross-user DoS — but a
  user with a very large cellar can still force unbounded Python
  deserialisation and memory use per request.
- **Recommendation:** Cap with `.limit(10000)` or equivalent and paginate.
- **Status:** New finding (introduced in 0.7.x cellar schema rewrite).

## :green_circle: CLEAN (Passed review)

### Authentication & owner scoping
- New `routers/cellar.py`, `routers/bottles.py`, `routers/cases.py` all require
  `RequireAuth` and scope every query by `cellar_id: current_user.id` or
  `owner_id: current_user.id`. No missing auth found in the cellar schema
  rewrite.
- `GET /api/prices/photos/{filename}` at
  `winebox/routers/price_tracker.py:345-374` correctly validates path traversal
  **and** enforces ownership via an `$elemMatch` filter on `owner_id`.
- Password hashing (Argon2 via `pwdlib`), constant-time comparison, anti-
  enumeration dummy hash, account lockout with `Retry-After`, JWT `jti`
  blacklist, startup secret-length validation — all still in place.

### Input validation
- All new endpoints use Pydantic models or typed `Form` parameters. No raw
  `dict` bodies.
- `ObjectId` parsing is wrapped in `try/except InvalidId` in `bottles.py` and
  `cases.py`. Only `price_tracker.py` regressed — see #14.
- All regex uses of user input go through `re.escape()` (verified in
  `search.py` and `routers/wines/crud.py`).
- No `$where`, `$expr`, `$function`, or `$accumulator` operators in the new
  cellar aggregation pipelines.

### Secrets management
- No hardcoded secrets, connection strings, or API keys found in new code
  (including `scripts/scrape_wine_prices.py`, which reads `WINEBOX_MONGODB_URL`
  from env or `secrets.env`).
- No `.env`, `.key`, `.pem`, or credential files tracked in git (verified via
  `git ls-files`).

### Git history
- 30 commits since last review. No security regressions introduced. Dominant
  change is the cellar schema migration (drop `bottles`, `cases`,
  `wine_events` collections in favour of unified `cellars` + `cellar_events`).
