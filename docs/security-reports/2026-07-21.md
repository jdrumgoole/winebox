### :orange_circle: WARNING (Address within 1 week)

**W-1: CVE-2026-48710 — Starlette Host header injection auth bypass (installed: 0.50.0, fixed: 1.0.1)**

- **Dependency:** Starlette 0.50.0 (via FastAPI 0.128.1)
- **CVE:** [CVE-2026-48710](https://nvd.nist.gov/vuln/detail/CVE-2026-48710) (CVSS 6.5–7.0)
- **Detail:** A malformed HTTP `Host` header makes `request.url.path` differ from the path actually routed, bypassing middleware-based path security restrictions. Affects Starlette < 1.0.1.
- **Mitigating factors:** WineBox uses FastAPI dependency injection (`RequireAuth`, `RequireAdmin`) on every endpoint, not middleware-based path matching. The `SecurityHeadersMiddleware` does not perform auth checks. This substantially reduces practical exploitability.
- **Risk:** Even with mitigated auth bypass, Host header manipulation could affect URL generation, redirect targets, CORS origin checks, or logging accuracy.
- **Fix:** Upgrade FastAPI to a version that depends on Starlette >= 1.0.1. This is a major version jump (Starlette 0.x → 1.x) and requires testing.
- **Sources:** [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-48710), [Red Hat](https://access.redhat.com/security/cve/cve-2026-48710), [Debian](https://security-tracker.debian.org/tracker/CVE-2026-48710)

**W-2: CVE-2026-55380 — Pillow memory exhaustion via crafted .gd files (installed: 12.2.0, fixed: 12.3.0)**

- **Dependency:** Pillow 12.2.0
- **CVE:** [CVE-2026-55380](https://www.cve.org/CVERecord?id=CVE-2026-55380) (CVSS 7.5)
- **Detail:** `GdImageFile._open()` reads image dimensions without calling `_decompression_bomb_check()`. A crafted 1037-byte `.gd` file can trigger ~4.3 GB of memory allocation.
- **Exploitability in WineBox:** The `/api/wines/scan` endpoint accepts image uploads and passes them to Pillow via the OCR service **without validating file type or magic bytes** (only size is checked). An authenticated user could upload a crafted `.gd` file to trigger memory exhaustion. Other upload endpoints (`/record`, `/met`, `/prices`) validate magic bytes and would reject `.gd` files.
- **Fix:** Bump `pillow>=12.3.0` in `pyproject.toml`. Additionally, add file type validation to the `/scan` endpoint (it currently only checks size via `validate_upload_size()`).
- **Sources:** [CVE.org](https://www.cve.org/CVERecord?id=CVE-2026-55380), [Red Hat](https://access.redhat.com/security/cve/cve-2026-55380), [Debian](https://security-tracker.debian.org/tracker/CVE-2026-55380)

**W-3: XSS vectors in price-tracker.js — unescaped values in HTML attribute context**

- **File:** `winebox/static/js/price-tracker.js`
- **Detail:** Three client-side XSS vectors identified:
  1. **Line 339:** `c.photo_url` is concatenated directly into an `<img src="...">` attribute without escaping. If the API ever returns a `photo_url` containing `" onerror="alert(1)`, JavaScript executes. Currently mitigated because `photo_url` is constructed server-side from UUID filenames.
  2. **Lines 105–113, 346:** `formatPrice()` catch path returns unescaped `currency` value into innerHTML. If `Intl.NumberFormat` throws for a malicious currency code, raw input enters the DOM.
  3. **Line 359:** `c.id` is unescaped in a `data-delete="..."` attribute. MongoDB ObjectIds are hex strings, so practically safe, but the pattern is incorrect.
- **Mitigating factors:** All values originate from server-controlled data (UUIDs, ObjectIds, validated currency codes). Exploitation requires either DB compromise or a separate server-side injection.
- **Fix:** Use the same 5-character `escapeHtml()` function (already implemented in `app.js` line 3585) for all values placed in HTML attributes. Replace string concatenation with DOM APIs or template literals that escape properly.

**New INFO findings:**

**INFO-50: CVE-2026-48526 — PyJWT algorithm confusion (installed: 2.12.1, fixed: 2.13.0)**

- **CVE:** [CVE-2026-48526](https://github.com/advisories/GHSA-xgmm-8j9v-c9wx) (CVSS 7.4)
- **Detail:** When a verifier accepts both asymmetric and HMAC algorithms with JWK-format keys, an attacker can forge tokens using the public key as an HMAC secret.
- **WineBox impact:** Not exploitable. WineBox/regstack uses HS256 only with a symmetric secret key. No algorithm mixing, no JWK-format keys, no asymmetric algorithms configured. Grep for `algorithm`, `RS256`, `JWK`, `asymmetric` returns zero results in the codebase.
- **Recommendation:** Bump `pyjwt>=2.13.0` in `pyproject.toml` for defense-in-depth.

**INFO-51: CVE-2026-48525 — PyJWT DoS via large detached JWS tokens (installed: 2.12.1, fixed: 2.13.0)**

- **CVE:** [CVE-2026-48525](https://github.com/advisories/GHSA-w7vc-732c-9m39) (CVSS 5.3)
- **Detail:** PyJWT 2.8.0–2.12.1 decodes the payload segment before validation when using `b64=false` (detached JWS), allowing CPU/memory exhaustion.
- **WineBox impact:** Not exploitable. WineBox does not use detached JWS (`b64=false`). Grep for `b64.*false`, `detached`, `b64=` returns zero results.
- **Recommendation:** Bump `pyjwt>=2.13.0` with INFO-50.

**INFO-52: CVE-2026-54280/54273/54274 — aiohttp DoS vulnerabilities (installed: 3.13.5, fixed: 3.14.1)**

- **CVEs:** [CVE-2026-54280](https://github.com/advisories/GHSA-9x8q-7h8h-wcw9), [CVE-2026-54273](https://github.com/advisories/GHSA-4fvr-rgm6-gqmc), [CVE-2026-54274](https://github.com/advisories/GHSA-xcgm-r5h9-7989)
- **Detail:** Three DoS vulnerabilities: resource starvation on client disconnect, unbounded pipelining memory, oversized WebSocket frame bypass.
- **WineBox impact:** Not exploitable. WineBox does not import or use aiohttp directly — no `import aiohttp` or `from aiohttp` appears in `winebox/`. It is a transitive dependency. WineBox uses uvicorn + Starlette for HTTP serving.
- **Recommendation:** Bump `aiohttp>=3.14.1` in `pyproject.toml` for defense-in-depth.

**INFO-53: admin.js `escapeHtml` does not escape quotes, used in attribute context**

- **File:** `winebox/admin/static/js/admin.js:56–61`
- **Detail:** The `escapeHtml()` function uses the `textContent`/`innerHTML` DOM trick, which only escapes `<`, `>`, and `&` — not `"` or `'`. At line 193, the result is placed in a `data-user-email="..."` attribute, where a quote character could break out.
- **Mitigating factors:** The admin panel is IP-restricted at the nginx layer. User emails are validated via `EmailStr` (Pydantic) on creation.
- **Recommendation:** Replace with the 5-character replacement function used in `app.js:3585`.

**INFO-54: price-tracker.js `escapeHtml` also uses weak textContent trick**

- **File:** `winebox/static/js/price-tracker.js:366–369`
- **Detail:** Same weak implementation as admin.js. Currently only used in text content contexts (not attribute contexts), so not exploitable today. Latent risk if future code uses it in attributes.
- **Recommendation:** Replace with the `app.js` version.

**INFO-55: Static site export reads files using DB-sourced image paths without traversal check**

- **File:** `winebox/services/export_service/static_site.py:144–147`
- **Detail:** Image filenames from `Wine.front_label_image_path` / `back_label_image_path` are used directly in `zf.write(img_file, ...)` without path traversal validation. If DB records were poisoned, this could leak sensitive files in the ZIP export.
- **Mitigating factors:** Image paths are always generated server-side as UUID filenames. Exploitation requires DB compromise. The export endpoint requires authentication and scopes by `owner_id`.
- **Recommendation:** Add `_safe_resolve()` validation before reading files for ZIP inclusion.

**INFO-56: Price photo deletion uses DB-sourced path without traversal check**

- **File:** `winebox/routers/price_tracker.py:358–362`
- **Detail:** `entry.photo_path` from the database is used to construct a filesystem path for deletion without traversal checks. The serving endpoint (line 441) does check, but the deletion path does not.
- **Mitigating factors:** `photo_path` is server-generated as `uuid4().hex`. Exploitation requires DB manipulation.
- **Recommendation:** Add path traversal validation consistent with `_safe_resolve()`.

**INFO-57: `/api/wines/scan` endpoint lacks file type validation**

- **File:** `winebox/routers/wines/scan.py:46–66`
- **Detail:** The `/scan` endpoint only validates file size (via `validate_upload_size()`), not file type or magic bytes. Arbitrary data can reach Pillow and the Claude Vision API. Other upload endpoints (`/record`, `/met`, `/prices`) all validate magic bytes.
- **Impact:** Low-Medium. No file is persisted to disk, but arbitrary data reaches Pillow's `Image.open()` (historically vulnerable to malformed images) and the paid Claude Vision API (cost abuse).
- **Recommendation:** Add magic byte validation matching the pattern in `image_storage.save_image()`.

**INFO-58: Several Pydantic request schemas missing `max_length` constraints**

- **Files:** `winebox/schemas/wine.py` (WineBase/WineUpdate: `wine_type`, `price_tier`, `producer_type`, `custom_fields`), `winebox/schemas/reference.py` (WineScoreBase: `score_type`, `notes`; WineGrapeBlendUpdate: unbounded `grapes` list), `winebox/admin/routers/admin.py` (CreateUserRequest: `password` has no `max_length`)
- **Detail:** These fields accept unbounded string lengths via JSON API. Most concerning is the admin `password` field — a multi-MB password sent to Argon2id hashing could cause CPU/memory exhaustion (mitigated by rate limiting at 30/minute and admin-only access).
- **Recommendation:** Add `max_length` constraints to all string fields in request schemas. Add `max_length` to list fields (e.g., `grapes`). Cap admin password at 128 characters.

**INFO-59: `tarfile.extractall()` without path filter in backup script**

- **File:** `scripts/mongodb_backup.py:378`
- **Detail:** `tar.extractall(path=dump_dir)` without `filter="data"` — the classic CVE-2007-4559 pattern. A crafted tar from S3 could write files outside `dump_dir`.
- **Mitigating factors:** Archives come from S3 under project control. Exploitation requires S3 bucket compromise.
- **Recommendation:** Add `filter="data"` parameter (available on Python 3.11+).

**INFO-60: Certifi CA bundle 2 months stale**

- **Installed:** 2026.4.22; **Latest:** 2026.6.17
- **Detail:** No CVE, but the TLS root certificate store should be kept current.
- **Recommendation:** Bump `certifi>=2026.6.17`.

**INFO-61: Import processor leaks raw exception messages to HTTP clients**

- **File:** `winebox/services/import_service/processor.py:159–160, 268–271`
- **Detail:** Row-level conversion and batch insert failures use `except Exception` (broad) and accumulate `str(e)` into error lists returned verbatim to clients via the import API and SSE stream. A MongoDB connection error, Pydantic validation error, or any internal exception during import could expose database field names, collection names, or internal model structures.
- **Mitigating factors:** Import endpoints require authentication. The broad `except Exception` catches controlled failure modes in practice.
- **Recommendation:** Log the real exception server-side and return a generic message like "Error processing row N" to the client.

**INFO-62: Migration scripts log MongoDB URL with credentials in plaintext**

- **Files:** `scripts/archive/migrate_wine_ownership.py:182`, `scripts/migrations/migrate_sqlite_to_mongo.py:218`
- **Detail:** These scripts log/print the full `mongodb+srv://` connection string including embedded username and password. Compare with `deploy/import_xwines_mongo.py:238–239` which correctly masks: `mongo_url[:30] + "..."`.
- **Mitigating factors:** One-off migration scripts (one archived), not the main app. Not used in production operations.
- **Recommendation:** Mask the URL in log output.

**INFO-63: Console email backend logs password reset and verification tokens**

- **Files:** `winebox/integrations/regstack_email.py:24–29`, `winebox/services/email/console.py:49–67`
- **Detail:** When the email backend is "console" (the default per `config/schema.py:75`), the full email body — including password reset URLs with JWT tokens — is logged to stdout. These tokens allow account takeover if logs are captured.
- **Mitigating factors:** Intentional for development debugging. Production uses SES. However, no guard prevents the console backend from running in OAT/production if misconfigured.
- **Recommendation:** Add a startup warning if the console email backend is active in a non-development environment.
