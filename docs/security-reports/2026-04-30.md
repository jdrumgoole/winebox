### 🟠 WARNING

#### WARN-1: Transitive dependency `aiohttp` 3.13.3 — CVE-2026-34520 (HTTP Response Splitting)

- **Location:** `uv.lock` (transitive via aiobotocore/aioboto3)
- **Installed:** 3.13.3
- **Fixed in:** 3.13.4
- **Details:** The C parser accepts null bytes and control characters in response headers, violating RFC 9110. This enables HTTP response splitting attacks.
- **Action:** Upgrade to aiohttp >= 3.13.4 by bumping aioboto3 or adding a direct constraint.

#### WARN-2: Transitive dependency `requests` 2.32.5 — CVE-2026-25645 (Local Privilege Escalation)

- **Location:** `uv.lock` (transitive via posthog and others)
- **Installed:** 2.32.5
- **Fixed in:** 2.33.1
- **Details:** `requests.utils.extract_zipped_paths()` writes to a predictable location in `/tmp`, allowing local file replacement attacks.
- **Action:** Upgrade requests to >= 2.33.1 by adding a direct constraint.

#### WARN-3: Transitive dependency `certifi` 2026.1.4 — Stale CA Bundle

- **Location:** `uv.lock`
- **Installed:** 2026.1.4
- **Latest:** 2026.4.22
- **Details:** The CA bundle is ~3 months old. Mozilla may have revoked or added certificates since January 2026.
- **Action:** Upgrade to certifi >= 2026.4.22.

#### WARN-4: Reference data endpoints call `.to_list()` without length bounds

- **Location:** `winebox/routers/reference.py` (lines 31, 76, 138, 164, 230, 270, 308, 335)
- **Details:** Multiple reference data endpoints (wine types, grape varieties, regions, classifications) call `.to_list()` without a `length` parameter. While these are system reference collections (not user-controlled), the region tree endpoint without a country filter could load the entire hierarchy into memory.
- **Action:** Add `length=` bounds to `.to_list()` calls, particularly the region tree endpoint.

#### WARN-5: `list_batches` endpoint has no max cap on `limit` parameter

- **Location:** `winebox/routers/import_router.py` (lines 506-517)
- **Details:** The `limit` parameter has no `le=MAX_PAGE_SIZE` constraint and defaults to `None` (unbounded). When omitted, the query has no bound at all. Inconsistent with all other paginated endpoints.
- **Action:** Add `le=MAX_PAGE_SIZE` to the `limit` parameter, matching the pattern used everywhere else.

#### WARN-6: `User.find_all().to_list()` in admin panel loads all users without pagination

- **Location:** `winebox/admin/routers/admin.py` (line 61)
- **Details:** Admin user listing loads ALL users into memory with no pagination or length bound. Protected by `RequireAdmin` and IP allowlist, but could become a problem if the user base grows.
- **Action:** Add pagination (skip/limit) to the admin user listing endpoint.

#### WARN-7: Admin panel does not disable `/docs`/`/redoc`/`/openapi.json` in production

- **Location:** `winebox/admin/main.py` (lines 52-56)
- **Details:** The main app correctly disables API docs when `debug=False`, but the admin app does not apply the same logic. Anyone who bypasses the IP allowlist (or any admin user) can browse the full admin API schema.
- **Action:** Add `docs_url=None, redoc_url=None, openapi_url=None` when not in debug mode, matching the main app's pattern.

#### WARN-8: MongoDB Atlas cluster hostname hardcoded in source code

- **Location:** `scripts/rename_mongodb_database.py` (line 11), `winebox/admin/routers/admin.py` (line 35)
- **Details:** The Atlas cluster hostname `shared.2t22cum.mongodb.net` appears in a usage docstring and in a code comment (ironically, the comment warns about not exposing it). While not a credential, a cluster hostname reduces the attacker's search space.
- **Action:** Replace with a generic placeholder like `<cluster>.mongodb.net` in both locations.

#### WARN-9: CellarEvent query in `get_item_events` lacks direct owner_id filter

- **Location:** `winebox/routers/bottles.py` (lines 188-190)
- **Details:** The endpoint first verifies ownership of the cellar item (line 184), but then queries CellarEvents with only `{"cellar_item_id": oid}` without an additional owner_id filter. Mitigated by the prior ownership check, but adding `cellar_id: current_user.id` to the CellarEvent query would be a defense-in-depth improvement.
- **Action:** Add owner scoping to the CellarEvent query.

#### WARN-10: Admin `admin_me` endpoint uses RequireAuth + manual is_superuser check instead of RequireAdmin

- **Location:** `winebox/admin/routers/auth.py` (lines 59-65)
- **Details:** The endpoint uses `RequireAuth` and then manually checks `current_user.is_superuser`. While functionally equivalent, it should use `RequireAdmin` for consistency and to avoid the risk of a developer forgetting the manual check in future endpoints.
- **Action:** Change to use `RequireAdmin` dependency.

### 🟡 INFO

#### INFO-1: Anthropic client in `annotate_xwines_prices.py` created without timeout

- **Location:** `scripts/annotate_xwines_prices.py` (line 344)
- **Details:** All other Anthropic client instantiations in the codebase specify explicit timeouts (60s or 120s). This standalone script creates the client without a timeout parameter, meaning it could hang indefinitely on a stalled API call.

#### INFO-2: Admin panel limiter instances bypass `make_limiter()` factory

- **Location:** `winebox/admin/routers/auth.py` (line 20), `winebox/admin/routers/admin.py` (line 23), `winebox/admin/main.py` (line 50)
- **Details:** Admin panel creates raw `Limiter(key_func=get_remote_address)` instead of using `make_limiter()`, which means they do not respect `WINEBOX_RATE_LIMIT_DISABLED=1`. This is arguably correct (admin rate limits should always be active), but it is inconsistent and could cause unexpected rate limiting in CI.

#### INFO-3: Admin state-changing endpoints lack per-endpoint rate limits

- **Location:** `winebox/admin/main.py` (line 50), `winebox/admin/routers/admin.py`
- **Details:** The admin app has no `default_limits`. State-changing admin endpoints (create/delete users, change privileges) lack per-endpoint rate limits. Mitigated by nginx IP allowlist, but defense-in-depth would benefit from explicit limits.

#### INFO-4: Several unbounded `.to_list()` calls in event/bottle/demo queries

- **Location:** `winebox/routers/bottles.py` (lines 188-190), `winebox/services/cellar_event_view.py` (lines 236-243), `winebox/services/demo_service.py` (lines 447-449, 465-467)
- **Details:** These queries call `.to_list()` without a length bound. While naturally bounded by real-world data volumes (events per item, demo wines per user), they lack explicit protection.

#### INFO-5: `$in` with up to 50,000 IDs in X-Wines price filter

- **Location:** `winebox/routers/xwines.py` (lines 132-134)
- **Details:** `_get_price_filtered_ids` fetches up to 50,000 xwines_ids and passes them as `$in` arrays. Bounded by `to_list(length=50000)`, but still a large `$in` clause that could cause performance issues.

#### INFO-6: Hardcoded test passwords in developer utility scripts

- **Location:** `scripts/screenshot_import_tab_order.py` (line 53), `scripts/screenshot_checkin_enrichment.py` (line 32), `scripts/check_url_hashes.py` (line 39)
- **Details:** These developer-only scripts use `TestPassword123!` for ephemeral test users against local/OAT databases. Not a credential leak, but loading from an env var would be more hygienic.

#### INFO-7: No OCSP stapling in nginx configuration

- **Location:** `deploy/nginx-winebox.conf`, `deploy/nginx-winebox-oat.conf`
- **Details:** Enabling `ssl_stapling on; ssl_stapling_verify on;` would improve TLS performance and certificate revocation checking.

#### INFO-8: Password validation only checks length (min 8), no common-password blocklist

- **Location:** `winebox/auth/schemas.py` (lines 34-39)
- **Details:** While NIST SP 800-63B favors length over complexity, adding a check against common passwords would improve security.

#### INFO-9: Developer scripts use httpx.AsyncClient() without explicit timeouts

- **Location:** `scripts/screenshot_import_tab_order.py`, `scripts/check_url_hashes.py`, `scripts/screenshot_checkin_enrichment.py`
- **Details:** These are local development/screenshot scripts connecting to localhost. Low risk but explicit timeouts would be best practice.

#### INFO-10: HTML injection in static site export (self-XSS)

- **Location:** `winebox/services/export_service/static_site_template.py` (lines 30-34)
- **Details:** User-supplied filter values are interpolated into exported HTML without escaping. Very low risk since the output is a ZIP file downloaded by the same user who supplied the filters (self-XSS scenario), and the HTML is served as a file download, not in the application's origin.

### 🟢 CLEAN

#### Authentication & Authorization
- All user-data endpoints require authentication via `RequireAuth` or `RequireAdmin`.
- Owner-scoping (`owner_id` / `cellar_id`) consistently applied across all collections.
- Reference data (`/api/reference`) and X-Wines (`/api/xwines`) intentionally public — read-only lookup data.
- Admin panel protected by IP allowlist (nginx) + JWT authentication + `RequireAdmin` checks.
- API docs disabled in production (main app).

#### Password Security
- Argon2 password hashing with constant-time verification via pwdlib.
- Timing attack prevention: dummy hash verified when user not found, preventing user enumeration.
- Account lockout after 5 failed attempts within 15 minutes.
- Password changes and resets invalidate all existing tokens via dual-layer revocation.

#### Session & Token Security
- JWT tokens use HS256 with minimum 32-character secret key (enforced at startup).
- Tokens include `jti` (UUID), `iat`, `exp`, and `sub` claims.
- Dual-layer revocation: per-token blacklist + bulk user invalidation cutoff.
- Purpose-specific secret derivation (SHA256) for reset/verification tokens.
- No token values logged anywhere in the codebase.

#### Rate Limiting
- Global: 60 requests/minute per IP.
- Login: 30/minute, 200/hour + account lockout.
- Registration: 10/minute, 50/hour.
- Password reset/change: 5/minute, 20/hour.
- Search: 120/minute, 2000/hour with 200-char query limit.
- Export: 10/minute, 30/hour.
- Scan/enrichment: 20/minute, 100-200/hour.
- Admin login: 5/minute.

#### Input Validation
- All API inputs use Pydantic models with field constraints.
- All regex construction from user input uses `re.escape()`.
- All ObjectId parsing wrapped in try/except.
- No unsafe MongoDB operators (`$where`, `$expr`, `$accumulator`, `$function`).
- File uploads validated: extension, size, magic bytes; UUID filenames prevent path traversal.
- `_safe_resolve()` prevents path traversal in image serving.

#### Security Headers
- `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `X-XSS-Protection: 1; mode=block`.
- `Content-Security-Policy`: `script-src 'self'` (no unsafe-inline for scripts).
- `Strict-Transport-Security`: 1 year with includeSubDomains and preload.
- `Referrer-Policy`, `Permissions-Policy`, `X-Permitted-Cross-Domain-Policies` all set.
- CORS: empty origin list by default (same-origin only).
- No inline scripts in any HTML template.

#### Data Exposure
- `UserResponse` model excludes `hashed_password` and internal fields.
- Error messages are generic — no user enumeration or internal detail leakage.
- No stack traces, database names, or file paths in error responses.
- Secret values masked during deploy sync.

#### Secrets Management
- No real API keys, connection strings, private keys, or JWTs in the codebase.
- `.gitignore` covers `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`.
- No sensitive files accidentally committed in git history.
- All API keys (Anthropic, PostHog, AWS) loaded from environment variables or `secrets.env`.

#### Infrastructure
- Production safety checks at startup: weak secret key blocked, debug mode blocked, HTTPS enforcement checked.
- Database safety check prevents dev environments from connecting to production MongoDB.
- Nginx: `server_tokens off`, TLS 1.2/1.3 only, strong ciphers, HSTS 2-year max-age.
- MongoDB connection with defensive timeouts (5s/10s/30s) and bounded connection pool.
- Systemd services hardened: `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome=true`, bind to 127.0.0.1 only.

#### Dependencies
- Proactive CVE patching: pillow (CVE-2026-25990, CVE-2026-40192), pyjwt (CVE-2026-32597), cryptography (CVE-2026-39892, CVE-2026-34073), python-multipart (CVE-2026-40347), cairosvg (CVE-2026-31899) all pinned to fixed versions.
- No yanked or compromised packages detected.
- No dependency more than 1 major version behind latest.

#### Git History
- Last 30 commits: feature work, security improvements, version bumps. No regressions.
- Recent security-positive commits: shlex.quote() injection fix, CSP improvements, admin panel IP restrictions.
- No secrets accidentally committed.
