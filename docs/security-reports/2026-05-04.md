### 🟡 INFO (Best practice recommendations)

**INFO-1: Missing rate limit on `/api/demo/remove` endpoint**

- **File:** `winebox/routers/demo.py` (line 122)
- **Detail:** The `DELETE /api/demo/remove` endpoint requires authentication but has no `@limiter.limit()` decorator, unlike its counterpart `POST /api/demo/install` which is rate-limited to 5/minute, 10/hour. A user could repeatedly call remove in a burst.
- **Impact:** Low — requires authentication, only affects the caller's own demo data.
- **Recommendation:** Add `@limiter.limit("5/minute;20/hour")` to match the install endpoint.

**INFO-2: Missing rate limit on SSE enrichment progress endpoint**

- **File:** `winebox/routers/wines/enrichment.py` (line 25)
- **Detail:** The `enrichment_progress` SSE streaming endpoint has no rate limiter on connection initiation. The stream self-terminates after 5 minutes (max_polls=600), which provides natural bounds, but repeated rapid reconnections are not throttled.
- **Impact:** Low — requires authentication, has built-in timeout, and the SSE connection is long-lived by design.
- **Recommendation:** Consider adding a connection rate limit (e.g., 10/minute) to prevent reconnection flooding.

**INFO-3: `datetime.utcnow()` usage in migration script and test file**

- **Files:** `scripts/migrations/migrate_sqlite_to_mongo.py` (lines 264–466), `tests/test_wine_ownership.py` (lines 38–39)
- **Detail:** These files use the deprecated `datetime.utcnow()` (timezone-naive) instead of `datetime.now(timezone.utc)` (timezone-aware). All application code in `winebox/` correctly uses timezone-aware datetimes.
- **Impact:** Negligible — the migration script is a one-time legacy tool, and the test file's usage doesn't affect production behaviour.
- **Recommendation:** Update to `datetime.now(timezone.utc)` for consistency when these files are next touched.

#### 2. Hardcoded Secrets Scan

- No API keys, connection strings, passwords, private keys, or JWTs found in source code.
- `config/secrets.env.example` contains only placeholder values.
- `.gitignore` properly covers: `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`.
- `git ls-files` confirms no sensitive files tracked (only `config/secrets.env.example`).
- Test fixtures use obvious dummy values (`AKIAIOSFODNN7EXAMPLE`, `phc_test_api_key`, `testpassword`).
- GitHub Actions workflows use `${{ secrets.NAME }}` pattern throughout.
- All scripts and deployment code load credentials from environment variables.

#### 3. Authentication & Authorization Audit

- **All 60+ endpoints** handling user data require `RequireAuth` or `RequireAdmin`.
- **All database queries** for user-owned data filter by `owner_id` or `cellar_id`.
- Public endpoints (`/api/reference/*`, `/api/xwines/*`, `/health`, `/api/config/analytics`) serve only static reference data — no user information exposed.
- Admin endpoints use `RequireAdmin` (not just `RequireAuth`).
- Admin panel self-modification prevented (`_check_not_self()` blocks self-deactivation, self-deletion, self-de-admin).
- Password changes invalidate all existing tokens via dual mechanism:
  - Per-token blacklist (JTI-based)
  - Bulk `tokens_invalidated_after` cutoff on user document
- User registration validates email format (Pydantic `EmailStr`) and password length (8+ chars).
- Constant-time password comparison via Argon2 `verify()` with dummy hash for non-existent users.
- Account lockout: 5 failed attempts within 15 minutes triggers 15-minute lockout.

#### 4. NoSQL Injection & Query Safety

- All regex searches use `re.escape()` before compilation.
- No unsafe MongoDB operators (`$where`, `$expr`, `$accumulator`, `$function`) found.
- All `ObjectId` parsing wrapped in `try/except` with proper 400/404 responses.
- All API inputs validated via Pydantic models — no raw `dict` or untyped JSON bodies.
- No raw pymongo collection access bypassing model safety.
- Search query length capped at 200 characters.
- `$in` queries bounded by `MAX_USER_RESULTSET` (10,000).
- No `eval()`, `exec()`, or `subprocess` with user input.

#### 5. Input Validation & Injection Prevention

- File uploads validated: magic byte detection, extension whitelist, size limits (images configurable, imports 25 MB, price photos 10 MB).
- Path traversal prevented in image serving (`_safe_resolve()` rejects `..`, `/`, `\`, and verifies `relative_to()`).
- Generated filenames use UUIDs, not user input.
- Jinja2 templates use `autoescape=True` — no `|safe` or `{% autoescape false %}` usage.
- HTML export uses `html.escape()` for user data.
- All paginated endpoints enforce maximum limits via `Query(ge=1, le=MAX)`.

#### 6. Rate Limiting & DoS Prevention

- **Global:** 60 requests/minute per IP.
- **Login:** 30/minute, 200/hour + account lockout after 5 failed attempts (15-minute window).
- **Registration:** 10/minute, 50/hour.
- **Password reset/change:** 5/minute, 20/hour.
- **Search:** 120/minute, 2000/hour with 200-char query limit.
- **Export:** 10/minute, 30/hour.
- **Scan/enrichment:** 20/minute, 100–200/hour.
- **Admin login:** 5/minute.
- **Admin endpoints:** 30/minute.
- **File uploads:** 10/minute, 30/hour.
- All paginated queries bounded by `MAX_USER_RESULTSET` (10,000) and `MAX_PAGE_SIZE` (200).

#### 7. Session & Token Security

- JWT tokens use HS256 with minimum 32-character secret key (enforced at startup).
- Tokens include `jti` (UUID), `iat`, `exp`, and `sub` claims.
- Dual-layer revocation: per-token blacklist + bulk user invalidation cutoff.
- Revoked token cleanup via background task (hourly) + MongoDB TTL indexes.
- Purpose-specific secret derivation (SHA256) for reset/verification tokens prevents type confusion.
- No token values logged anywhere in the codebase.
- HSTS enabled in production: `max-age=31536000; includeSubDomains; preload`.

#### 8. Security Headers

- `X-Content-Type-Options: nosniff` — in both FastAPI middleware and nginx.
- `X-Frame-Options: DENY` — in both FastAPI middleware and nginx.
- `X-XSS-Protection: 1; mode=block`.
- `Referrer-Policy: strict-origin-when-cross-origin`.
- `X-Permitted-Cross-Domain-Policies: none`.
- `Permissions-Policy` restricting camera, geolocation, microphone, etc.
- `Content-Security-Policy`: `script-src 'self'` (no unsafe-inline for scripts), PostHog domains whitelisted.
- CORS: empty origin list by default (same-origin only), explicit whitelist when configured.
- No inline scripts in HTML templates — all use external JS files.
- Nginx adds security headers to static file locations (including SVG, CSS, JS).

#### 9. Data Exposure

- `UserResponse` model excludes `hashed_password` and internal fields.
- Error messages are generic ("Incorrect email or password") — no user enumeration.
- API docs (`/docs`, `/redoc`, `/openapi.json`) disabled in production (both main app and admin panel).
- No stack traces, database names, or file paths in error responses.
- Exports strip `owner_id` from JSON/YAML output.
- Price tracker hides owner-specific PII (coordinates, notes, photos) from non-owners.
- Admin `/api/info` endpoint intentionally omits MongoDB hostname.
