### :orange_circle: WARNING

**W-1: Dependency upgrade backlog — 5 packages with known CVEs remain unpatched (escalated from INFO)**

- **Packages and CVEs:**
  - `starlette 0.50.0` (via FastAPI) — CVE-2026-48710: Host header auth bypass (CVSS 6.5–7.0), fixed in 1.0.1. Directly relevant to WineBox's `RequireAuth` middleware pattern.
  - `pyjwt 2.12.1` — CVE-2026-48526: Algorithm confusion allowing token forgery (CVSS 7.4), fixed in 2.13.0. Relevant to WineBox's JWT-based session handling.
  - `python-multipart 0.0.28` — CVE-2026-53537: Content-Disposition parameter smuggling, fixed in 0.0.30. Relevant to file upload endpoints.
  - `cryptography 46.0.7` — CVE-2026-69249: Exponential path-building DoS via duplicate self-signed intermediates, fixed in 49.0.0.
  - `pillow 12.2.0` — CVE-2026-55798 (RCE via WindowsViewer, lower risk on Linux) and CVE-2026-59203 (DoS via crafted EPS), both fixed in 12.3.0.
- **Impact:** The Starlette and PyJWT CVEs are the most concerning — they target authentication and token validation, which are core to WineBox's security model. While exploitability depends on specific configuration, the packages are multiple patches behind their fixes.
- **Recommended `pyproject.toml` changes:**

  | Package | Current pin | Recommended pin |
  |---------|-------------|-----------------|
  | fastapi | `>=0.109.0` | `>=0.136.0` |
  | pyjwt | `>=2.12.0` | `>=2.13.0` |
  | python-multipart | `>=0.0.26` | `>=0.0.30` |
  | cryptography | `>=46.0.7` | `>=49.0.0` |
  | pillow | `>=12.2.0` | `>=12.3.0` |

- **Status:** Escalated from INFO. This backlog has been tracked since 2026-05-11 and now spans 21+ CVEs across 6 packages. The previous review's #1 priority was a batch dependency upgrade; it remains unaddressed.

**W-2: Hardcoded test passwords in 3 scripts (NEW)**

- **Files:**
  - `scripts/check_url_hashes.py:39` — `password = "TestPassword123!"`
  - `scripts/screenshot_import_tab_order.py:53` — `password = "TestPassword123!"`
  - `scripts/screenshot_checkin_enrichment.py:32` — `TEST_PASSWORD = "TestPassword123!"`
- **Detail:** These scripts hardcode a password used to create ephemeral test users against the OAT environment. CLAUDE.md explicitly prohibits hardcoded passwords in scripts: "NEVER hardcode credentials, connection strings, passwords, API keys, or tokens in source code — not in scripts, tests, config files, or anywhere that gets committed to git."
- **Impact:** Low direct risk (OAT environment, ephemeral users), but violates project security policy and sets a bad precedent.
- **Recommendation:** Refactor all three scripts to read the password from an environment variable (e.g., `WINEBOX_TEST_PASSWORD`) and fail with a clear error if not set.

**INFO-57: HSTS header missing on two nginx static-file locations (NEW)**

- **File:** `deploy/nginx-winebox.conf`
- **Detail:** The `location = /static/index.html` and `location = /static/landing.html` blocks add cache headers but omit HSTS. nginx's `add_header` in child `location` blocks overrides rather than appends to parent headers, so the parent server block's HSTS header is lost for these two paths.
- **Impact:** Low — browsers that first visit these specific paths won't receive HSTS. Subsequent navigation to other paths will set it. Both pages are served over HTTPS regardless.

**INFO-58: Admin panel limiter has no default rate limits (NEW)**

- **File:** `winebox/admin/main.py:58`
- **Detail:** The admin `Limiter` is initialised without `default_limits`. Existing admin endpoints have explicit per-route limits (30/min), but any new endpoint added without a decorator gets zero rate limiting.
- **Impact:** Low — the admin panel is IP-restricted at nginx, so the blast radius is small. Adding a default limit would be defense-in-depth.

**INFO-59: Some `to_list()` calls missing explicit length bounds (NEW)**

- **Files:** `bottles.py:190`, `price_tracker.py:316,403`, `import_router.py:516`
- **Detail:** Four `to_list()` calls have no `length=` argument. Queries are scoped to a single user/item and typically return small result sets, but a theoretical edge case with massive event history could cause unbounded memory use.
- **Impact:** Very low — owner-scoped queries and rate limiting provide sufficient mitigation.

**INFO-60: Admin user deletion leaves orphaned documents (NEW)**

- **File:** `winebox/admin/routers/admin.py:303-330`
- **Detail:** `delete_user` cleans up `wines`, `transactions`, `import_batches`, and `raw_uploads`, but does not delete from `cellar_items`, `cellar_events`, `wine_prices`, or `wine_price_history`. Orphaned documents persist with stale references.
- **Impact:** Not a data exposure risk (all queries filter by `owner_id`), but a data hygiene gap.

**INFO-61: Broad `except Exception` for ObjectId parsing in reference endpoints (NEW)**

- **Files:** `winebox/routers/reference.py:91-96,198-201,220-224,249-253`, `winebox/services/cellar_event_view.py:206`
- **Detail:** Five locations catch `Exception` broadly for ObjectId parsing instead of the more precise `except (InvalidId, ValidationError)` pattern used elsewhere. Could mask unrelated errors as 404 responses.
- **Impact:** Very low — defense-in-depth, not a vulnerability.

### :green_circle: CLEAN (Passed review)

#### 1. Hardcoded Secrets

No real secrets in the codebase. `.gitignore` properly covers `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`. The only tracked secrets-related file is `config/secrets.env.example` (a template with no real values). The `AKIAIOSFODNN7EXAMPLE` in tests is the AWS documentation example key.

#### 2. Authentication & Authorization

All user-data endpoints require `RequireAuth`. All admin endpoints use `RequireAdmin`. Owner-scoping (`owner_id` filtering) is applied consistently across all routers. The shared helper `get_wine_or_404` always filters by both `_id` and `owner_id`. Reference and X-Wines endpoints are intentionally public (shared data, not user-specific).

#### 3. NoSQL Injection & Query Safety

No injection vulnerabilities found. All regex patterns from user input use `re.escape()`. All `ObjectId()` parsing is wrapped in try/except. No dangerous MongoDB operators (`$where`, `$expr`, `$accumulator`, `$function`) used anywhere. No raw `dict` or untyped JSON body endpoints.

#### 4. Input Validation

All API inputs use Pydantic models. File uploads validate MIME types, enforce size limits, and check magic bytes. Path traversal prevented via `_safe_resolve()`. Search queries capped at 200 characters. Jinja2 templates use `autoescape=True`.

#### 5. Session & Token Security

JWT tokens use dedicated secret with 120-minute TTL. JTI present for revocation support. Token revocation verified via blacklist. Password changes invalidate all existing tokens via `tokens_invalidated_after`. Constant-time password verification via Argon2id. No token leakage in logs or responses. HTTPS enforced in production.

#### 6. Security Headers

`SecurityHeadersMiddleware` sets X-Content-Type-Options, X-Frame-Options, CSP, Referrer-Policy, Permissions-Policy, and conditional HSTS. No inline scripts (CSP compliant). CORS defaults to same-origin only.

#### 7. Rate Limiting

Auth endpoints rate-limited (login 30/min, register 10/min, password reset 5/min). Admin login 5/min. Global default 60/min. Expensive endpoints (scan, export, enrichment, import) have explicit limits.

#### 8. DoS Prevention

Pagination limits enforced (`MAX_PAGE_SIZE=200`). Result sets bounded (`MAX_USER_RESULTSET=10,000`). File upload sizes validated. MongoDB connection has explicit timeouts (serverSelection 5s, connect 10s, socket 30s).

#### 9. Data Exposure

API responses exclude sensitive fields (hashed passwords never returned). API docs disabled in production. No sensitive data in logs. Error messages use controlled exception types.

#### 10. Git History

No secrets files ever committed to git history. No security regressions in recent commits. Recent changes limited to security reports and infrastructure tasks (`prod-ssl`).

#### 11. Infrastructure & Configuration

Debug defaults to `False`. Startup validation blocks production with weak keys. Database safety check prevents non-production hosts from touching production DB. nginx hides version (`server_tokens off`), uses TLS 1.2+ with strong ciphers, and IP-restricts the admin panel.

#### 12. Third-Party Integration Security

Anthropic API key loaded from environment with explicit timeouts (60–120s). PostHog API key loaded from secrets config (public write-only key served via standard pattern). AWS credentials use named profile, never logged. No SSRF vectors.
