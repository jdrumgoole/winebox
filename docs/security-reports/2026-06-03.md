### :orange_circle: WARNING

**WARNING-1: `skip` query parameter has no maximum cap on 7 endpoints**

- **Files:**
  - `winebox/routers/cellar.py:25` — `skip: int = Query(0, ge=0)`
  - `winebox/routers/transactions.py:32` — `skip: int = Query(0, ge=0)`
  - `winebox/routers/search.py:46` — `skip: int = Query(0, ge=0)`
  - `winebox/routers/wines/crud.py:23` — `skip: int = Query(0, ge=0)`
  - `winebox/routers/met.py:17` — `skip: int = Query(0, ge=0)`
  - `winebox/routers/price_tracker.py:307,380` — `skip: int = Query(0, ge=0)`
- **Detail:** A client can pass `skip=999999999`, forcing MongoDB to scan and discard that many documents before returning results. While all queries are owner-scoped (limiting the practical data set), an attacker who imports a large data set could tie up MongoDB connections (up to the 30-second socket timeout) with repeated high-skip requests. At the global 60/minute rate limit, this could exhaust the connection pool (max 100).
- **Comparison:** The X-Wines search endpoint already correctly caps skip at 10,000 (`winebox/routers/xwines.py:482`), showing this pattern is known in the codebase. The `limit` parameter is properly capped everywhere.
- **Recommendation:** Add `le=10000` (or `le=MAX_USER_RESULTSET`) to all `skip` parameters, consistent with the X-Wines endpoint.
- **Status:** New finding.

**WARNING-2: Missing rate limits on regstack account management routes**

- **File:** `winebox/auth/regstack_setup.py` (absent from `_RATE_LIMITS` dict)
- **Detail:** The `_RATE_LIMITS` dictionary omits `change_email_rate_limit`, `confirm_email_change_rate_limit`, and `delete_account_rate_limit`. These default to `None` (no rate limit) per regstack's `config/schema.py:228-230`. The `change_email` endpoint triggers a verification email, so an authenticated attacker could use it to spam a target email address at the global 60/minute rate. `delete_account` requires password confirmation, reducing abuse risk.
- **Recommendation:** Add `"change_email_rate_limit": "5/minute;20/hour"`, `"confirm_email_change_rate_limit": "5/minute;20/hour"`, and `"delete_account_rate_limit": "3/minute;10/hour"` to the `_RATE_LIMITS` dict.
- **Status:** New finding.

**INFO-8: Starlette 0.50.0 is affected by CVE-2026-48710 (BadHost) — no practical impact on WineBox**

- **File:** `uv.lock` — starlette pinned at 0.50.0; patch is in starlette 1.0.1
- **CVE:** CVE-2026-48710 — Starlette reconstructs `request.url` from the HTTP Host header without validation. A malformed Host header can cause `request.url.path` to differ from the path the ASGI server actually routed, allowing middleware that makes security decisions based on `request.url.path` to be bypassed.
- **Impact on WineBox: None.** WineBox does not use path-based auth middleware. Authentication is enforced via FastAPI dependency injection (`RequireAuth`, `RequireAdmin`) on individual route handlers, which operate on the ASGI scope path (the correctly-routed path), not `request.url.path`. Additionally, nginx normalises Host headers in production.
- **Upgrade path:** FastAPI 0.128.1 constrains starlette to `<0.51.0,>=0.40.0`. Upgrading to starlette 1.0.1 requires upgrading FastAPI to >=0.136.0 (latest: 0.136.3).
- **Recommendation:** Plan a coordinated FastAPI + Starlette upgrade in a future maintenance cycle.
- **Status:** Carried forward from 2026-05-27 review.

**INFO-14: Deprecated `X-XSS-Protection` header set to `1; mode=block`**

- **File:** `winebox/main.py:46`
- **Detail:** The `X-XSS-Protection` header is deprecated and has been removed from modern browsers. **INFO-17: Two JS files use weaker `escapeHtml()` function**

- **Files:**
  - `winebox/static/js/price-tracker.js:366` — uses `textContent`/`innerHTML` technique
  - `winebox/admin/static/js/admin.js:56` — uses `textContent`/`innerHTML` technique
- **Detail:** The main `app.js` was updated to escape all five HTML-significant characters (`<`, `>`, `&`, `"`, `'`) at line 3585 with a comment explaining attribute-context safety. However, `price-tracker.js` and `admin.js` still use the `textContent`/`innerHTML` technique, which only escapes `<`, `>`, and `&` but not `"` or `'`. In `admin.js:193`, user email is inserted into a `data-user-email` attribute — if an email contained `"`, it could break the attribute boundary. In practice, `EmailStr` validation rejects emails containing `"`.

**INFO-18: Landing page served directly by nginx lacks CSP header**

- **Files:** `deploy/nginx-winebox.conf`, `deploy/nginx-winebox-oat.conf`
- **Detail:** The landing pages at `winebox.app` and `www.winebox.app` are served directly by nginx (not proxied to the application), so the application's `SecurityHeadersMiddleware` does not apply. These pages get HSTS and X-Frame-Options from nginx but no Content-Security-Policy header. The landing page uses only external scripts and styles, so adding CSP at the nginx level would provide defence in depth.
- **Recommendation:** Add `add_header Content-Security-Policy "default-src 'self'; ..."` to the nginx landing page location blocks.
- **Status:** New finding.

**INFO-19: Nginx HSTS header lacks `includeSubDomains` on server-level directives**

- **Files:** `deploy/nginx-winebox.conf:78`, `deploy/nginx-winebox-oat.conf`
- **Detail:** Nginx sets `Strict-Transport-Security: max-age=63072000` without `includeSubDomains` or `preload`. The application middleware sets `max-age=31536000; includeSubDomains; preload` on proxied responses. For the landing page blocks served directly by nginx, the HSTS header is missing `includeSubDomains`, leaving subdomains unprotected by HSTS preload.
- **Recommendation:** Add `includeSubDomains; preload` to the nginx-level HSTS header.
- **Status:** New finding.

**INFO-20: OCSP stapling not enabled in nginx SSL configuration**

- **Files:** `deploy/nginx-winebox.conf`, `deploy/nginx-winebox-oat.conf`
- **Detail:** Neither nginx configuration enables `ssl_stapling on; ssl_stapling_verify on;`. OCSP stapling improves TLS handshake performance and prevents OCSP responder downtime from affecting clients. This is a minor TLS hardening improvement.
- **Recommendation:** Add `ssl_stapling on; ssl_stapling_verify on; resolver 8.8.8.8 8.8.4.4;` to the SSL server blocks.
- **Status:** New finding.

**INFO-21: Missing timeouts on HTTP requests in DNS setup script**

- **File:** `scripts/setup_digitalocean_fastmail_dns.py:64,77,92,102`
- **Detail:** The `DigitalOceanDNS` class makes `requests.get/post/delete` calls to the DigitalOcean API without any `timeout` parameter. The equivalent class in `deploy/common.py` properly sets `self._timeout = 30`. This is a one-off setup script, not a production code path.
- **Recommendation:** Add `timeout=30` to all `requests.*` calls, consistent with `deploy/common.py`.
- **Status:** New finding.

#### 3. Authentication & Authorization Audit

All endpoints across 25+ router files audited:

- **All database queries** for user-owned data filter by `owner_id` or `cellar_id`.
- Public endpoints (`/api/reference/*`, `/api/xwines/*`, `/health`, `/api/config/analytics`) serve only static reference data — no user information exposed.

- JWT tokens use purpose-separated derived keys (session, password_reset, email_change) via HMAC-SHA256.
