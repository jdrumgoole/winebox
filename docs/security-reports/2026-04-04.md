# WineBox Security Review — 2026-04-04

## Scope

Full security audit of the WineBox codebase covering: dependency vulnerabilities, hardcoded secrets, authentication & authorization, NoSQL injection & input validation, rate limiting & DoS prevention, session & token security, security headers, data exposure, infrastructure configuration, and third-party integrations.

---

## :red_circle: CRITICAL — Immediate Action Required

### C1. `python-jose` is unmaintained — replace with `pyjwt`

- **Package:** `python-jose` 3.5.0
- **CVEs:** CVE-2024-33663 (algorithm confusion), CVE-2024-33664 (JWT bomb DoS)
- The library is effectively abandoned. It handles JWT signing/verification — a security-critical function.
- **Action:** Migrate to `pyjwt`, which is actively maintained and recommended by the FastAPI community.

### C2. `cryptography` needs bump to >=46.0.6

- **Current:** 46.0.5 (resolved in uv.lock)
- **CVE-2026-34073:** Incomplete DNS name constraint enforcement during certificate validation. Fixed in 46.0.6.
- **Action:** Bump minimum to `cryptography>=46.0.6` and run `uv lock --upgrade-package cryptography`.

### C3. `anthropic` SDK has two CVEs — upgrade to >=0.87.0

- **Current:** 0.77.1
- **CVE-2026-34450:** Insecure default file permissions (0o666) in local filesystem memory tool.
- **CVE-2026-34452:** Race condition in async memory tool path validation allowing sandbox escape.
- **Action:** Bump to `anthropic>=0.87.0`.

## :orange_circle: WARNING — Address Within 1 Week

### W1. Password change only revokes the current session token, not all tokens

- **File:** `winebox/routers/auth.py`, lines 170–178
- When a user changes their password, only the current request's token is revoked. Other sessions on other devices remain valid for up to 2 hours.
- The project's own CLAUDE.md guideline states: "When changing passwords, invalidate all existing tokens for that user."
- **Recommendation:** Implement `revoke_all_user_tokens(user_id)` or use a per-user `password_changed_at` timestamp to reject older tokens.

### W2. Password reset does not invalidate existing tokens

- **File:** `winebox/auth/users.py`, lines 90–94
- `on_after_reset_password` only logs the event. If a reset was triggered due to account compromise, existing attacker sessions remain valid.
- **Recommendation:** Revoke all user tokens in `on_after_reset_password`.

### W3. X-Wines regex search has unbounded `.to_list()` — DoS vector

- **File:** `winebox/routers/xwines.py`, lines 391–393
- `_regex_search` runs three unbounded `.to_list()` calls (tier1, tier2, tier3) with no `limit`. A broad query like "a" would scan the entire collection (~100K+ docs) three times.
- **Recommendation:** Add `.to_list(length=50)` or similar limit to each tier query.

### W4. `owner_id` leaked in JSON/YAML export responses

- **File:** `winebox/routers/export.py`, lines 91 and 206
- `wine.model_dump(mode="json")` and `txn.model_dump(mode="json")` include `owner_id` (internal MongoDB ObjectId) in responses. CSV/XLSX exports correctly use filtered schemas.
- **Recommendation:** Use `model_dump(exclude={"owner_id"})` or route through a dedicated export schema.

### W5. FastAPI-Users auth routes bypass custom rate limiter and account lockout

- **File:** `winebox/routers/auth.py`, lines 42–58
- The `fastapi_users.get_auth_router()`, `get_register_router()`, and `get_reset_password_router()` sub-routers have no `@limiter.limit()` decorators. Only the global 60/min limit applies.
- The FastAPI-Users `/api/auth/login` endpoint does NOT use `authenticate_user()`, so it bypasses the account lockout mechanism entirely.
- **Recommendation:** Add per-endpoint rate limits to FastAPI-Users sub-routers, or apply prefix-level middleware limiting to `/api/auth/`.

### W6. No database query timeouts configured

- **File:** `winebox/database.py`, lines 39–43
- No `serverSelectionTimeoutMS`, `socketTimeoutMS`, or per-query `maxTimeMS` is set. A slow query could block a worker indefinitely.
- **Recommendation:** Set `serverSelectionTimeoutMS=5000`, `socketTimeoutMS=30000` on the client. Add `maxTimeMS` to expensive aggregations.

### W7. Multiple endpoints accept `skip`/`limit` without maximum cap

- **Files:** `wines/crud.py:22-23`, `search.py:40-41`, `cellar.py:22-23`, `met.py:15-16`, `transactions.py:24-25`
- These accept bare `int` parameters with no upper bound. A user can pass `limit=999999999`.
- **Recommendation:** Add `Query(ge=0)` to `skip` and `Query(ge=1, le=1000)` to `limit` on all endpoints.

### W8. `python-multipart` ReDoS vulnerability

- **Current:** 0.0.22
- **CVE-2026-28356:** Malicious Content-Type header causes exponential backtracking in multipart parser. Fix is in 1.x series.
- **Action:** Investigate whether 0.0.22 includes the fix or whether an upgrade to 1.x is needed (depends on FastAPI compatibility).

### W9. Anthropic API calls have no explicit timeout

- **Files:** `winebox/services/xwines_matcher.py:154`, `winebox/services/import_service/mapping.py:194`, `winebox/services/vision.py`
- The Anthropic SDK default timeout is 10 minutes. If the API hangs, user requests block for that duration.
- **Recommendation:** Add explicit `timeout=30.0` to all `client.messages.create()` calls.

## :yellow_circle: INFO — Best Practice Recommendations

### I1. `.gitignore` should explicitly exclude sensitive file patterns

- Currently missing: `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`
- While none of these are currently tracked, the omission risks accidental future commits.

### I2. Weak password policy — minimum 6 characters, no complexity

- **File:** `winebox/auth/schemas.py`, line 10
- `MIN_PASSWORD_LENGTH = 6` with no complexity requirements (uppercase, digits, special chars).
- **Recommendation:** Increase to 8+ characters and consider basic complexity rules.

### I3. FastAPI auto-generated docs exposed in production

- **File:** `winebox/main.py`, line 233
- `/docs`, `/redoc`, `/openapi.json` are accessible in production, exposing the full API schema.
- **Recommendation:** Disable in production or gate behind admin auth.

### I4. Admin HTML page served without authentication

- **File:** `winebox/routers/admin.py`, lines 25–34
- The admin panel HTML is served to unauthenticated users. API calls behind it all require `RequireAdmin`, so this is information disclosure only.

### I5. Static image files served without authentication

- **File:** `winebox/main.py`, lines 331–333
- Wine label images at `/api/images/` are accessible to anyone who knows the filename. UUID-based filenames mitigate guessability.

### I6. nginx missing `server_tokens off`

- **Files:** `deploy/nginx-winebox.conf`, `deploy/nginx-winebox-oat.conf`
- nginx exposes its version in response headers.

### I7. X-Wines search `q` parameter has no `max_length`

- **File:** `winebox/routers/xwines.py`, lines 472 and 641
- Unlike the main search (which limits to 200 chars), X-Wines search accepts unbounded query strings.

### I8. `collection` filter parameter accepts arbitrary strings

- **Files:** `winebox/routers/wines/crud.py:32`, `winebox/routers/search.py:52`
- Should validate against the `WineCollection` enum values.

### I9. Rate limiting can be disabled via environment variable

- **File:** `winebox/main.py`, line 37
- `WINEBOX_RATE_LIMIT_DISABLED` disables all rate limiting. Verify this is not set in production.

### I10. Export endpoints have unbounded queries

- **File:** `winebox/routers/export.py`, lines 57 and 157
- `Wine.find(conditions).to_list()` and similar with no limit. Scoped by `owner_id` so risk is proportional to a single user's data.

### I11. Search and scan endpoints lack dedicated rate limits

- **Files:** `winebox/routers/search.py`, `winebox/routers/wines/scan.py`
- Expensive operations (regex search, Claude Vision OCR) at global 60/min rate.

## :green_circle: CLEAN — Passed Review

### Authentication & Authorization
- **All user-data endpoints** require `RequireAuth` and filter by `owner_id` — no data leakage across users
- **All admin endpoints** use `RequireAdmin`, not just `RequireAuth`
- **Constant-time password comparison** with Argon2 via `pwdlib` and anti-enumeration dummy hashing
- **Account lockout** after 5 failed attempts in 15 minutes (on custom token endpoint)
- **JWT tokens** include `jti` for revocation, checked on every authenticated request
- **Token lifetime** is 2 hours with hourly cleanup of expired revoked tokens
- **Secret key** validated at startup (minimum 32 characters in production)

### Hardcoded Secrets
- **No real secrets** found in source code — all API keys, connection strings, and passwords loaded from environment variables
- **No sensitive files** tracked in git
- **Test values** are clearly dummy data (`"testpassword"`, `AKIAIOSFODNN7EXAMPLE`)

### NoSQL Injection & Input Validation
- **All `re.compile()` calls** use `re.escape()` on user input
- **All `ObjectId()` parsing** wrapped in `try/except`
- **No dangerous MongoDB operators** (`$where`, `$expr`, `$accumulator`) in the codebase
- **All API inputs** use Pydantic models for validation
- **File uploads** validated for extension, size, magic bytes, and content type; UUID filenames prevent path traversal
- **HTML escaping** consistently applied via `escapeHtml()` in JS and `autoescape=True` in Jinja2
- **`$in` queries** built from server-side data, not unbounded user input
- **Search queries** limited to 200 characters with `max_length`

### Security Headers
- **Comprehensive headers:** X-Content-Type-Options, X-Frame-Options (DENY), X-XSS-Protection, Referrer-Policy, Permissions-Policy, Content-Security-Policy
- **HSTS** with 2-year max-age in production
- **No inline scripts** — CSP compliant
- **CORS** conservative — empty origins by default, explicit method/header allowlists

### Infrastructure
- **Debug mode** defaults to `False`, validated at startup
- **Production security checks** block startup with weak secret keys or debug enabled
- **Database safety** prevents non-production hosts from connecting to production database
- **SSL/TLS** 1.2/1.3 only with modern cipher suites, HSTS, disabled session tickets
- **HTTP to HTTPS redirects** configured in nginx

### Third-Party Integrations
- **Anthropic API key** loaded from environment, not hardcoded
- **PostHog API key** served via API endpoint (standard for client-side analytics keys)
- **No webhook endpoints** requiring signature validation

### Git History
- **Last 30 commits** are clean — version bumps, bug fixes, feature work
- **No accidentally committed secrets** in git history
