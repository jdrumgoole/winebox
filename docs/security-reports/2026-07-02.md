# Security Review — 2026-07-02

## 🔴 CRITICAL (Immediate action required)

### C-1. Starlette 0.50.0 — CVE-2026-48710 (CVSS 9.1) — Authentication bypass via malformed Host header

- **Resolved version:** starlette 0.50.0 (transitive via FastAPI 0.128.1)
- **Fixed in:** starlette >= 1.0.1 (requires FastAPI >= 0.133.0)
- **Impact:** A malformed character in the Host header makes `request.url.path` differ from the actual routed path. Any middleware or endpoint using `request.url` for security decisions (auth checks, path-based access control) can be bypassed.
- **Remediation:** Bump `fastapi>=0.133.0` in `pyproject.toml` and run `uv lock --upgrade`.

### C-2. PyJWT 2.12.1 — CVE-2026-48526 (CVSS 8.8), CVE-2026-48523, CVE-2026-48525

- **Resolved version:** pyjwt 2.12.1
- **Fixed in:** pyjwt >= 2.13.0
- **Impact:**
  - **CVE-2026-48526:** Algorithm confusion — public-key JWK accepted as HMAC secret, enabling forged HS256 tokens.
  - **CVE-2026-48523:** Algorithm allow-list bypass when decoding with PyJWK/PyJWKClient keys.
  - **CVE-2026-48525:** Resource exhaustion via unbounded Base64URL decoding in detached JWS.
- **Remediation:** Bump `pyjwt>=2.13.0` in `pyproject.toml`.

### C-3. pydantic-settings 2.12.0 — CVE-2026-32690 (CVSS 5.9) — Path traversal via symlink race

- **Resolved version:** pydantic-settings 2.12.0
- **Fixed in:** pydantic-settings >= 2.14.2
- **Impact:** Path traversal via symlink race in `NestedSecretsSettingsSource`. An attacker with write access to the secrets directory can exfiltrate arbitrary files.
- **Remediation:** Bump `pydantic-settings>=2.14.2` in `pyproject.toml`.

### C-4. python-multipart 0.0.28 — CVE-2026-53539 (High) — CPU denial of service

- **Resolved version:** python-multipart 0.0.28
- **Fixed in:** python-multipart >= 0.0.30
- **Impact:** Quadratic-time querystring parsing with semicolon separators causes CPU denial of service. An attacker sends a POST with `Content-Type: application/x-www-form-urlencoded` and a body of repeated `a;` patterns, triggering O(n²) complexity.
- **Remediation:** Bump `python-multipart>=0.0.30` in `pyproject.toml`.

## 🟠 WARNING (Address within 1 week)

### W-1. Deprecated X-XSS-Protection header value

- **File:** `winebox/main.py:46`
- **Detail:** `X-XSS-Protection: 1; mode=block` is deprecated and removed from all modern browsers. Setting it to `1; mode=block` can theoretically introduce XSS vulnerabilities in older browsers by enabling the buggy XSS auditor. The strong CSP already provides XSS protection.
- **Recommendation:** Change to `X-XSS-Protection: 0` or remove the header.
- **Previously flagged:** 2026-06-04

### W-2. No OCSP stapling in nginx configuration

- **Files:** `deploy/nginx-winebox.conf`, `deploy/nginx-winebox-oat.conf`
- **Detail:** Neither nginx config enables `ssl_stapling` or `ssl_stapling_verify`. OCSP stapling improves TLS handshake performance and privacy.
- **Recommendation:** Add `ssl_stapling on; ssl_stapling_verify on; resolver 1.1.1.1 8.8.8.8 valid=300s;` to HTTPS server blocks.
- **Previously flagged:** 2026-06-04

### W-3. Hardcoded test passwords in development scripts

- **Files:**
  - `scripts/check_url_hashes.py:39` — `password = "TestPassword123!"`
  - `scripts/screenshot_checkin_enrichment.py:32` — `TEST_PASSWORD = "TestPassword123!"`
  - `scripts/screenshot_import_tab_order.py:53` — `password = "TestPassword123!"`
- **Detail:** These are dev/screenshot scripts using throwaway test accounts on local/OAT environments. Low risk, but violates the project's "never hardcode credentials" guideline in CLAUDE.md.
- **Recommendation:** Read passwords from environment variables.
- **Previously flagged:** 2026-05-03

### W-4. No minimum length check for WINEBOX_REGSTACK_JWT_SECRET

- **File:** `winebox/config/settings.py:121-127`
- **Detail:** `WINEBOX_SECRET_KEY` is validated for minimum length (32 chars) at startup, but `WINEBOX_REGSTACK_JWT_SECRET` (the actual JWT signing master secret) has no minimum length check. A short or guessable value would undermine JWT security.
- **Recommendation:** Add a minimum-length check (32+ characters) for `regstack_jwt_secret` in `_validate_security_configuration()`.

## 🟡 INFO (Best practice recommendations)

### I-1. JWT tokens stored in browser localStorage/sessionStorage

- **File:** `winebox/static/js/app.js:42-53`
- **Detail:** Tokens are stored in `localStorage` (if "remember me") or `sessionStorage`. Accessible to any JS on the page, but the strict CSP (`script-src 'self'`) mitigates XSS-based token theft.

### I-2. Token prefix logged in dev screenshot script

- **File:** `scripts/screenshot_checkin_enrichment.py:100`
- **Detail:** `print(f"Got auth token: {token[:20]}...")` — logs first 20 chars of a token. Dev-only script, not production code.

### I-3. Landing page lacks CSP/Referrer-Policy at nginx level

- **Detail:** Security headers are set by FastAPI middleware on proxied responses. Directly-served static files (landing page at `winebox.app`) don't get these headers from nginx. The landing page has no user data or login forms, so the risk is minimal.

### Authentication & Authorization

- All user data endpoints require `RequireAuth` and filter by `owner_id`
- All admin endpoints use `RequireAdmin`
- Password hashing: Argon2id via pwdlib (constant-time verification)
- Password change/reset invalidates all existing tokens via bulk revocation
- JWT tokens include `jti` claim; dual-layer revocation (per-token blacklist + bulk cutoff)
- Per-purpose JWT key derivation (session, password_reset, email_change)
- Anti-enumeration on forgot-password and change-email endpoints

### Hardcoded Secrets Scan

- No real API keys, connection strings, passwords, or private keys in source code
- `.gitignore` covers `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`
- Only `config/secrets.env.example` tracked (placeholder values only)

### NoSQL Injection

- All regex patterns from user input use `re.escape()`
- ObjectId parsing wrapped in `try/except`
- No dangerous operators (`$where`, `$accumulator`, `$function`) in production code
- `$in` queries use server-side lists, not raw user input

### Input Validation

- All API inputs use Pydantic models with `max_length` and range constraints
- File uploads validate extension, size, and magic bytes
- Path traversal prevented by `_safe_resolve()` with `Path.resolve()` + `relative_to()`
- No raw `dict` or untyped JSON body acceptance
- No inline scripts in HTML (CSP compliant)
