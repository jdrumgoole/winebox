### 🟡 INFO (Best practice recommendations)

**INFO-1: X-Wines export endpoint is unauthenticated**

- **File:** `winebox/routers/xwines.py` (line 647)
- **Detail:** `GET /api/xwines/export` allows unauthenticated bulk export of up to 10,000 reference wines per request. The endpoint is rate-limited (10/minute, 30/hour) and serves only public X-Wines reference data (no user data), so this is not a data-breach risk. However, a determined scraper could extract the full 150K-wine reference dataset in ~50 requests over several hours.
- **Risk:** Low. Data is publicly sourced from the X-Wines academic dataset. No user PII involved.
- **Recommendation:** Consider requiring authentication on the export endpoint, or adding a lower absolute cap (e.g. 1,000 per day per IP) to discourage bulk scraping of the curated dataset.

**INFO-2: E2E test secret key hardcoded in tasks.py**

- **File:** `tasks.py` (line 279)
- **Value:** `"e2e-test-secret-key-not-for-production-use-1234567890"`
- **Detail:** Clearly labelled test-only value used for isolated E2E test environments started by `invoke test-e2e-oat`. Not used in production.
- **Risk:** Negligible. Key is only valid for ephemeral test processes and is obvious from its name.
- **Recommendation:** Consider loading from `WINEBOX_E2E_SECRET_KEY` environment variable for consistency with project conventions.

#### 3. Authentication & Authorization Audit

- **All user-data endpoints** require `RequireAuth` or `RequireAdmin`.
- **All database queries** for user-owned data filter by `owner_id`.
- Public endpoints (`/api/reference/*`, `/api/xwines/*`, `/health`, `/api/config/analytics`) serve only static reference data.
- Admin endpoints in `winebox/admin/routers/admin.py` use `RequireAdmin` throughout.
- Admin panel is IP-restricted at nginx layer with explicit allowlist (`deploy/winebox-admin.toml`).
- Password changes invalidate all existing tokens via dual mechanism:
  - Per-token JTI blacklist (immediate)
  - Bulk `tokens_invalidated_after` cutoff on user document (covers all sessions)
- Registration validates email format (Pydantic `EmailStr`) and password strength (8+ chars with specific actionable feedback).
- Constant-time password comparison via Argon2 `verify()` with dummy hash for non-existent users (timing attack prevention).

#### 4. NoSQL Injection & Query Safety

- All regex searches use `re.escape()` before compilation (verified in `search_service.py`, `xwines.py`, `reference.py`, `xwines_enrichment.py`).
- No unsafe MongoDB operators (`$where`, `$expr`, `$accumulator`, `$function`) found anywhere.
- All `ObjectId` parsing from URL parameters wrapped in `try/except (InvalidId, ...)` with proper 400/404 responses.
- All API inputs validated via Pydantic models — no raw `dict` or untyped JSON bodies accepted.
- No raw pymongo collection access bypassing model safety.
- Search query lengths capped at 200 characters across all endpoints.

#### 5. Input Validation & Injection Prevention

- File uploads validated: magic byte signature detection, extension whitelist, configurable size limits.
- Path traversal prevented in image serving via `_safe_resolve()` — rejects `..`, `/`, `\`, and validates resolved path stays within storage directory.
- Generated filenames use UUIDs, never user input.
- Jinja2 templates use default autoescaping — no `|safe` filters or `{% autoescape false %}` blocks.
- No `eval()`, `exec()`, `__import__()`, or `compile()` in application code.
- All paginated endpoints enforce maximum limits via `Query(ge=1, le=MAX_PAGE_SIZE)`.

#### 6. Rate Limiting & DoS Prevention

- **Global:** 60 requests/minute per IP (configurable, disabled in test mode).
- **Login:** 30/minute, 200/hour + account lockout after 5 failed attempts (15-minute window).
- **Registration:** 10/minute, 50/hour.
- **Password reset/change:** 5/minute, 20/hour.
- **Search:** 120/minute, 2000/hour with 200-char query limit.
- **Export:** 10/minute, 30/hour.
- **Demo install:** 5/minute, 10/hour.
- All paginated queries bounded by `MAX_USER_RESULTSET` (10,000) or `MAX_REFERENCE_RESULTSET` (5,000).
- Database connection timeouts configured: serverSelection 5s, connect 10s, socket 30s.
- All Anthropic API calls have explicit timeouts (60-120s).

#### 7. Session & Token Security

- JWT tokens use HS256 with minimum 32-character secret key (enforced at startup — blocks production boot if missing).
- Tokens include `jti` (UUID for per-token revocation), `iat` (issued-at for bulk invalidation), `exp`, and `sub` claims.
- Dual-layer revocation: per-token JTI blacklist + bulk user `tokens_invalidated_after` cutoff.
- Background cleanup task removes expired revoked tokens hourly.
- No token values logged anywhere.
- HSTS enabled in production: `max-age=31536000; includeSubDomains; preload`.
- 2-hour token lifetime (reduced from longer defaults for security).

#### 8. Security Headers

All responses include:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Permitted-Cross-Domain-Policies: none`
- `Permissions-Policy` restricting camera, geolocation, microphone, etc.
- `Content-Security-Policy`: `script-src 'self'` (no `unsafe-inline` for scripts), PostHog domains whitelisted.
- CORS: empty origin list by default (same-origin only), explicit whitelist when configured.
- Nginx adds security headers to static file locations (fixed since last review).
