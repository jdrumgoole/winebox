### INFO (Best practice recommendations)

**INFO-1: Rate limiting absent on several mutation endpoints**

- **Files:**
  - `winebox/routers/demo.py` — `DELETE /api/demo/remove` has no rate limit
  - `winebox/routers/cases.py` — `POST /api/cases` has no rate limit
  - `winebox/routers/bottles.py` — `POST /api/bottles` has no rate limit
  - `winebox/routers/price_tracker.py` — `POST`/`DELETE` endpoints have no rate limit
  - `winebox/routers/import_router.py` — `POST /api/import/{batch_id}/rows` has no rate limit
- **Detail:** All these endpoints require authentication and are scoped to the current user, so the blast radius is limited. However, an authenticated user (or a compromised token) could spam these endpoints without throttling. The global `60/minute` rate limit provides a baseline safeguard but per-endpoint limits would give tighter control.
- **Recommendation:** Add `@limiter.limit("10/minute;60/hour")` or similar to mutation endpoints that create, modify, or delete data.

**INFO-2: `datetime.utcnow()` used in test and migration files**

- **Files:**
  - `tests/test_wine_ownership.py:38-52` — uses `datetime.utcnow()` (4 occurrences)
  - `scripts/migrations/migrate_sqlite_to_mongo.py:264-466` — uses `datetime.utcnow()` (8 occurrences)
- **Detail:** `datetime.utcnow()` is deprecated in favour of `datetime.now(timezone.utc)`. The test file and the one-shot migration script are not production-critical, but keeping them consistent with the codebase standard prevents copy-paste propagation.
- **Recommendation:** Replace with `datetime.now(timezone.utc)` in both files.

**INFO-3: Nginx static file locations missing CSP header**

- **Files:** `deploy/nginx-winebox.conf`, `deploy/nginx-winebox-oat.conf`
- **Detail:** Nginx's `add_header` in `location` blocks overrides parent-level headers. The static file locations correctly re-emit `X-Content-Type-Options`, `X-Frame-Options`, `Strict-Transport-Security`, but do not include `Content-Security-Policy`. Static HTML files served directly by nginx (e.g. `landing.html`) lack CSP protection. API responses served through FastAPI's `SecurityHeadersMiddleware` are unaffected.
- **Recommendation:** Add `add_header Content-Security-Policy "default-src 'self'" always;` to nginx static file locations.

**2. Hardcoded Secrets Scan — CLEAN**

- No API keys, connection strings, passwords, private keys, or JWTs found in source code
- `.gitignore` correctly covers `.env`, `secrets.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`
- Only tracked secrets-related file: `config/secrets.env.example` (placeholder values only)
- Test files use clearly labelled dummy credentials (`sk-ant-api-key`, `AKIAIOSFODNN7EXAMPLE`, `TestPassword123!`)
- No secrets found in git history via `git log --diff-filter=A`

**3. Authentication & Authorization Audit — CLEAN**

- All user-data endpoints require `RequireAuth` and filter by `owner_id`
- All admin endpoints require `RequireAdmin`
- Password change/reset invalidates all existing tokens via `revoke_all_user_tokens()`
- Registration validates email format (Pydantic `EmailStr`) and password strength (8+ chars)
- Constant-time password comparison via pwdlib/Argon2 (not `==`)
- Timing-safe user enumeration prevention: dummy hash verified for non-existent users
- Self-modification prevention: admins cannot deactivate/delete their own account
- Login attempt tracking with 5-attempt lockout (15 minutes)

**4. NoSQL Injection & Query Safety — CLEAN**

- All regex patterns from user input use `re.escape()`
- All `ObjectId` parsing wrapped in `try/except`
- No unsafe operators (`$expr`, `$where`, `$accumulator`, `$function`) in codebase
- All `$in` queries use bounded, application-controlled lists
- No raw pymongo collection access bypassing model safety
- All API inputs validated via Pydantic models

**5. Input Validation & Injection — CLEAN**

- File uploads validated: extension whitelist, magic byte detection, size limits
- Path traversal prevented via `_safe_resolve()` in image serving
- HTML auto-escaping enabled in Jinja2 templates (`autoescape=True`)
- Static site export uses `html.escape()` for all user data
- Search queries length-limited (`MAX_QUERY_LENGTH = 200`)
- Import row counts capped (`le=10000`), headers capped (`max_length=200`)

**6. Rate Limiting & DoS Prevention — CLEAN (with INFO-1 noted)**

- Auth endpoints comprehensively rate-limited (login 30/min, register 10/min, password reset 5/min)
- Global 60/minute default rate limit
- Database query timeouts configured (`serverSelectionTimeoutMS=5000`, `socketTimeoutMS=30000`)
- Pagination bounded (`MAX_PAGE_SIZE = 200`, `MAX_USER_RESULTSET = 10,000`)
- All `.to_list()` calls use `length=` parameter
- File upload sizes bounded (10 MB images, 25 MB imports)

**7. Session & Token Security — CLEAN**

- JWT: HS256 algorithm, 2-hour expiry, `jti` claim for per-token revocation
- Token blacklist with hourly cleanup of expired entries
- Bulk user invalidation via `tokens_invalidated_after` cutoff
- Password changes revoke all user tokens immediately
- Secret key minimum 32 characters enforced; production startup blocked if weak
- HTTPS enforcement available via `enforce_https` setting with HSTS header

**8. Security Headers — CLEAN**

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Content-Security-Policy`: restrictive, `script-src 'self'` (no `unsafe-inline`)
- `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy`: restricts camera, geolocation, microphone, etc.
- CORS: same-origin by default, explicit whitelist required
- No inline scripts (CSP compliant)

**9. Data Exposure — CLEAN**

- API responses strip `owner_id` from export payloads
- Error messages generic for auth failures ("Incorrect email or password")
- Image serving returns same 404 for "not found" and "not owned"
- Admin `/info` endpoint does not expose MongoDB hostname
- API docs (`/docs`, `/redoc`) disabled outside debug mode
- `str(e)` usage in routers limited to application-controlled exception classes (`CellarDebitError`, `ValueError` with known messages)

**10. Git History — CLEAN**

- No security-sensitive files modified without corresponding security review

**11. Infrastructure & Configuration — CLEAN**
