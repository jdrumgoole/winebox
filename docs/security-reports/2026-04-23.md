## :orange_circle: WARNING (Address within 1 week)

### 1. Price tracker history leaks other users' location data

- **Location:** `winebox/routers/price_tracker.py:345-376`
  (`get_wine_price_history` endpoint)
- **Issue:** The `WinePriceHistory` query returns archived price entries for a
  wine by name/vintage/type without filtering by `owner_id`. The response
  includes `town_city`, `state_county`, and `notes` for ALL users' entries
  (lines 367-370). This is inconsistent with the privacy filtering applied to
  active price entries in `_entry_to_out()`, which correctly redacts GPS
  coordinates, notes, and photo URLs for entries not owned by the requester.
- **Impact:** Other users' shop locations and free-text notes are exposed to
  any authenticated user who queries the same wine's price history.
- **Recommendation:** Apply the same ownership-based redaction from
  `_entry_to_out()` to `WinePriceHistory` entries, or strip `notes`,
  `town_city`, and `state_county` for entries where
  `entry.owner_id != current_user.id`.
- **Status:** Unchanged since 2026-04-14 (first reported). Now 9 days open.

### 2. `posthog` SDK is 4 major versions behind latest

- **Package:** `posthog>=3.0.0` in `pyproject.toml`; latest is 7.11.2.
- **Issue:** The PostHog Python SDK had significant breaking changes in v6
  (removed `identify()`, `screen()`, `page()` methods; changed `capture()` to
  keyword-only args) and v7 (dropped Python 3.9). While no CVEs were found,
  running a version 4 major versions behind means missing security hardening,
  bug fixes, and API deprecations. The v3 SDK may stop working against newer
  PostHog server APIs.
- **Recommendation:** Bump to `>=7.0.0` (or at minimum `>=6.0.0`) after
  verifying API compatibility. Test that the integration still works with the
  new `capture()` keyword-arg API.
- **Status:** New finding.

## :yellow_circle: INFO (Best practice recommendations)

### 3. `bottles.py` CellarEvent query lacks defense-in-depth owner scoping

- **Location:** `winebox/routers/bottles.py:188-190`
- **Issue:** `get_item_events` queries CellarEvent by `{"cellar_item_id": oid}`
  without including `cellar_id` or `owner_id` in the filter. The item
  ownership is verified first (lines 183-186), and `cellar_item_id` is a
  unique ObjectId, so this is not exploitable. However, adding owner scoping
  to the event query would be defense-in-depth.
- **Status:** Unchanged since 2026-04-17.

### 4. `import_router.py` list_batches limit parameter unbounded

- **Location:** `winebox/routers/import_router.py:509`
- **Issue:** `list_batches` accepts `limit: int | None = None` with no upper
  bound constraint. While scoped to a single user's batches, an attacker could
  request an unbounded number of results. Other list endpoints correctly use
  `le=MAX_PAGE_SIZE`.
- **Status:** Unchanged since 2026-04-17.

### 5. `skip` parameter lacks `ge=0` validation in price tracker

- **Location:** `winebox/routers/price_tracker.py:258,334`
- **Issue:** `list_wine_prices` and `get_wine_price_history` accept `skip`
  without `ge=0`, allowing negative values. Limit is clamped to 200 in code
  (lines 263, 342) but not via `Query(le=200)`.
- **Status:** Unchanged since 2026-04-17.

### 6. Reference data `to_list()` calls unbounded

- **Location:** `winebox/routers/reference.py` lines 31, 76, 138, 164, 230,
  270, 308, 335
- **Issue:** Multiple `.to_list()` calls without a `length=` parameter. These
  are static reference datasets so the risk is low, but a massive dataset
  import could lead to memory exhaustion.
- **Status:** Unchanged since 2026-04-14.

### 7. ObjectId parsed without try/except in price_tracker

- **Location:** `winebox/routers/price_tracker.py:247, 267, 304`
- **Issue:** `ObjectId(wine_price_id)` raises `bson.errors.InvalidId` on a
  malformed ID, surfacing as a 500 instead of a clean 404.
- **Status:** Unchanged since 2026-04-07.

### 8. Form fields in price_tracker lack `max_length`

- **Location:** `winebox/routers/price_tracker.py:118-132`
- **Status:** Unchanged since 2026-04-07.

### 9. `POST /api/prices` photo upload size limit enforced after read

- **Location:** `winebox/routers/price_tracker.py:168-170`
- **Issue:** `content = await photo.read()` loads the full upload into memory
  before the 10 MB check fires.
- **Status:** Unchanged since 2026-04-14.

### 10. Unbounded `.to_list(length=None)` in cellar and search code paths

- **Location:** `winebox/routers/cellar.py:125, 172`,
  `winebox/routers/search.py:132, 157, 176`,
  `winebox/routers/bottles.py:73`, `winebox/routers/cases.py:195`
- **Issue:** All scoped by `owner_id`, but a user with a very large cellar
  can force unbounded memory use per request.
- **Status:** Unchanged since 2026-04-14.

### 11. Missing `max_length` on query parameters in xwines and reference routers

- **Location:** `winebox/routers/xwines.py:472, 475, 476`,
  `winebox/routers/reference.py:62-64, 116, 119, 295, 296`
- **Issue:** 10 query parameters that flow into MongoDB regex queries lack
  `max_length` constraints. Compare to `search.py` which correctly applies
  `max_length=200`.
- **Status:** Unchanged since 2026-04-17.

### 12. No `server_tokens off` in nginx config

- **Location:** `deploy/nginx-winebox.conf`
- **Status:** Unchanged since 2026-04-06.

### 13. Inline script in `og-preview.html`

- **Location:** `winebox/static/og-preview.html:132`
- **Status:** Unchanged since 2026-04-06.

### 14. OAT nginx has no admin IP restriction

- **Location:** `deploy/nginx-winebox-oat.conf`
- **Status:** Unchanged since 2026-04-07.

### 15. DigitalOcean API calls in `deploy/common.py` have no timeout

- **Location:** `deploy/common.py` lines 142, 161, 191, 211, 222, 232, 242,
  252, 268, 286
- **Status:** Unchanged since 2026-04-07.

### 16. HSTS header dropped for nginx-served static files

- **Location:** `deploy/nginx-winebox.conf:179-184`
- **Issue:** nginx `add_header` directives are not inherited into `location`
  blocks that contain their own `add_header`. The `/static/` location adds
  `Cache-Control`, which silently drops HSTS for those responses.
- **Status:** Unchanged since 2026-04-17.

### 17. `anthropic` MCP protocol design flaw (CVE-2026-30623)

- **Issue:** Anthropic has declined to patch the MCP stdio command injection
  design issue. This is an inherent protocol design concern, not specific to
  a version of the SDK. If WineBox uses MCP server connections, command
  inputs should be validated/allowlisted at the application level.
- **Status:** Informational. WineBox does not appear to use MCP server
  connections in the main application.

### 18. `bcrypt` one major version behind latest

- **Package:** `bcrypt>=4.1.2`; latest is 5.0.0.
- **Issue:** bcrypt 5.0.0 has a breaking change: passwords > 72 bytes now
  raise `ValueError` instead of silently truncating. No CVEs, but the
  version gap is worth tracking.
- **Status:** New finding.

### 19. `slowapi` low maintenance activity

- **Package:** `slowapi>=0.1.9`
- **Issue:** No new releases in over 12 months. Monitor for abandonment;
  consider alternatives if the project becomes unmaintained.
- **Status:** New finding.

## :green_circle: CLEAN (Passed review)

### Authentication & authorization
- All user-data endpoints use `RequireAuth` and scope every query by
  `cellar_id: current_user.id` or `owner_id: current_user.id`. Every endpoint
  in `cellar.py`, `bottles.py`, `cases.py`, `met.py`, `transactions.py`,
  `search.py`, `export.py`, `import_router.py`, `demo.py`, `wines/`,
  `price_tracker.py`, and `images.py` was individually verified.
- Password hashing (Argon2 via `pwdlib`), constant-time comparison, anti-
  enumeration dummy hash, account lockout with `Retry-After`, JWT `jti`
  blacklist, startup secret-length validation — all in place.
- Password change invalidates all existing tokens via both per-jti blacklist
  and bulk `tokens_invalidated_after` cutoff.
- Password reset also calls `revoke_all_user_tokens`.
- Registration validates email format and password strength (min 8 chars).
- Comprehensive rate limits on all auth endpoints: login (30/min), register
  (10/min), forgot/reset password (5/min), password change (5/min), verify
  (10/min).

### NoSQL injection
- No `$where`, `$expr`, `$function`, or `$accumulator` operators anywhere.
- All regex uses of user input go through `re.escape()` (verified in
  `search_service.py`, `reference.py`, `xwines.py`, `wines/crud.py`,
  `xwines_enrichment.py`).
- No user input placed into MongoDB operator positions. FastAPI typed
  parameters prevent dict-type injection.
- All `$in` queries use server-generated arrays, never user-supplied.
- All ObjectId parsing wrapped in try/except (except price_tracker, noted
  as INFO #7).

### Input validation
- All JSON body endpoints use Pydantic models. No raw `dict` bodies.
- File uploads validate type, size, and magic bytes. User-supplied filenames
  discarded in favour of UUID-generated names.
- Jinja2 templates have `autoescape=True`. Email templates render only
  server-controlled values.
- Path traversal protection via `_safe_resolve()` in image storage and image
  router.
- XSS protection: `escapeHtml()` applied consistently in JS frontend (134
  usages verified).

### Token security
- JWT algorithm: HS256 with explicit algorithm list on decode (prevents
  algorithm confusion).
- Token expiry: 2 hours.
- JTI claim for per-token revocation; revoked tokens checked on every request.
- `iat` claim for bulk invalidation via `tokens_invalidated_after`.
- Derived secrets for password reset and email verification tokens (HMAC-
  SHA256).
- No token leakage in logs or error messages.

### Secrets management
- No hardcoded secrets, connection strings, or API keys found anywhere in
  the codebase. All values are test/placeholder (`"test-key"`,
  `AKIAIOSFODNN7EXAMPLE`, `mongodb://localhost:27017`).
- No `.env`, `.key`, `.pem`, or credential files tracked in git.
- `.gitignore` covers: `.env`, `.env.local`, `secrets.env`, `*.pem`, `*.key`,
  `*.p12`, `*.pfx`.

### Security headers
- Full CSP with `script-src 'self'` (no `unsafe-inline` for scripts),
  `frame-ancestors 'none'`, `object-src 'none'`.
- HSTS with `max-age=31536000; includeSubDomains; preload` (when
  `enforce_https` is true).
- `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`.
- CORS whitelist-only (default: empty = same-origin).

### API surface
- OpenAPI docs (`/docs`, `/redoc`, `/openapi.json`) disabled outside debug
  mode, preventing endpoint enumeration in production.

### Third-party integrations
- Anthropic API key loaded from environment, not hardcoded. Client has 60s
  timeout.
- PostHog API key exposure is correct (project API keys are designed for
  client-side use).
- No webhook endpoints requiring signature validation.
- MongoDB connection configured with bounded timeouts
  (`serverSelectionTimeoutMS=5000`, `connectTimeoutMS=10000`,
  `socketTimeoutMS=30000`).

### Dependency versions
- All known CVEs addressed by current version pins:
  - `pillow>=12.2.0` (CVE-2026-25990, CVE-2026-40192)
  - `pyjwt>=2.12.0` (CVE-2026-32597)
  - `cryptography>=46.0.7` (CVE-2026-39892, CVE-2026-34073)
  - `python-multipart>=0.0.26` (CVE-2026-40347)
  - `cairosvg>=2.9.0` (CVE-2026-31899)
  - `anthropic>=0.96.0` (CVE-2026-34450, CVE-2026-34452)
- No supply chain compromises or yanked versions found for any package.

### Git history
- No security regressions in the last 30 commits. Recent changes include
  static site export, version bumps, E2E test improvements.
- No accidentally committed secrets in git history.
- PyJWT CVE fix (commit `82e82a7`) and dependency bumps were the most
  recent security-relevant changes.
