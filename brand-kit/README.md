# WineBox Brand Kit & Design System

This folder is the home of everything that defines how WineBox looks and reads.

## Start here

| File | What it covers |
|------|---------------|
| [BRAND.md](BRAND.md) | Brand identity: logo, colour palette, typography, usage rules |
| [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md) | Design tokens, components, UX voice & tone, accessibility baseline |
| [colors.json](colors.json) | Raw brand colours (name → hex) |
| [tokens.json](tokens.json) | Full design tokens (colour, type, spacing, radius, shadows, motion) |

## Live showcase

With the app running locally, open **[http://localhost:8899/design-system](http://localhost:8899/design-system)** to see every component rendered with the real `style.css`. This is the visual source of truth.

## Assets

| Folder | What's inside |
|--------|--------------|
| `svg/` | Logo variants — icon, compact wordmark, full lockup, across light / dark / on-cream / on-dark themes |
| `png/` | PNG renders of the logos at 200–1600px widths (generated by `generate_pngs.py`) |
| `favicon/` | Favicons at 16 / 32 / 48 / 180 / 192 / 512 px plus `apple-touch-icon.png` and `favicon.svg` |

### Regenerating PNGs

```
cd brand-kit
uv pip install playwright pillow
uv run playwright install chromium
uv run python generate_pngs.py
```

## Editing the system

1. **Tokens** (colour, spacing, radius, etc.) live in `winebox/static/css/style.css` under `:root`. That stylesheet is the source of truth; `tokens.json` documents it.
2. Change the CSS → update `tokens.json` → visit `/design-system` to verify.
3. If you add a new component, document it in [DESIGN-SYSTEM.md §2](DESIGN-SYSTEM.md#2-components) **and** add a section to the live showcase (`winebox/static/design-system.html`).
4. If you change a UI label, rename the matching HTML ids, CSS classes, JS functions, and API paths too (see DESIGN-SYSTEM.md §3.5).
